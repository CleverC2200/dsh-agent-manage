# Agent Note: Full-chain distribution mock reception

Status: implemented

## Problem

The fixed distribution candidate must join the current unified page/resource interfaces without consuming new live data authorization.

## Decision

Manage declares `inventory-qll` as fixed mock input with empty tables and MCP capabilities. Manage owns the restored pure business calculation through its public inventory-compute modules. Workbench owns the local fixture, UI intent and current Session page references. The existing Consumer identifier remains a module identifier and grants no query authority.

## Alternatives considered

A live-by-default page would query on open and exceed the authorized mock reception. A second resource or Session authority would duplicate existing ownership. The original Git objects retain historical live query sources for separately authorized work.

## Consequences

The original company/customer units and null/zero rules remain. Fixture row filters prove local behavior only; real customer data, row grants and original ticket14 acceptance remain open. This partially narrows the current distribution mode described by the [business resource ownership note](../architecture/2026-09-29-workbench-business-resources.md), which still owns resource assembly and cleanup.

The fixed trend input matches the current distribution organization and SKU codes. Trend context and its single reference bind the captured snapshot and narrowed range; missing dates remain null. UI intent can restore, while historical facts require a new explicit query. Original live query and pagination protection remain recoverable from the fixed ticket15 Git object and are absent from the mock runtime.
