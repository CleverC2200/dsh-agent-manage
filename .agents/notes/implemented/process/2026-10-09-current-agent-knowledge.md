# Agent Note: Current Agent knowledge and reference checks

Status: implemented

## Problem

The default Agent entry named the old market package and directed isolated work through historical release and SDK assumptions. Current notes also described retired listeners and resource publication.

## Decision

AGENTS links to current-development for current module ownership and fixed-input discovery. Package metadata owns scripts, versions and exports. The Workbench-owned check-agent-knowledge CLI checks the Manage declaration of current references; Manage adds no second checker implementation. Historical design/release/research and archived records remain explicitly historical references. Former market release skills are preserved under docs/history outside skill discovery; the old standard path points to current owners and its original snapshot. Package metadata, the fixed SDK and current owners continue to define executable facts.

Current notes update implementation facts and link the current owner. Partial supersession preserves unique reasons. The SDK/icon, workspace, project lifecycle and business-resource decisions stay in their existing owner records; the current source company slice does not become live acceptance.

## Alternatives considered

**Deleting old notes by age or count.** This would remove still-useful storage, cancellation, containment and unit reasons.

**Copying commands and a separate checker into each repository.** Package metadata already owns command facts; one developer checker avoids competing rules. Manage declares its active inputs and consumes that interface.

## Consequences

The checker covers local references and declared commands/paths; prose correctness and current decision scope still require review. Archived outgoing links are not read or repaired. Reference checks, AST/public-export comparison and applicable contract/architecture tests do not prove remote CI, prepared SDK artifacts or live business authorization.
