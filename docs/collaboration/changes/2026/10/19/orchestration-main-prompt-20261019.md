# 智能编排主提示词与配置入口

按用户提供的 COO 主提示词替换原分流短文，仅按用户明确确认纠正第 7 条的两个诊断 Skill 对应关系。三个既有 Skill 及其引用文件保留原内容；文案提及的 aging-inventory-disposal 当前未随包提供，本次未补造该 Skill。

智能编排原先只注册原生预设，因此不出现在 Agent 配置。现在由已有 BusinessResources owner 管理同一个 auto-negotiation 身份，复用插件 Agent 的提示词、Skill、启停与持久化流程。保留官方标准工具、上下文压缩与用户默认选择；编辑用于新会话，既有会话保留原版本。

本次冷启动回归同时暴露了 Skill 目录别名问题：文件系统 provider 返回真实路径，快照元数据可能保留符号链接路径。改为解析真实入口路径，并以明确的目录别名覆盖配置保存、调用范围、启停与重启恢复。

验证只使用本任务源码、固定 Core 和隔离临时 Home，不修改正式客户端、用户会话、企业数据或发行频道。远端 CI 与后续发布分别留证。

补充现有验收缺口：Manage 的 package-version 测试仍断言历史 company.19，而主线已到 company.21。删除该次发行专用断言，保留清单对照的 Host/client 类型检查、两代真实编译产物与不可变标识验证。默认智能编排继续继承全局可用 Skill，只有用户显式定制 Skill 列表时才按列表限定新会话。三包接收校验同时去除 company.20 分支，按包内提示词与受管资源的实际声明推导预期。

本地客户端验收曾沿用上次发行的 Workbench .11；当前 Manage 登记的同组 .12 才提供测试导入的新 Session 入口与草稿接线。验证改用登记提交，并在现有客户端 Vitest 配置中按测试实际命名导入检查所选 Workbench 的 TypeScript 导出。缺接口时在运行测试前给出固定输入修复入口，不再手工固定“当前版本”列表。

纯计算工具与 Skill 引用读取不再等待原生预设资源初始化，避免更完整的智能编排配置准备延迟这些独立工具。
