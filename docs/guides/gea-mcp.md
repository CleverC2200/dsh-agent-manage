# GEA Cube-New MCP

GEA Host owns login, credentials and business authorization. Manage registers the server input schemas for `inspect_cube_model` and `query_business_data` under `mcp__gea-gateway__inspect_cube_model` and `mcp__gea-gateway__query_business_data`. Set `geaMcp: false` to disable integration. Manage configuration and model arguments do not choose a Consumer.

GEA derives the Consumer from the calling Core Session's installed, enabled business preset. Sales and inventory modes retain their own identities. Unprofiled or agentless calls cannot borrow the default Consumer. Old calls cannot publish into a changed preset, environment or login.

Inspect the actual model or View, use its current `aliasMember`, and submit the original server query schema. Each call targets one underlying model with `action=query` and `response_mode=inline_complete`. Host reads the returned artifact in the original business and transport sessions and verifies its raw digest, dataset names, rows and pagination. It does not fall back to old Cube, SQL or storage URLs. Only two methods are model-facing.

Tool discovery, model visibility and business query success are separate acceptance results. Preserve `DATA_QUERY_MEMBER_NOT_PUBLISHED` as a failed call; independent authorized queries remain available. It requires server publication checks rather than automatic parameter retries.

Logout and identity changes cancel old calls before retiring their tools. New login generations rediscover. Failed discovery does not recreate business sessions automatically. The old `gea_gateway_catalog`, `gea_cube_query` and `gea_module_mcp` wrappers are retired. Durable Sessions, drafts and historical evidence remain.

GEA projects its current identity through `geaMcp.identitySignal()`. Manage keeps current authorized schemas while preparing a resource refresh under the same identity. Public Core prompt assembly waits for the pending publication, including the first business request, and collects the new schemas after successful registration. An ordinary discovery failure leaves the unavailable GEA methods unpublished while the model and its other tools can continue. It does not veto later assemblies or discard still-authorized tools from the same identity.

When discovery has failed, new input through Core's `agent/inbox/inserted` event retries metadata discovery for an allowed Agent through the existing GEA service. Concurrent inputs and assemblies share the pending discovery. Prompt reassembly does not itself retry, and there is no background retry timer, retry budget or new timeout. Caller cancellation stops its readiness waiter without cancelling shared discovery. Publication and cleanup failures retain their failure/rollback behavior. A changed identity cancels old calls and retires its schemas before discovery; recovery does not replay business queries or recreate a revoked authorization.

Personal Agents may select one trusted installed Cube reference. The Host resolves its owner and Consumer through the actual Core preset revision; the reference exposes these two Cube tools plus `weknora_list_knowledge_bases` and `weknora_ask` under the same Consumer and current server grants. It grants no business profile, writes or page actions. Missing, disabled, removed or revoked sources cannot fall back to another Consumer.
