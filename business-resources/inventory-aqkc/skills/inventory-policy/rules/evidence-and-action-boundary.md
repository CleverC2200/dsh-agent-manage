# 基地库存证据状态与行动边界规范

定义结论的证据状态标准，以及 AI 可以做什么、不可以做什么。

## 一、证据状态

| 状态 | 含义 | 使用场景 | 输出要求 |
|---|---|---|---|
| 已验证 | 有直接数据支撑 | 系统直接读取的库存、目标、订单、货龄数值 | 直接陈述事实，标注来源与时间 |
| 有支撑未验证 | 有间接数据关联，缺直接验证 | 多指标关联推断，如「动销偏慢叠加高货龄」 | 说明支撑依据，标注待进一步验证 |
| 推测 | 基于经验或模式的合理推测 | 「疑似生产批次延迟」 | 不得作为结论，须给验证建议 |
| 数据缺失 | 因数据不足无法判断 | 目标缺失、动销未接入 | 说明缺什么数据及对结论的影响 |

标注方式：在结论后用方括号标注，例如「原因线索：近 30 日动销仅为计划的 45%【已验证】」「原因线索：批次集中入库【推测】」。推演类结论（未来 7 / 14 日预计超龄）统一按【有支撑未验证】标注，并说明窗口与是否扣减预计动销。

## 二、行动边界

### 2.1 AI 可以做的
读取与展示数据、计算指标（库存差额、偏差率、周转天数、货龄、动销达成）、按规则识别风险、输出原因线索（带证据状态）、生成建议（标注待人工确认）、解释口径与计算方法。

### 2.2 AI 不可以做的
不修改目标库存 / 生产计划 / 补货单 / 调拨单 / 订单；不写入任何业务系统；不建、不关、不升级待办与事件；不做正式定责；**P1 不做责任推断、不给具体责任人与责任人指派**；建议责任角色属推荐（非推断），可给但须标【待人工确认】、不写人名；不承诺到货时间；补货量测算属建议，不是补货单。

### 2.3 P1 不做、留待 P2 的事项

| 事项 | 说明 |
|---|---|
| 待办 / 事件 / 历史反馈闭环 | P1 只出报告与建议，状态流转未实现 |
| 责任判定与责任人指派 | 业务规则未确认，P1 不输出具体责任人、不做定责；建议责任角色（角色级）可输出，用于协同参考 |
| 升级与审批 | 不做升级判断、不自动创建事项 |
| 大日期专项台账与锁定 | P1 只识别 61 天以上库存并给出处理方向 |

### 2.4 必须人工确认的事项（P1 口径）

| 事项 | 说明 |
|---|---|
| 目标库存调整 | 由品类计划与大数据流程处理，Agent 不参与 |
| 补货动作 | P1 输出补货 SKU 与补货量测算（属建议）；正式补货单、调拨与排产由业务确认 |
| 大日期处理方案 | 是否处理、如何消化由业务确认 |
| 口径与数据异常 | 版本冲突、字段缺失、数据异常需人工复核 |

## 三、建议与执行的区分

| 场景 | 正确表述 | 错误表述 |
|---|---|---|
| 补货 | 「建议关注补货节奏（待人工确认）」 | 「已补货 5000 件」 |
| 处理建议 | 「建议优先消化 41-60 天库存」 | 「已下达消化指令」 |
| 原因分析 | 「疑似生产延迟导致」 | 「生产延迟导致」 |
| 风险判断 | 「存在滞库风险」 | 「已经滞库了」 |

建议的标准格式：建议内容（做什么）+ 建议理由（为什么）+ 优先级（高/中/低）+ 状态【待人工确认】。P1 不写具体人名；建议责任角色写角色不写人。

## 四、业务判断边界

| 现象 | 不等于 | 原因 |
|---|---|---|
| 低于目标库存 | 当前订单缺货 | 目标是策略值，交付风险要看订单缺口与可用库存 |
| 高于目标库存 | 滞库 | 要结合动销达成、货龄与日均计划量 |
| 目标缺失 | 库存异常 | 可能是新 SKU 或版本未同步 |
| 目标为 0 | 库存异常 | 可能是停产品种，需结合实际需求判断 |
| 货龄 61 天以上 | 已定责 | 大日期只说明需要处理，不定责 |
| 动销偏慢 | 一定滞库 | 还需结合库存差额、货龄与计划量 |
