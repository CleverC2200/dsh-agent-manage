# 基地库存偏差监控 Skill

## 参考资源（按需加载）

- **本 Skill 的 `rules.md`**：本技能的公式、阈值与判断规则
  → 计算与判定前读取
- **`inventory-policy` Skill**：指标口径矩阵、数据与知识访问契约、数据边界与目标版本、证据与行动边界、输出规范
  → 取数前读它的 `rules/data-access-contract.md`；口径解释、排名与筛选前读 `rules/metric-catalog.md`；生成回答前读 `rules/output-guide.md`

## 目标

把当前库存、目标库存、动销、货龄等输入，转化为可追溯、可复核的库存偏差结论：库存差额、偏差率、重点对象、原因线索、建议和数据边界；保留目标版本、数据时间、粒度、证据状态和人工确认边界。

## 触发场景

- 「库存怎么样」「库存差额多少」「偏差率多少」
- 「哪些基地 / 品类 / SKU 高于（低于）目标」
- 「目标库存有没有缺失」「用的是哪个版本的目标」
- 「为什么这个 SKU 偏差这么大」
- 「帮我重新算一下目标库存 / 安全库存」「现有目标好像不合理」（走「目标复核」答法，不重算）
- 「郑州基地安全库存是多少」（业务口语的安全库存 = 目标库存，直接按目标库存回答）

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 分析范围 | 基地、品类、SKU、仓库 | 是 |
| 分析粒度 | 基地 / 品类 / SKU / 基地×品类×SKU | 是 |
| 库存数据 | 当前库存、可用库存、占用库存 | 是 |
| 目标库存 | 最终目标库存、目标版本、生效日期（按基地） | 是 |
| 数据截止时间 | 各数据源时间 | 是 |
| 订单数据 | 当前订单量、未备单完成订单量与占用量 | 否 |
| 动销数据 | 近 30 日动销量、日均动销、日均计划量 | 否 |
| 货龄数据 | 平均货龄、货龄分段 | 否 |

缺可选字段时继续输出可判断部分，并在数据边界说明限制。**不使用单价与金额口径。**

## 执行步骤

### 第 1 步：确定目标版本
按 `rules.md` 的目标版本取值规则（日期区间 + 优先级，按基地维度）确定本次使用的版本，逐基地记录版本与生效日期；缺失的基地单列。

### 第 2 步：库存与目标对齐
按基地 + 品类 + SKU 匹配。
- 有库存无目标 → 标记「目标缺失」
- 有目标无库存 → 标记「库存为 0」
- 目标为 0 → 标记「目标为 0」，不算偏差率
- 整个基地全部 SKU 都无目标（目标合计为 0）且有库存 → 判**数据异常**，该基地不出差额与偏差率结论，提示核查目标版本，其余基地照常

### 第 3 步：计算差额与偏差率
按 `rules.md` 公式：库存差额 = 当前库存 − 目标库存（主口径，件）；偏差率 = 差额 ÷ 目标库存 × 100%（目标 > 0 时）。
**不计算偏差金额。**

### 第 4 步：风险分层
按 `rules.md` 的默认阈值分为 正常 / 关注 / 高风险，并区分高于目标与低于目标。
排序：先按风险等级，再按库存差额绝对值（件），偏差率作补充。

### 第 5 步：关联订单影响（如有数据）
对低于目标的 SKU：订单充足 → 风险降级；存在当前订单缺口 → 标注「建议转缺货分析」。

### 第 6 步：关联动销与货龄（如有数据）
对高于目标的 SKU：动销达成（日均动销 ÷ 日均计划量）≥ 100% → 风险降级；< 60% 且货龄 41 天以上 → 风险升级，标注「建议转货龄滞库分析」。

### 第 7 步：生成原因线索
按 `rules.md` 触发条件生成，每条标注证据状态，最多 5 条，无数据支撑的不列。不做目标设置合理性的推断。

### 第 8 步：生成建议
按 `rules.md` 建议规则输出，标注优先级与【待人工确认】。P1 不指定具体责任人与责任人指派，可给建议责任角色（角色级、不写人名）。

### 第 9 步：整理数据边界
按 `inventory-policy` Skill 的 `rules/data-boundary.md` 整理：数据时间、目标版本（逐基地）、缺失目标清单、不可判断项。

### 第 10 步：形成交付结果
按 `inventory-policy` Skill 的 `rules/output-guide.md` 组织输出（问答档 / 看板档）。

## 目标复核 / 重算类请求（不重算的标准答法）

命中「重新算一下目标库存 / 安全库存」「现有目标不合理」「目标偏高偏低」时，**不进入第 3–8 步的测算流程**，按四段作答：

1. **结论**：目标库存由上游按月测算并锁定，本 Agent 只读不重算；是否合理需业务确认。
2. **事实**：当前目标版本与生效日期、目标库存合计、当前库存、库存差额；用户明确要求拆分时再给周转库存 / 安全库存分项；目标缺失与目标为 0 的 SKU 数与清单。
3. **边界**：不输出自算目标值、不输出测算过程、不评价偏高偏低。
4. **引导**：查看目标缺失清单 / 查看目标为 0 的 SKU / 查看低于目标 SKU / 查看目标版本说明。

口径：用户说「安全库存」按**目标库存**回答，表头写「目标库存」，不反问、不默认给技术口径的安全库存分项。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 库存差额 = 当前库存 − 目标库存（主口径）
- 偏差率 = 差额 ÷ 目标库存 × 100%（目标 > 0）
- 不使用偏差金额，不做金额分层与金额排序
- 目标版本：1–20 日优先当月纠偏版，21–月末优先次月月初版
- 风险等级前后一致：高风险（红）/ 关注（橙）/ 正常（绿）
- 缺数按 0，分母 0 或无数不计算；目标缺失不参与差额与排名；建议 ≠ 已执行

## 默认交付

> 输出结构、语言、数字、引导格式统一遵守 `inventory-policy` Skill 的 `rules/output-guide.md`：快速问数用四段式，分析类问题用「核心结论 → 关键数字 → 问题根因 → 行动建议（短/中/长期 + 责任角色）→ 风险提示 → 数据说明」，报告类按模板输出。


1. 核心结论（一句话：偏差对象数、高风险数、最大差额对象）
2. 分析范围、粒度、数据时间与目标版本
3. 偏差汇总（按基地 / 品类，高于 / 低于 / 正常分布）
4. 重点偏差 TOP 10（按风险等级 + 库存差额排序）
5. 原因线索（标注证据状态）
6. 建议与待确认
7. 数据边界

## 边界与禁止动作

- 不调整目标库存、不生成补货单、不派发任务、不定责、不推荐责任人（P1）
- 不输出自算目标 / 安全库存数值（含「重新算一版」）；不把技术口径的安全库存当作业务安全库存输出
- 低于目标 ≠ 当前订单缺货；高于目标 ≠ 滞库
- 原因线索 ≠ 定责结论；建议 ≠ 已执行动作
- 不推断目标设置是否合理，不解释目标重算过程
- 不使用金额口径

## 与其他 Skill 的边界

| 场景 | 本 Skill 输出 | 转其他 Skill |
|---|---|---|
| 问「会不会缺货」 | 偏差情况 + 标注需结合订单判断 | 缺货 Skill |
| 高于目标且动销偏慢、货龄长 | 偏差情况 + 标注滞库风险 | 货龄滞库 Skill |
| 只问一个数字 | 直接回答，不启动完整流程 | — |

## P2 承接（本 Skill 不做）

待办 / 事件建议卡、未关闭事项续更、历史反馈关联、责任角色推荐、目标波动专项。
