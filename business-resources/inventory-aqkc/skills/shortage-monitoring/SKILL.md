# 基地库存缺货监控 Skill

## 参考资源（按需加载）

- **本 Skill 的 `rules.md`**：本技能的公式、阈值与判断规则
  → 计算与判定前读取
- **`inventory-policy` Skill**：指标口径矩阵、数据与知识访问契约、数据边界与目标版本、证据与行动边界、输出规范
  → 取数前读它的 `rules/data-access-contract.md`；口径解释、排名与筛选前读 `rules/metric-catalog.md`；生成回答前读 `rules/output-guide.md`

## 目标

把当前订单、可用库存、占用量、在途与预计入库等输入，转化为可追溯、可复核的当前订单缺口结论：缺口量、影响范围、原因线索、可补方向和数据边界。

## 触发场景

- 「现在缺什么货」「缺多少」「哪些订单发不出去」
- 「这个 SKU 什么时候能补上」
- 「为什么库存不少还缺货」
- 「订单满足率和当前缺货有什么区别」

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 分析范围 | 基地、品类、SKU、客户类型 | 是 |
| 未备单完成订单 | 需求量、已占用量 | 是 |
| 可用库存 | 当前可用库存 | 是 |
| 数据截止时间 | 订单与库存各自时间 | 是 |
| 在途与调拨 | 在途量、预计到货时间 | 否 |
| 生产计划 | 近期预计入库量与日期 | 否 |
| 动销与计划 | 近 30 日动销量、日均动销、日均计划量 | 否 |
| 事后订单满足率 | 当月已发货完成口径 | 否 |

**不使用金额口径，不使用「订单量 − 库存」近似算法。**

## 执行步骤

### 第 1 步：校验订单与库存口径
确认订单状态范围（未备单完成订单）、占用量口径、可用库存口径与数据时间，并记录。

### 第 2 步：计算当前订单缺口
按 `rules.md` 公式计算：
`当前订单缺口 = max(0, 未备单完成订单需求量 − 未备单完成订单已占用量 − 当前可用库存)`
- 缺口 = 0 → 「当前订单可满足」
- 可用库存 = 0 → 「完全缺货」
- 有库存但不足 → 「部分缺口」

### 第 3 步：缺口分层
按 `rules.md` 默认阈值分为 一般 / 关注 / 紧急（按缺口数量与影响面，不用金额）。
排序：风险等级，其次缺口量。

### 第 4 步：关联影响范围
统计影响订单数、客户数、SKU 数；有客户优先级时标注重点客户。

### 第 5 步：关联在途与预计入库（如有数据）
计算预计可补量（**不推算到货时间**），区分「近期有预计入库量」与「短期无补货安排」。预计入库时间 ≠ 实际到货时间，不作为承诺。

### 第 6 步：区分事后满足率与当前缺口
用户问订单满足率时，说明它是**事后**已发货完成口径（1 − 缺货量 ÷ 需求数量），不代表当前交付风险；不得互相倒推。

### 第 7 步：生成原因线索
按 `rules.md` 触发条件生成，每条标注证据状态，最多 5 条。

### 第 8 步：生成补货建议（P1）
按 `rules.md` 第 7 节输出**补货 SKU 清单 + 建议补货量 + 测算依据**（目标库存 − 当前库存 − 在途 − 7 日内预计入库，存在订单缺口时取缺口为下限），标注【待人工确认】。
**不给到货时间**（缺乏可靠依据）、不生成正式补货单、不使用自算安全库存。若同一 SKU 同时存在 60 天以上或动销偏慢库存，先提示「先消化再补」的冲突。

### 第 9 步：整理数据边界
按 `inventory-policy` Skill 的 `rules/data-boundary.md` 整理：数据时间、订单状态范围、库存口径、缺失字段、不可判断项。

### 第 10 步：形成交付结果
按 `inventory-policy` Skill 的 `rules/output-guide.md` 输出。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 当前订单缺口 = max(0, 未备单完成需求量 − 已占用量 − 可用库存)
- 不等同于「订单量 − 占用量」或「订单量 − 库存」
- 缺口分层按数量与影响面，不用金额
- 事后订单满足率 ≠ 当前交付风险
- 预计入库时间 ≠ 实际到货时间
- 输出补货 SKU 与补货量测算（属建议），不承诺到货时间、不生成正式补货单
- 数据缺失不填 0；建议 ≠ 已执行

## 默认交付

> 输出结构、语言、数字、引导格式统一遵守 `inventory-policy` Skill 的 `rules/output-guide.md`：快速问数用四段式，分析类问题用「核心结论 → 关键数字 → 问题根因 → 行动建议（短/中/长期 + 责任角色）→ 风险提示 → 数据说明」，报告类按模板输出。


1. 核心结论（一句话：缺口 SKU 数、缺口总量、影响订单数）
2. 分析范围、粒度、数据时间与订单口径
3. 缺口汇总（按基地 / 品类）
4. 重点缺口 TOP 10（按风险等级 + 缺口量）
5. 影响范围（订单数、客户数、SKU 数）
6. 在途与预计入库（如有数据）
7. 原因线索（带证据状态）
8. 补货建议（SKU、建议补货量、测算依据，标注待人工确认）
9. 数据边界

## 边界与禁止动作

- 不生成正式补货单、不调整生产计划、不调拨、不承诺到货时间、不定责、不推荐责任人（P1）
- 低于目标 ≠ 当前缺货；当前订单缺口 ≠ 事后订单满足率
- 不使用自算安全库存；不使用金额口径

## 与其他 Skill 的边界

| 场景 | 本 Skill 输出 | 转其他 Skill |
|---|---|---|
| 「库存为什么少了」 | 缺口情况 + 标注需结合目标判断 | 库存偏差 Skill |
| 缺货与批次/货龄相关 | 缺口情况 + 标注需核查批次货龄 | 货龄滞库 Skill |
| 只问一个 SKU 是否缺货 | 直接回答，不启动完整流程 | — |

## P2 承接

周补货执行与排产落位、待办 / 事件、历史反馈、责任与协同角色、到货时间承诺。
