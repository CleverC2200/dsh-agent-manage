# 基地库存缺货监控 — 规则与阈值

## 1. 计算公式

| 指标 | 公式 | 说明 |
|---|---|---|
| 未备单完成订单需求量 | 处于「未备单完成」状态订单的需求数量合计 | 按订单状态过滤 |
| 未备单完成订单已占用量 | 上述订单自身已占用的数量合计（**只算这批订单的占用**） | 占用不等于出库 |
| 可用库存 | 当前库存 − 占用量（**备单完成订单占用 + 未备单完成订单占用**）− 锁定 / 冻结 / 质检等不可用库存 | 已扣掉全部占用，不再含任何订单占用 |
| 备单量 | SUM(未备单完成订单量) | 不含已备单完成未发货 |
| 当前订单量 | 备单量 + 已备单未发货占用量（剔除已作废 / 已取消） | 看板「当前订单」 |
| 订单还需满足量（订单 + SKU 级） | `max(订单需求量 − 该订单自身占用量, 0)` | 只取**未备单完成**订单；改单 / 超额占用出现负数按 0；需求量与占用量必须同源同状态 |
| 总还需满足量（基地 + SKU 级） | Σ 订单还需满足量 | 逐单相加，不再截零 |
| 当前订单缺口 | 基地 + SKU 级：`max(总还需满足量 − 当前可用库存, 0)`；基地层：Σ 各 SKU 缺口 | **唯一口径**；**可用库存只在这一层减一次**，不能摊到订单层；基地层不二次截零 |
| 缺口率 | 当前订单缺口 ÷ 未备单完成订单需求量 × 100% | 分母 > 0 时计算 |
| 可满足率 | min(可用库存 ÷ 总还需满足量, 1) × 100% | 分母用**总还需满足量**，不用需求量，否则满足率被低估 |
| 事后订单满足率 | 1 − 缺货量 ÷ 需求数量（当月已发货完成订单） | **事后指标**，与当前缺口互不替代 |

禁止口径：缺口 = 订单量 − 占用量；缺口 = 订单量 − 当前库存；**缺口 = 未备单订单量 − 全部占用 − 可用库存（自身占用被扣两次，缺口低估）**；缺口 = 未备单订单量 − 可用库存（漏减自身占用，缺口高估）；**把可用库存摊到订单层再截零（富余订单余量被丢掉，缺口低估）**；**基地层对汇总缺口二次截零**；把备单完成订单的需求或占用代入缺口；用当前缺口倒推订单满足率。

口径边界：备单完成订单已下发 WMS，即使未完全满足也视为无需求，不进入缺口计算；存在超额占用（改单）时 `Σ max(需求量 − 占用, 0) < Σ需求量 − Σ占用`，**不能再用「需求 + 备单完成占用 + 锁定 − 库存」的等价式**，必须按三层算。

特殊情况：
- 需求量为 0 / 无订单记录：缺口按 0，标注「无待发订单」，不计算缺口率
- 无占用量、无可用库存：按 0 参与计算，缺口 = 需求量；这是正常业务情形（订单完全未被覆盖），不标缺失、不作废
- 缺口按 SKU 算出来 ≤ 0：按 0 计入，属正常无缺口
- 整批数据未到（如库存快照未覆盖该基地）：在数据说明里写明覆盖范围，不逐 SKU 判缺失
- 不使用金额口径

## 2. 缺口分层（受控配置默认值，待业务确认）

| 层级 | 缺口量 | 附加条件 | 标记 |
|---|---|---|---|
| 一般 | < 50 件 | — | 🟡 |
| 关注 | 50 ~ 200 件 | 或多订单受影响 | 🟠 |
| 紧急 | > 200 件 | 或影响重点客户 / 交付计划 | 🔴 |

自动升级条件：涉及重点客户；缺口持续且无预计补货；缺口率 > 50%。命名统一为 高风险（红）/ 关注（橙）/ 正常（绿）体系下的缺口等级。

## 3. 重点对象筛选

排序：风险等级 → 缺口量 → 影响订单数。必纳入：紧急对象、用户点名对象、影响重点客户的对象。

## 4. 影响评估

| 指标 | 计算 |
|---|---|
| 影响订单数 | 存在缺口的订单数 |
| 影响客户数 | 去重客户数 |
| 影响 SKU 数 | 去重 SKU 数 |
| 预计影响天数 | 缺口量 ÷ 近 30 日日均动销（无动销数据时不计算） |

发货优先级仅为建议：重点客户优先、先到订单优先、小批量优先；不自动调整分配。

## 5. 动销与计划的使用

- 判断「缺口是否要紧」用近 30 日日均动销与日均计划量比对（动销达成 = 日均动销 ÷ 日均计划量）
- **不使用动销率（%/周、%/日）**
- 动销数据缺失时：只输出缺口量与影响面，不判断消化速度

## 6. 原因线索（最多 5 条，标注证据状态）

| 方向 | 子原因 | 触发条件 | 证据状态 |
|---|---|---|---|
| 需求端 | 订单突增 | 近 3 日订单量 > 近 30 日日均 × 200% | 有支撑未验证 |
| 需求端 | 客户集中拉货 | 前 3 大客户拉货占比 > 70% | 有支撑未验证 |
| 需求端 | 计划偏低 | 实际订单 > 计划 × 150% | 推测（有预测数据则为有支撑） |
| 供给端 | 生产延迟 | 应入库未入库数量 > 0 | 已验证（有计划数据时） |
| 供给端 | 调拨延迟 | 预计到货日已过未到货 | 已验证（有调拨数据时） |
| 库存端 | 占用偏高 | 已占用量接近或超过可用库存 | 已验证（有占用数据时） |
| 库存端 | 仓库 / 批次不可发 | 有库存但仓库或批次不满足发货要求 | 推测 |

## 7. 补货建议（P1 纳入：补货 SKU + 补货量测算）

| 情形 | 方向建议 |
|---|---|
| 有在途调拨 | 跟进调拨到货，确认可用时间 |
| 同基地其他仓库有可用库存 | 建议基地内调剂 |
| 无在途、近期无排产 | 建议确认排产节奏与生产可行性 |
| 其他基地有可供量 | 建议评估跨基地调拨可行性 |

### 7.1 建议补货量

```text
先按 基地 + SKU 算：建议补货量 = max(0, max(当前订单缺口, 目标库存差额) − 在途量)
其中：目标库存差额 = 目标库存 − 当前库存；在途量 = 调拨在途量 + 调拨备单量（或 7 日内预计入库量，需标注口径）
再逐级汇总（禁止先汇总总量再算）
```

| 情形 | 处理 |
|---|---|
| 目标库存缺失 | 只按当前订单缺口给参考量，并标注「目标缺失，补货量仅按缺口测算」 |
| 目标库存差额为负（当前高于目标） | 不因高于目标就不补：存在当前订单缺口时仍按缺口测算，并提示「高库存与缺货并存，需核查库位 / 批次 / 客户要求」 |
| 无在途 / 无预计入库数据 | 按 0 处理但**必须标注**「未考虑在途与预计入库，实际补货量可能更低」 |
| 日均计划量为 0 或缺失 | 不影响本公式；不输出周转结论 |
| 该 SKU 存在 61 天以上或 41-60 天动销偏慢库存 | 先提示消化冲突，建议「先消化再补」，不直接给出补货量 |

不使用自算安全库存（安全库存与目标库存均由大数据落表，Agent 不重算）。

### 7.2 补货 SKU 清单（输出字段）

基地 / 品类 / SKU / 当前库存 / 目标库存 / 在途量 / 7 日内预计入库量 / 当前订单缺口 / 建议补货量 / 风险等级 / 测算依据 / 状态【待人工确认】。

### 7.3 约束

- **不给到货时间**（缺乏可靠测算依据），只说明「预计入库时间」数据是否存在
- 不生成正式补货单、不指定生产批次、不调整排产
- 同一 SKU 不与滞库结论冲突：既缺货又高货龄时，先提示冲突再给建议
- 排序：风险等级 → 建议补货量 → 缺口量

## 8. 数据完整性校验

必备字段：SKU 编码、基地、未备单完成订单需求量、可用库存、数据截止时间。缺字段时按指标分别处理，**不整行作废**：无可用库存或占用量 → 按 0 参与计算，缺口 = 需求量；无订单 → 缺口按 0；其余列照常输出。

可选字段缺失时：无占用量→不作确定结论；无在途 / 排产→不给可补时间判断；无动销→不判断消化速度。

## 9. P2 承接

周补货执行与排产落位、待办 / 事件、历史反馈、责任与协同角色、到货时间承诺。
