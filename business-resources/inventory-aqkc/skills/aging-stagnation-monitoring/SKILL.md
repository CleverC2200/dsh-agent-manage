# 基地库存货龄与滞库监控 Skill

## 参考资源（按需加载）

- **本 Skill 的 `rules.md`**：本技能的公式、阈值与判断规则
  → 计算与判定前读取
- **`inventory-policy` Skill**：指标口径矩阵、数据与知识访问契约、数据边界与目标版本、证据与行动边界、输出规范
  → 取数前读它的 `rules/data-access-contract.md`；口径解释、排名与筛选前读 `rules/metric-catalog.md`；生成回答前读 `rules/output-guide.md`

## 目标

把库存批次、货龄、动销与计划等输入，转化为可追溯、可复核的货龄与滞库结论：货龄分布、大日期对象、滞库风险、原因线索、消化方向和数据边界。

## 触发场景

- 「货龄分布怎么样」「平均货龄多少」
- 「大日期有多少」「60 天以上库存有多少」
- 「哪些 SKU 卖不动」「高库存低动销」
- 「滞库风险怎么看」
- 「未来 7 日 / 14 日哪些库存会超龄」→ 由 `future-aging-projection` Skill 推演，本 Skill 先给当前货龄结构

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 分析范围 | 基地、品类、SKU、仓库 | 是 |
| 分析粒度 | 基地 / 品类 / SKU / 批次 | 是 |
| 库存数据 | 当前库存、批次数量、入库日期 | 是 |
| 动销数据 | 近 30 日动销量、日均动销 | 是 |
| 数据截止时间 | 库存 / 动销 / 计划各自时间 | 是 |
| 目标库存与库存差额 | 当前目标版本、差额 | 否 |
| 日均计划量 | 目标库存版本绑定的计划日均 | 否 |

**本 Skill 不涉及保质期与效期数据**（公司产品保质期统一 12 个月），不做效期比例推算。

## 执行步骤

### 第 1 步：校验批次与动销数据
确认批次粒度与入库日期完整性、动销数据时间范围与口径，并记录。

### 第 2 步：计算货龄
按 `rules.md`：批次货龄 = 当前日期 − 入库日期；SKU / 品类平均货龄按数量加权。无入库日期的批次标注「货龄未知」，不参与货龄排名。

### 第 3 步：货龄分段
按 0-30 / 31-40 / 41-60 / 60 天以上分段（与看板一致），统计各段数量与占比。

### 第 4 步：动销与计划比对
按 `rules.md` 计算近 30 日动销量、日均动销、动销达成（日均动销 ÷ 日均计划量），判定动销偏快 / 正常 / 偏慢；动销量为 0 的单列「无动销」。

### 第 5 步：滞库风险判定
按 `rules.md` 同时结合库存差额、货龄、动销达成判定，输出 高风险 / 关注 / 正常，不用单一指标定滞库。

### 第 6 步：大日期专项输出（P1）
筛选货龄 60 天以上的批次 / SKU，按货龄降序输出清单（数量、占比、所在基地与仓库、动销情况），并给出处理方向。
明确标注：「大日期只按货龄判定，处理方案需业务确认」；P1 不做专项台账与锁定。

### 第 7 步：生成原因线索
按 `rules.md` 触发条件生成，每条标注证据状态，最多 5 条。不做目标设置合理性的推断。

### 第 8 步：生成消化方向建议
按 `rules.md` 给出方向性建议（优先消化、基地内调剂、跨基地调拨评估、控制新增入库），标注【待人工确认】；涉及报废、降价等重大决策必须业务确认，P1 不给结论。

### 第 9 步：整理数据边界
按 `inventory-policy` Skill 的 `rules/data-boundary.md` 整理：数据时间、批次完整性、动销口径、缺失字段、不可判断项。

### 第 10 步：形成交付结果
按 `inventory-policy` Skill 的 `rules/output-guide.md` 输出。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 货龄 = 当前日期 − 入库日期；平均货龄按数量加权
- 货龄分段：0-30 正常 / 31-40 关注 / 41-60 重点关注 / 60 天以上大日期
- 大日期只按货龄判定，不涉及效期
- 动销只用数量口径（近 30 日动销量、日均动销、动销达成），不用动销率
- 滞库需同时看库存差额、货龄、动销达成，不用单一指标
- 消化建议 ≠ 处理指令；数据缺失不填 0

## 默认交付

> 输出结构、语言、数字、引导格式统一遵守 `inventory-policy` Skill 的 `rules/output-guide.md`。


1. 核心结论（一句话：滞库高风险对象数、大日期库存量、动销偏慢对象数）
2. 分析范围、粒度、数据时间与动销口径
3. 货龄分布（四段数量与占比）
4. 大日期清单（60 天以上）
5. 滞库风险对象 TOP 10（按风险等级 → 货龄 → 库存量）
6. 原因线索（带证据状态）
7. 消化方向建议（待人工确认）
8. 数据边界

## 边界与禁止动作

- 不决定报废、不发起促销、不调价、不调拨、不定责、不推荐责任人（P1）
- 高于目标 ≠ 滞库；货龄长 ≠ 一定有问题；动销偏慢 ≠ 一定滞库
- 不做效期比例判断；不做大日期专项锁定与台账（P2）
- 处理建议 ≠ 正式处理指令

## 与其他 Skill 的边界

| 场景 | 本 Skill 输出 | 转其他 Skill |
|---|---|---|
| 「为什么库存这么高」 | 货龄与动销情况 + 标注需结合目标判断 | 库存偏差 Skill |
| 滞库可能与订单结构有关 | 货龄情况 + 标注需结合订单 | 缺货 Skill |
| 只问一个 SKU 货龄 | 直接回答，不启动完整流程 | — |
| 问未来 7 / 14 日预计超龄 | 先给当前货龄结构，再说明可转未来推演 | future-aging-projection Skill |

## P2 承接

大日期专项台账与每月锁定、待办 / 事件、历史反馈、责任判定与协同角色、费用与报废评估。
