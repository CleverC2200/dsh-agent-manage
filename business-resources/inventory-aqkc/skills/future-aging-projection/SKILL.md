# 未来 N 日预计超龄 Skill

## 参考资源（按需加载）

- **本 Skill 的 `rules.md`**：本技能的公式、阈值与判断规则
  → 计算与判定前读取
- **`inventory-policy` Skill**：指标口径矩阵、数据与知识访问契约、数据边界与目标版本、证据与行动边界、输出规范
  → 取数前读它的 `rules/data-access-contract.md`；口径解释、排名与筛选前读 `rules/metric-catalog.md`；生成回答前读 `rules/output-guide.md`

## 目标

按批次推演未来 7 / 14 日内将超过 60 天货龄的库存，输出新增超龄对象、数量与批次，并明确说明推演窗口、是否扣减预计动销、是否排除当前 60 天以上库存。

## 触发场景

- 「未来 7 日哪些库存会超货龄」「未来 14 日新增多少大日期」
- 「未来 7 日预计超龄是什么意思」
- 「当前 60 天以上和未来 7 日预计超龄有什么区别」
- 日报 / 大日期报告中的未来窗口段

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 分析范围 | 基地、品类、SKU、仓库 | 是 |
| 批次数据 | 批次数量、入库日期、当前货龄 | 是 |
| 动销数据 | 近 30 日动销量 / 日均动销（用于扣减窗口内消耗） | 是（缺失则标注未扣减） |
| 推演窗口 | 7 日 / 14 日（30 日暂不支持） | 是 |
| 当前 60 天以上清单 | 用于排除，避免重复计入 | 是 |
| 预计出库 / 订单 | 窗口内预计出库量（可选，优先于日均动销） | 否 |
| 数据截止时间 | 批次与动销各自时间 | 是 |

**不扣减未来生产入库。**

## 执行步骤

### 第 1 步：确认批次与动销口径
确认批次粒度、入库日期完整性、动销数据时间范围；记录窗口（7 日 / 14 日）。

### 第 2 步：排除当前 60 天以上库存
先取当前货龄 ≥ 60 天的批次清单，本次推演**不重复计入**，并在输出中明确说明。

### 第 3 步：逐批推演
对当前货龄 < 60 天的批次：
1. 计算窗口结束时货龄 = 当前货龄 + 窗口天数
2. 按先进先出扣减窗口内预计消耗（优先预计出库 / 订单，其次近 30 日日均动销 × 窗口天数）
3. 扣减后仍有剩余且窗口结束时货龄 ≥ 60 天 → 计入「未来 N 日预计超龄」
4. 无动销数据时按未扣减测算，并显式标注「本次未扣减预计动销」

### 第 4 步：汇总与排序
按基地 / 品类 / SKU / 批次汇总数量与占比；排序：预计超龄日期（升序）→ 数量（降序）。

### 第 5 步：与当前 60+ 区分说明
明确写出：当前 60+ 是存量风险，未来 N 日预计超龄是新增风险，两者**不能相加**。

### 第 6 步：生成建议
对预计超龄对象给方向性建议（提前消化、优先出库、关注动销），标注【待人工确认】；不做责任判定，不创建专项。

### 第 7 步：整理数据边界
窗口、是否扣减动销、是否排除当前 60+、批次与动销数据时间、不可判断项。

### 第 8 步：形成交付结果
按 `inventory-policy` Skill 的 `rules/output-guide.md` 输出；推演结果标注为预警，不写成既定事实。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 粒度：基地 + SKU + 批次；先进先出扣减
- 窗口：P1 支持未来 7 日与 14 日（30 日不支持）
- 必须排除当前 60 天以上库存，不与存量相加
- 不扣减未来生产入库
- 无动销数据时按未扣减测算并标注
- 推演属预警，不直接升级事件（事件属 P2）

## 默认交付

> 输出结构、语言、数字、引导格式统一遵守 `inventory-policy` Skill 的 `rules/output-guide.md`。


1. 核心结论（一句话：未来 7 / 14 日预计新增超龄批次与数量）
2. 推演口径（窗口、扣减方式、是否排除当前 60+）
3. 按基地 / 品类汇总
4. 预计超龄清单（基地 / 仓库 / SKU / 批次 / 数量 / 当前货龄 / 预计超龄日期）
5. 与当前 60 天以上库存的关系说明
6. 建议与待确认
7. 数据边界

## 边界与禁止动作

- 不与当前 60+ 相加；不把推演结果说成既定事实
- 不扣减未来生产入库；不做 30 日窗口
- 不创建大日期专项、不定责、不推荐责任人（P1）

## P2 承接

30 日窗口推演、未来货龄风险转入待办 / 事件、专项台账与锁定。
