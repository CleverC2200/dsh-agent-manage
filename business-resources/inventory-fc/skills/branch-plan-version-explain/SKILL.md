# 分仓计划与版本解释 Skill

## 参考资源（按需加载）
- **先加载 `branch-policy` Skill**（共享规范：指标口径、数据边界、取数契约、证据与行动边界、输出规范；内部包，不单独回答用户）。涉口径、排名、取数、分析、报告之前必读。

- **`rules.md`**：四个计划公式、增长率构成、版本与来源优先级、计划完整性判定、特殊业务标记 → 第 2、3、4、5 步前读取
- **branch-policy 数据边界**：计划版本与来源取值规则、缺失处理 → 第 2、6 步前读取
- **branch-policy 证据与行动边界**：证据状态与行动边界（增长率属测算，不得写成已验证预测） → 第 5 步前确认
- **branch-policy 输出规范**：计划与版本相关表述要求 → 第 7 步前读取
- **branch-policy 取数契约**：取数与知识查询契约（版本与来源整体选定、上卷铁律） → 取数前必读
- **branch-policy 指标口径**：补货与计划类指标口径、白名单 → 第 1 步前读取

本 Skill 只做**展示与解释**：四个正式计划由大数据计算并提供结果，Agent **不重新生成正式计划**；页面临时调整只生成预览。

## 目标

把四个计划、目标月份、版本、来源、增长率输入与库存状态解释清楚：本次用的是哪个版本与来源、每个计划怎么算出来的、为什么计划发生变化的可能原因、哪些情况属于计划不完整或缺失，以及业务能确认什么、不能改什么。

## 触发场景

- 「本月出货计划是多少」「次月调拨计划怎么算的」
- 「用的是月初版本还是滚动版本」「人工计划和 BI 计划哪个生效」
- 「计划为什么比上个月高了」「增长率是怎么来的」
- 「为什么这个分仓没有计划」「人工计划不完整是什么意思」
- 「临时改的数字算正式计划吗」

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 分析范围 | 分仓、目标月份、品类、物料组、SKU | 是 |
| 计划版本 | 月初版本 / 滚动版本 | 是 |
| 计划来源 | 人工提报 / BI 计算 | 是 |
| 四个计划量 | 本月出货计划、本月调拨计划、次月出货计划、次月调拨计划 | 是 |
| 增长率输入 | 分仓辐射客户月度目标金额、参考月份实际、历史同期、近 3 个月平均 | 是（用于解释） |
| 库存与在途 | 当前可用库存、两类在途 | 是（用于解释调拨计划） |
| 补货周期 | 已生效周期（未配置默认 7 天） | 是 |
| 计划状态 | 是否预览、是否人工计划不完整、是否有效提报 | 是 |

**计划量输出为非负整数；不使用金额口径**（金额只用于分仓整体增长率的解释）。

## 执行步骤

### 第 1 步：确定目标月份与版本
按「分仓 + 目标月份」整体确定版本：**存在月初版本则用月初版本，否则用滚动版本**。不能按 SKU 混用。

### 第 2 步：确定计划来源
在选定版本内：**存在完整有效人工计划则用人工提报，否则用 BI 计划**。人工计划缺 SKU 时标记「人工计划不完整」，**不自动按 SKU 回退 BI**。

### 第 3 步：解释四个计划的计算
按 `rules.md` 公式逐项说明输入：增长率、参考月份实际出货、历史同期、补货周期、当前可用库存、基准出货计划（1–20 日本月计划、21 日起次月计划）、日均出货计划、预计月末库存。明确「在途不在四个计划公式中重复抵扣」。

### 第 4 步：解释计划为什么变化
按 `rules.md` 列出可能原因（增长率变化、上月实际出货变化、补货周期调整、库存水位变化、版本或来源切换、人工提报调整），每条标注证据状态，最多 5 条，并区分「已证原因」与「待确认原因」。

### 第 5 步：说明增长率性质
分仓整体增长率由大数据按分仓辐射客户月度目标金额总额计算，**不按 SKU 拆金额目标、不做金额到件数换算**；它是**增长率不是倍数**，实际倍数为 1 + 增长率。必须说明它属测算逻辑，**不是经过完整业务验证的预测模型**，不得表述为预测准确结论。任一必要目标缺失时结果标记数据不完整，**不得把缺失当 0**。

### 第 6 步：判定计划完整性
按 `rules.md`：整行四个计划量为空或 0 时不形成有效提报；业务明确填 0 视为有效 0；人工计划未覆盖该版本需要的 SKU 范围时标记不完整，不作为有效人工版本。

### 第 7 步：说明预览与生效边界
页面临时修改只形成预览；保存或导入后才形成人工计划结果。临时修改补货周期只影响当前看板预览，不影响定时预警。**Agent 不判断「是否最新版本」**，只按优先级取值并展示所选版本与来源。

### 第 8 步：形成交付结果
按 **branch-policy 输出规范** 输出，必须写出目标月份 + 版本 + 来源 + 是否预览。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 月初版本优先于滚动版本；人工提报优先于 BI
- 版本与来源按「分仓 + 目标月份」整体选定，**不能按 SKU 混用**
- 人工计划不完整时不作为有效人工版本，不按 SKU 回退 BI
- 整行四个计划量为空或 0 不形成有效提报；明确填 0 视为有效 0
- 增长率 = 目标环比 × 40% + 历史同期 × 40% + 近 3 个月平均 × 20%；是增长率不是倍数
- 在途不在四个计划公式中重复抵扣
- 正式计划由大数据计算，Agent 只展示、解释、承接人工确认
- 缺数按 0；计划量输出非负整数

## 默认交付

1. 核心结论（本次采用的目标月份、版本与来源）
2. 四个计划值（本月/次月出货、本月/次月调拨）
3. 计算输入说明（增长率构成、参考实际、库存与周期）
4. 增长率性质与数据完整性说明
5. 计划变化的可能原因（带证据状态）
6. 计划完整性判定（是否有效人工计划、是否不完整）
7. 可确认与不可修改的边界
8. 数据边界（数据时间、版本、来源、缺失项）

## 边界与禁止动作

- 不在对话中重新生成或覆盖正式计划；不用临时计算替代正式计划
- 不按 SKU 混用版本或来源；不把预览值说成正式计划
- 不把增长率说成已验证的预测准确结论；不做金额到件数换算
- 不直接发布正式计划、不修改计划版本优先级、不自动补 BI
- 不定责、不推荐责任人（P1）；不承诺到货时间
