# 分仓计划与版本解释 — 规则与阈值

## 1. 四个计划的范围与公式

四个计划 = 本月出货计划、次月出货计划、本月调拨计划、次月调拨计划。正式计算由大数据完成，Agent 负责展示、解释与承接人工确认。

```text
分仓月度目标金额 = 分仓辐射客户月度目标金额之和

目标环比增长率 = 本月目标金额 ÷ 上月目标金额 - 1
历史同期增长率 = 本月目标金额 ÷ 去年同月目标金额 - 1
近 3 个月平均增长率 = 最近 3 个月目标环比增长率的平均值
分仓整体增长率 = 目标环比增长率 × 40% + 历史同期增长率 × 40% + 近 3 个月平均增长率 × 20%

本月出货计划(SKU) = 上月分仓实际出货量(SKU) × (1 + 分仓整体增长率)
次月出货计划(SKU) = 本月出货计划(SKU) × (1 + 分仓整体增长率)

基准出货计划 = 计算日 1–20 日 → 本月出货计划
               计算日 21 日及以后 → 次月出货计划
日均出货计划 = 基准出货计划 ÷ 基准月自然日数（本月计划用本月自然日数、次月计划用次月自然日数）
次月日均出货量 = 次月出货计划 ÷ 次月自然日数

本月调拨计划 = max(0, 安全库存周转天数 × 日均出货计划 - 当前可用库存量 + 本月出货计划)
预计本月末库存 = 当前可用库存量 + 本月调拨计划 - 本月出货计划
次月调拨计划 = max(0, 安全库存周转天数 × 次月日均出货量 - 预计本月末库存 + 次月出货计划)
```

| 要点 | 说明 |
|---|---|
| 安全库存周转天数 | 已生效补货周期 + 3 天备货期；周期按分仓配置，未配置默认 7 天 |
| 日均出货计划 | 基准出货计划 ÷ 基准月自然日数；基准按计算日切换：**1–20 日用本月出货计划、21 日及以后用次月出货计划**；出货计划导入版优先，无导入用系统版 |
| 增长率性质 | 是**增长率**，实际计算倍数为 1 + 增长率 |
| 金额使用边界 | 只在分仓总量层面用于计算增长率，**不按 SKU 拆金额目标、不做金额到件数换算** |
| 在途处理 | 在途用于库存水位、展望周转与补货风险判断，**不在四个计划公式中重复抵扣** |
| 计划量取值 | 输出为非负整数 |

## 2. 计划版本与来源优先级

```text
目标月份存在月初版本 → 使用月初版本
目标月份不存在月初版本 → 使用滚动版本
选定版本存在完整有效人工计划 → 使用人工提报
选定版本不存在完整有效人工计划 → 使用 BI 计划
```

| 规则 | 说明 |
|---|---|
| 选择粒度 | 按「分仓 + 目标月份」整体确定，**不能按 SKU 混用** |
| 人工计划缺 SKU | 标记「人工计划不完整」，不作为有效人工版本，**不自动按 SKU 回退 BI** |
| 九月次月计划 | 保存为 10 月滚动计划 |
| 十月本月计划 | 保存为 10 月月初计划 |
| 整行为空或 0 | 不形成有效提报 |
| 业务明确填 0 | 按有效 0 处理 |
| 页面修改 | 只影响预览；保存或导入后才形成人工计划结果 |
| 临时改周期 | 只影响当前看板预览，不影响定时预警 |

Agent **不判断「是否最新版本」**，只按上述优先级取值并展示所选版本与来源。

## 3. 增长率的数据完整性规则

| 情况 | 处理 |
|---|---|
| 目标金额、历史同期、近 3 个月数据齐备 | 按权重计算，可正常输出 |
| 任一必要目标数据缺失 | 结果必须标记**数据不完整**，**不得把缺失默认为 0** |
| BI 目标缺失 | 仍可提示按历史数据计算的参考口径，但必须标注「缺少目标数据」，不得伪装成有目标的完整结果 |

表述约束：增长率属测算逻辑，**不是经过完整业务验证的预测模型**；不得表述为预测准确的结论，也不得倒推为实际销售结果。

## 4. 计划为什么变化（可能原因，标注证据状态，最多 5 条）

| 方向 | 子原因 | 触发条件 | 证据状态 |
|---|---|---|---|
| 增长率 | 目标或历史同期变化 | 目标金额、历史同期或近 3 个月平均发生变化 | 已验证（有输入数据时） |
| 基线 | 上月实际出货变化 | 上月分仓实际出货量高于或低于前期 | 已验证 |
| 周期 | 补货周期调整 | 补货周期近期由小变大或由大变小 | 已验证（有变更记录时） |
| 库存 | 库存水位变化 | 当前可用库存显著低于或高于前期 | 已验证 |
| 版本或来源 | 月初 / 滚动切换、人工 / BI 切换 | 本次版本或来源与上次不同 | 已验证（有版本记录时） |
| 提报 | 人工提报调整 | 人工计划覆盖了部分或全部 SKU | 有支撑未验证 |
| 业务 | 活动、节令、新品、替代、清库标记 | 存在特殊业务标记 | 有支撑未验证 |
| 数据 | 计划结果缺失或刷新失败 | 无有效计划结果 | 数据缺失 |

不做目标设置合理性的推断，不解释大数据内部计算过程。

## 5. 特殊业务标记的边界

| 标记类型 | 可维护内容 | Agent 处理 |
|---|---|---|
| 节令切换 | 产品/品类、节令日期、关注窗口、处理要求 | 标记并提示人工确认，不自动改计划 |
| 产品替代 | 原 SKU、替代 SKU、替代关系、生效日期 | 标记，不自动抵扣计划 |
| 新品 | 上市日期、铺货分仓、首批计划、爬坡说明 | 标记，不自动生成计划 |
| 活动 / 大单 | SKU、客户、数量、活动窗口 | 单独提示业务确认 |
| 清库 / 下市 | SKU、清库日期、去化要求 | 控制新增补货，转去化处理 |

特殊标记未生效或缺少关键依据时，Agent **不得自动改量**；上月无实际出货的 SKU 不自动生成虚假计划。

## 6. 计划完整性判定

| 情况 | 判定 | 输出要求 |
|---|---|---|
| 选定版本存在完整有效人工计划 | 人工提报为有效来源 | 标注版本、来源、确认人（如可得）与确认时间 |
| 人工计划未覆盖该版本需要的 SKU 范围 | 人工计划不完整 | 标记不完整，不作为有效人工版本，不按 SKU 回退 BI |
| 无人工计划 | 使用 BI 计划 | 标注来源为 BI |
| 选定月份与版本无有效计划结果 | 计划缺失 | 不给派生指标（目标库存、调拨计划），说明缺失范围 |
| 计划量整行为空或 0 | 该行不形成有效提报 | 说明未形成有效提报 |
| 业务明确填 0 | 有效 0 | 与「未填写」区分表述 |

## 7. 展示与表述要求

- 每次涉及四个计划，必须写出**目标月份 + 版本（月初 / 滚动）+ 来源（人工 / BI）+ 是否预览**
- 页面或对话中的临时修改必须标注为预览，不得表述为正式计划
- 涉及目标库存与调拨计划时，同时说明补货周期值与来源
- 四个计划量不得为负数；比例或天数分母为 0 时显示「—」
- 建议类内容标注【待人工确认】与建议责任角色，不写责任人姓名

## 8. 数据完整性校验

必备字段：分仓、目标月份、版本、来源、计划量、数据截止时间。缺字段时按指标分别处理，**不整行作废**：该指标缺数按 0 参与并标注，两个输入都缺的行单列；其余指标照常输出。

可选字段缺失时：无增长率输入 → 只展示计划值并标注无法解释变化；无库存 → 不解释调拨计划；无补货周期 → 按默认 7 天说明并标注。

## 9. P2 承接

待办 / 事件闭环、计划确认失败与计划缺失事件、历史反馈闭环、责任判定与协同角色推荐、升级审批、计划模型与增长率口径复盘、季度或年度计划机制迭代。
