# 分仓覆盖客户库存信号 — 规则与阈值

本文件是 `SKILL.md` 的规则明细。所有判断必须遵守 **branch-policy 证据与行动边界**（证据状态与行动边界）、**branch-policy 数据边界**（数据边界与缺失处理）与 **branch-policy 取数契约**（只读取数、上卷铁律、权限两层）。

## 1. 信号定义与类型

客户库存信号 = 分仓覆盖客户或提货点的**最新库存提报或库存状态信号**，用于辅助判断客户侧高库存、低库存、临期，以及客户侧与分仓侧的库存冲突。

| 信号类型 | 定义 | 判定依据 | 处理 |
|---|---|---|---|
| 低库存 | 客户或提货点提报其库存处于低水位 | 客户提报的库存状态或数量低于业务维护阈值 | 纳入辅助输入；须与分仓缺货量、库存差额、调拨中同时核对后才给方向 |
| 高库存 | 客户或提货点提报其库存处于高水位 | 客户提报的库存状态或数量高于业务维护阈值 | 纳入辅助输入；须核对分仓是否仍有订单缺口或低于目标 |
| 临期 | 客户或提货点提报其库存存在临期或近效期风险 | 客户提报的效期或临期状态 | 只作客户侧提示；分仓侧按分仓口径看货龄（大日期为 91 天及以上） |
| 无提报 | 有覆盖关系但在时效窗口内没有有效提报 | 无提报记录或提报超出时效 | 单列，不判高低、不与分仓比对、不外推 |

信号口径边界（必须与分仓口径区分）：

| 项目 | 客户库存信号 | 分仓库存口径 |
|---|---|---|
| 数据性质 | 客户或提货点自主提报或库存状态信号，**不是主账** | 分仓库存快照，分仓侧可直接取数与计算 |
| 时效 | 按客户提报周期更新，通常日级或周级 | 库存与订单约 2 小时刷新，至少每日一份快照 |
| 覆盖 | 只覆盖当前有效提报范围内的客户，部分覆盖 | 覆盖分仓当前可用库存全量（权限范围内） |
| 库存含义 | 客户侧持有的库存，与分仓库存不重叠 | 分仓当前可用于发货与订单满足的库存，**不含在途** |
| 可否作为计算输入 | 只作辅助输入，**不进入任何公式** | 缺货量、库存差额、建议补货量的计算基准 |
| 能否外推 | 不能对未覆盖客户外推 | 不能在无历史快照时外推趋势 |

固定口径（不得改写）：

```text
缺货量 = max(0, 备单中剩余未占用量 − 当前可用库存量)
库存差额（净额）= 订单扣减后可供库存 − 目标库存量；低于目标量 = max(0, 目标库存量 − 订单扣减后可供库存量)
建议补货量 = max(0, max(缺货量, 低于目标量) − 调拨中)
```

在途必须分「已下单未发货」与「已发货未入库」两类展示，**禁止合并为一个在途量**；当前可用库存**不含在途**。

## 2. 覆盖范围规则

1. 只统计**属授权分仓集合**且**在当前有效提报范围内**的客户；「全部分仓」= 用户授权分仓集合，不等于系统全部分仓。
2. 提报范围内的客户集合是按提报触发的**部分覆盖**，不得等同于分仓服务的全部客户，也不得按客户数比例倒推覆盖客户的库存情况。
3. **未覆盖客户不得外推**：不推测其库存高低，不用同区域、同品类、同规模客户的结果代替，不在排行与引导中出现。
4. **不得把提报当全量、实时、准确的客户库存主账**：提报是客户侧快照，可能存在延迟、口径不一致、只报部分 SKU 的情况。
5. 提报缺失**不填 0**、不按「无库存」或「库存充足」处理；只说明「该客户本次无有效提报，未纳入客户侧判断」。
6. 无客户库存信号时，**不能用分仓库存推断客户库存**；只能给已覆盖客户信号与分仓口径数据。
7. 未授权客户（不在 DMS 用户—分仓关系内）的名称、数值、排名一律不得出现；结果可能通过汇总值反推无权限客户时，降低粒度或说明只能给汇总。
8. 客户提报的 SKU 或包装口径与分仓口径不一致时，只比对可匹配对象，并标注「客户提报口径与分仓口径匹配范围有限」。

## 3. 信号与分仓口径的联动判断

客户信号一律定位为**辅助输入**：判断是否补货、补多少，仍以缺货量、库存差额、当前可用库存、调拨中为主。

| 客户信号 | 分仓侧需同时核对 | 结论方向 |
|---|---|---|
| 客户低库存 | 当前可用库存、备单中剩余未占用量、订单扣减后可供库存、缺货量、库存差额、调拨中、该客户订单未发货量 | 分仓有缺货量或低于目标 → 按缺货量与库存差额走补货判断，客户信号作为佐证；分仓无缺口 → 判断为客户侧消耗偏快或客户自有库存不足，提示关注提货节奏，不单独提高建议补货量 |
| 客户高库存 | 分仓是否仍有缺货量、是否仍提示补货、库存差额、该客户订单未发货量、近 30 日动销 | 分仓仍有缺口 → 说明客户侧积压与分仓侧缺口可能并存，提示核实客户提货计划与订单占用；分仓无缺口且高于目标 → 可作为客户侧积压的辅助线索，同时检查分仓 60-90 天与 91 天及以上结构 |
| 客户临期 | 分仓同类品货龄结构（0-30 / 31-60 / 61-90 / 91 及以上）、分仓大日期库存量与 SKU 数、客户提报批次或效期表述、分仓调拨中 | 分仓同类品 60 天以上集中 → 建议优先分仓侧去化再考虑向客户补货，方向标注【待人工确认】；分仓货龄健康 → 提示客户侧自行消化并核实可售性，不由 AI 判定可售 |
| 无提报 / 提报过期 | 分仓当前可用库存、备单中剩余未占用量、缺货量、库存差额、调拨中 | 完全按分仓口径判断，客户侧不作任何结论；标注「客户信号未覆盖 / 提报过期，本段结论仅基于分仓口径」 |

强制顺序：先分仓口径结论（缺货量、目标差分、可用库存、调拨中），再叠加客户信号佐证；**禁止顺序颠倒**，禁止用客户信号反推缺货或补货量。

## 4. 冲突分析规则

| 冲突现象 | 判定 | 处理 |
|---|---|---|
| 客户库存低但分仓不缺货（无缺货量且订单扣减后可供库存不低于目标） | 客户侧提报低库存不能证明分仓需补货；缺口需由分仓订单与目标口径确认 | 不给补货结论；提示关注客户提货节奏与订单占用，核对客户侧消耗数据；标注【有待人工确认】 |
| 客户库存高但分仓仍提示补货（存在缺货量或订单扣减后可供库存低于目标） | 客户侧高库存与分仓缺口可并存：备单中订单未完全占用、库存差额仍需补足、调拨中不足均可成立 | 按分仓口径保留补货建议；把客户高库存列为核对项，提示核实客户提货计划、订单是否已下未提、是否属小单高频提货；不因客户高库存下调系统建议量 |
| 客户临期与分仓大日期并存（客户提报临期且分仓同类品存在 91 天及以上库存） | 两侧同时存在消化压力，但**客户临期与分仓大日期是两个口径，不得合并计数** | 提示优先分仓侧 60-90 天与 91 天及以上去化，再评估向客户补货；临期处理方案（是否可售、如何处置）须品控与业务确认；方向标注【待人工确认】 |
| 客户提报时间过期（超出时效窗口） | 过期提报只说明历史状态，不能代表当前 | 标注提报具体时间与「已过期，仅作参考」；不作为冲突结论依据，不提高补货优先级；提示客户重新提报后复核 |
| 客户提报与分仓订单方向相反但幅度小（客户低库存且分仓低于目标，但差额很小） | 属正常波动区间，不构成强冲突 | 作为关注项列出，不给处置动作，等下一个提报周期复核 |
| 有覆盖关系但整体无有效提报 | 客户侧数据缺失，不是「客户无库存」 | 按【数据缺失】标注，说明缺什么数据及对结论的影响，只输出分仓口径部分 |

冲突处理共同约束：冲突只提示人工核对，**不自动创建补货、调拨、事件或客户触达**；冲突不改变缺货量、库存差额与建议补货量的计算。

## 5. 时效规则

| 数据项 | 刷新与时间口径 | 过期判定与处理 |
|---|---|---|
| 客户库存提报 | 按客户提报周期更新，通常日级或周级 | 超出该客户提报周期仍未更新 → 标注「提报过期，仅作参考」；只描述历史状态，不参与冲突结论 |
| 分仓库存与订单 | 约 2 小时刷新，至少每日一份快照 | 快照过期 → 说明当前不是最新，展示最近有效快照与数据时间 |
| 调拨在途 / 调拨中 | 约 2 小时 | 剔除已取消、已入库、失效调拨后再使用 |
| 库龄结果 | 以大数据标准库龄结果为准 | 缺失时不给货龄结构结论 |
| 动销 | 近 30 日窗口 | 无出库记录时不给同比类结论 |

统一要求：

1. 输出必须同时标注**提报时间分布**（最新提报时间、最旧提报时间）与各分仓数据源时间。
2. 各数据源时间不一致时按 **branch-policy 数据边界** 第五节处理：分别标注、说明影响、以最接近分析时点的数据为主、建议时间一致时复核。
3. 提报过期只作参考并标注，不因此把客户信号说成当前事实；也不因此删除该客户行，保留可追溯性。
4. 数据刷新未完成时，不输出估算值。

## 6. 原因线索

最多 5 条，每条标注一个证据状态标记（【已验证】/【有支撑未验证】/【推测】/【数据缺失】）。全篇证据状态标记**最多 3 处**。

| 方向 | 子原因 | 触发条件 | 证据状态 |
|---|---|---|---|
| 客户侧 | 客户消耗偏快 | 客户提报低库存，且该客户订单未发货量或近期提货量偏高 | 有支撑未验证 |
| 客户侧 | 客户侧库存积压 | 客户提报高库存，且分仓侧无缺口或已高于目标 | 有支撑未验证 |
| 客户端数据 | 提报过期或口径不一致 | 提报超出时效窗口，或客户 SKU / 包装口径与分仓不一致 | 数据缺失 |
| 分仓侧 | 分仓支撑不足 | 客户低库存且分仓存在缺货量或订单扣减后可供库存低于目标 | 已验证 |
| 分仓侧 | 分仓去化压力 | 客户临期且分仓同类品存在 60-90 天或 91 天及以上库存 | 有支撑未验证 |

禁止：推断客户真实库存总量、客户资金与经营状况、客户是否虚报；禁止把提报缺失写成「客户无库存」；禁止推断「目标库存偏高 / 补货策略激进」等目标设置类结论。

## 7. 建议方向

| 对象 | 方向建议 | 优先级 |
|---|---|---|
| 分仓计划员 | 核对覆盖客户信号的提报时间与分仓缺货量、库存差额后再确认补货节奏（客户信号只作辅助）【待人工确认】 | 高 |
| 分仓计划员 | 对存在冲突的客户，核实客户提货计划、订单占用与调拨中到货情况【待人工确认】 | 中 |
| 分仓运营经理 | 涉及客户临期且分仓存在 60-90 天与 91 天及以上库存时，优先安排分仓侧去化，再由品控与业务确认客户侧可售性【待人工确认】 | 高 |
| 区域计划 | 评估分仓间调拨可行性，覆盖同时存在缺口与客户高库存的分仓【待人工确认】 | 中 |
| 平台计划员 | 复核客户提报覆盖范围与提报质量，反馈未覆盖或长期过期提报的客户清单【待人工确认】 | 低 |

写法约束：只给建议责任角色，P1 不写姓名；每条写清动作 + 对象 + 时间窗；建议总数 ≤5 条且短期优先；所有建议标注【待人工确认】；不建议客户侧自动触达、不承诺到货时间、不预填或提交 DMS 订单。

## 8. 输出字段清单

| 字段 | 说明 |
|---|---|
| 分仓 | 授权范围内的分仓 |
| 区域 | 分仓所属区域 |
| 省区 | 客户所属省区（维度支持时输出） |
| 客户 | 提报客户或提货点（未授权客户不出现） |
| 品类 | 信号覆盖品类 |
| SKU | 信号覆盖 SKU（客户提报口径与分仓不一致时标注匹配范围） |
| 信号类型 | 低库存 / 高库存 / 临期 / 无提报 |
| 提报时间 | 该条提报的提交或更新时间，并标注是否过期 |
| 分仓库存与订单口径 | 当前可用库存（不含在途）、在途（已下单未发货 / 已发货未入库分列）、备单中剩余未占用量、订单扣减后可供库存、缺货量、库存差额、调拨中、建议补货量 |
| 冲突说明 | 冲突现象 + 判定 + 处理方向（无冲突时说明已核对一致） |
| 证据状态 | 【已验证】/【有支撑未验证】/【推测】/【数据缺失】，全篇最多 3 处 |
| 状态 | 【待人工确认】 |

每条信号行不得缺省提报时间与证据状态；数值缺失写「数据缺失」，不写 0；分母为 0 的比率写「—」。

## 9. 数据完整性校验

必备字段：客户覆盖关系、提报时间、信号类型、分仓当前可用库存、备单中剩余未占用量、数据截止时间、权限范围。缺字段时按指标分别处理，**不整行作废**：该指标缺数按 0 参与并标注，两个输入都缺的行单列；其余指标照常输出。

| 缺失情况 | 处理 |
|---|---|
| 无覆盖关系 | 说明客户库存信号未覆盖该客户 / 分仓，不给客户侧结论，只给分仓口径部分 |
| 提报缺失或过期 | 不纳入客户信号判断，标注时间与「仅作参考」，不外推 |
| 分仓可用库存缺失 | 按 0 参与缺货计算，标注「可用库存缺失，缺货按需求量计」 |
| 订单或占用量缺失 | 按 0 参与，标注缺失字段；两者都缺的行不参与缺货、单列 |
| 目标库存或生效计划缺失 | 不给精确库存差额与建议补货量，标注「目标缺失，补货量仅按缺口测算」 |
| 调拨中数据缺失 | 建议补货量中调拨中按 0 处理，**必须标注**「未考虑调拨中，实际建议量可能更低」 |
| 货龄或批次缺失 | 不给分仓货龄结构结论，标注「库存结构无法完整判断」，客户临期与分仓对照降级为方向性提示 |
| 动销缺失 | 不给动销相关线索，只输出库存与货龄事实 |

数据质量分级按 **branch-policy 数据边界** 第六节：完整 / 基本完整 / 不足 / 不可用，输出时同步标注等级与影响范围。缺数按 0；分母为 0 或无数显示「—」；不出现表名、字段名、工具名。

## 10. P2 承接

1. 客户库存主账接入：客户侧库存与提报质量治理、提报口径与分仓 SKU 口径对齐。
2. 客户侧自动触达：低库存、临期提醒的自动推送与提报复核。
3. 事件与升级闭环：客户信号转待办与事件、冲突升级与审批。
4. 责任判定：客户侧与分仓侧责任界定、协同角色推荐与处理时限。
