与其他 Skill 的配合：

- 与 `branch-shortage-monitoring` 配合：先取分仓缺货量、缺货 SKU 与订单占用，再看客户侧信号是否与缺口方向一致；**客户库存低不产生缺货量**。
- 与 `branch-replenishment-demand` 配合：补货判断以缺货量、库存差额、当前可用库存、调拨中为主，客户信号只作辅助输入，不改变建议补货量公式。
- 与 `branch-aging-stagnation-monitoring` 配合：分仓侧按分仓口径看货龄结构（91 天及以上为大日期），客户临期信号只作客户侧提示，两者不合并计算。
- 与 `branch-upstream-base-availability` 配合：需要上游供给承接时说明归属，本 Skill 不承诺到货时间。

## 目标

把分仓覆盖客户或提货点的最新库存提报与库存状态信号，转化为可追溯的客户侧判断：先说清提报覆盖范围与最新提报时间，再输出信号类型（低库存 / 高库存 / 临期 / 无提报），然后与分仓当前可用库存、订单与缺货、库存差额、调拨中及补货建议做冲突比对，最后给出原因线索、建议方向与数据边界。

客户信号是**辅助输入**，不是全量、实时、准确的客户库存主账；本 Skill 不替代分仓库存与订单口径，也不对未覆盖客户外推。

## 触发场景

- 「哪些客户库存低，要不要补货」「客户库存低是不是必须补货」
- 「哪些客户库存高」「客户库存高的客户有哪些」
- 「客户说库存临期怎么办」「客户提报临期了要不要调拨」
- 「客户库存和分仓库存对不上」「为什么客户库存低但分仓不缺货」
- 「为什么分仓还提示补货，客户那边库存明明很高」
- 「客户库存信号覆盖了哪些客户」「某客户有没有库存提报」
- 日报 / 滞库风险报告中的客户信号佐证段（如「查看覆盖客户库存信号」）

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 客户覆盖关系 | 分仓 / 提货点与客户的归属关系，以及当前有效提报范围（决定本次可判断的客户集合） | 是 |
| 最新提报与提报时间 | 客户或提货点最近一次库存提报的内容与其时间；缺失时不得按 0 或「无库存」处理 | 是 |
| 信号类型 | 低库存 / 高库存 / 临期 / 无提报（阈值由业务维护，未维护时只做方向性提示） | 是 |
| 分析范围 | 分仓、区域、省区、客户、品类、SKU | 是 |
| 分仓库存与订单口径 | 当前可用库存（不含在途）、备单中剩余未占用量、订单扣减后可供库存、缺货量、缺货 SKU 与订单 | 是 |
| 分仓补货口径 | 目标库存量与库存差额、调拨中（已下单未发货 / 已发货未入库分列，不合并）、建议补货量 | 是（缺失时标注影响） |
| 分仓货龄口径 | 客户临期比对时需要的分仓货龄分段：0-30 / 31-60 / 61-90 / 91 及以上（分仓大日期为 91 天及以上） | 临期信号必填 |
| 数据截止时间 | 分仓库存与订单、在途与调拨、库龄、客户提报各自的提交或刷新时间 | 是 |
| 权限范围 | 角色决定动作；DMS 用户与分仓关系决定数据范围 | 是 |

数据刷新参考：分仓库存与订单约 2 小时（至少每日一份快照）；调拨在途约 2 小时；库龄结果以大数据结果为准；**客户提报按客户提报周期更新，通常为日级或周级**。

客户提报缺失不做外推，不把缺失提报当成 0 库存；客户侧的订单与履约口径（当前未发货订单量、满足率）属客户订单类问题，不在本 Skill 展开。

## 执行步骤

### 第 1 步：校验权限与覆盖范围
确认角色与 DMS 用户—分仓关系，把分析范围收敛到授权分仓集合（「全部分仓」= 授权分仓集合，不等于系统全部分仓）。再取分仓 / 提货点与客户的覆盖关系，确定本次可判断的客户集合。未覆盖客户必须单独列出，**不纳入信号判断、不参与排行、不进入名称输出**。

### 第 2 步：确认提报有效性与时效
记录每条提报的时间、来源客户或提货点、覆盖的品类与 SKU；按 `rules.md` 第 5 节判定是否为最新有效提报。提报缺失或过期时标注「提报缺失」或「提报过期，仅作参考」，并保留其时间，不填充数值、不补 0。

### 第 3 步：判定信号类型
按 `rules.md` 第 1 节把提报归入低库存 / 高库存 / 临期 / 无提报，并说明本次信号是「客户或提货点自主提报」，不是客户库存主账。无提报的客户单列一类：只说明未覆盖或未提报，不判定其库存高或低。

### 第 4 步：读取分仓侧对应口径
按 `rules.md` 第 2 节与 **branch-policy 取数契约** 取分仓侧数据：当前可用库存（**不含在途**）、在途（**已下单未发货与已发货未入库分列，禁止合并**）、备单中剩余未占用量、订单扣减后可供库存、缺货量、目标库存量与库存差额、调拨中、建议补货量。
口径固定：缺货量 = max(0, 备单中剩余未占用量 − 当前可用库存量)；库存差额（净额）= 订单扣减后可供库存 − 目标库存量；低于目标量 = max(0, 目标库存量 − 订单扣减后可供库存量)；建议补货量 = max(0, max(缺货量, 低于目标量) − 调拨中)。

### 第 5 步：信号与分仓口径联动比对
按 `rules.md` 第 3 节逐条比对客户信号与分仓侧口径：客户低库存 → 分仓是否有缺货量、订单扣减后可供库存是否低于目标；客户高库存 → 分仓是否仍有缺货、是否仍提示补货、是否属小单高频提货模式；客户临期 → 分仓同类品 60-90 天与 91 天及以上库存情况；无提报 → 只走分仓口径。
判断补货仍以缺货量、库存差额、当前可用库存、调拨中为主。

### 第 6 步：冲突分析
按 `rules.md` 第 4 节输出冲突清单（冲突现象 / 判定 / 处理），必须覆盖四类冲突：客户库存低但分仓不缺货、客户库存高但分仓仍提示补货、客户临期与分仓大日期并存、客户提报时间过期。
每条冲突都要写明分仓侧对应数值与提报时间，并标注证据状态标记（全篇最多 3 处）。**冲突不改变缺货量、库存差额与建议补货量的计算。**

### 第 7 步：生成原因线索
按 `rules.md` 第 6 节触发条件生成，最多 5 条，每条标注【已验证】/【有支撑未验证】/【推测】/【数据缺失】之一，并说明支撑依据。禁止推断客户真实库存总量、客户资金与经营状况，禁止把客户信号缺失写成「客户无库存」。

### 第 8 步：给出建议方向
按 `rules.md` 第 7 节面向分仓计划员 / 分仓运营经理 / 区域计划 / 平台计划员给出方向性建议（只给角色，不写姓名），每条写清动作 + 对象 + 时间窗，统一标注【待人工确认】。不自动创建补货或调拨，不承诺到货时间，不做客户侧自动触达。

### 第 9 步：汇总与排序
按分仓 / 区域 / 省区 / 客户 / 品类 / SKU 汇总信号数与信号类型分布；排序：信号类型（低库存 → 高库存 → 临期）→ 是否有冲突 → 提报时间（新在前）。计数类按去重口径（SKU 个数按 SKU 去重，不各分仓相加）；比率类按汇总分子 ÷ 汇总分母；分母为 0 显示「—」。

### 第 10 步：整理数据边界并形成交付结果
按 **branch-policy 数据边界** 与 **branch-policy 输出规范** 整理数据边界：覆盖客户数与未覆盖客户数、提报时间分布（最新与最旧）、分仓各数据源时间、口径限制、不可判断项；按分析类五段式输出，口径限制段必须写明「客户信号为辅助输入，未覆盖客户不外推」。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 覆盖范围：只统计当前有效提报范围内且属授权范围的客户；未覆盖或未提报客户单列，**不得外推，不得把提报当全量、实时、准确的客户库存主账**
- 客户信号定位为**辅助输入**：判断补货仍以缺货量、库存差额、当前可用库存、调拨中为主，客户信号不改变公式、不产生缺货量
- 分仓口径固定：库存为当前可用库存（**不含在途**）；在途必须分「已下单未发货」与「已发货未入库」两类展示，**禁止合并**
- 分仓大日期阈值为 **91 天及以上**（与基地 61 天及以上口径不得混用）；货龄分段为 0-30 / 31-60 / 61-90 / 91 及以上
- 时效：分仓库存与订单约 2 小时、调拨在途约 2 小时、库龄每日一份；客户提报按客户提报周期（通常日 / 周级）；过期提报只作参考并标注时间
- 冲突方向固定四类：客户低库存与分仓不缺货、客户高库存与分仓仍提示补货、客户临期与分仓大日期并存、客户提报过期；冲突只提示人工核对，不自动处置
- 缺数按 0；分母为 0 或无数显示「—」；证据状态标记全篇最多 3 处；不出现表名、字段名、工具名
- P1 不做待办、事件、定责、升级与责任角色推荐

## 默认交付

1. 核心结论（一句话：本次纳入判断的客户数、信号类型分布、存在冲突的客户数与主要冲突方向）
2. 覆盖范围与时效说明（授权分仓、覆盖客户数、未覆盖 / 未提报客户数、提报时间最新与最旧）
3. 信号明细（分仓 / 区域 / 省区 / 客户 / 品类 / SKU / 信号类型 / 提报时间）
4. 信号与分仓口径对照（当前可用库存、备单中剩余未占用量、订单扣减后可供库存、缺货量、库存差额、调拨中、建议补货量）
5. 冲突清单（冲突现象 / 判定 / 处理方向 / 证据状态）
6. 原因线索（最多 5 条，带证据状态）
7. 建议方向（按角色，全部【待人工确认】）
8. 数据边界与不可判断项（含未覆盖客户、过期提报、缺失口径）

## 边界与禁止动作

- **不对未覆盖客户外推**；不把客户提报当全量、实时、准确的客户库存主账
- **不以客户信号替代分仓库存与订单口径**；客户库存低不等于分仓缺货，也不等于必须补货；客户库存高不等于分仓不需要补货
- 不自动创建补货、调拨或任何正式动作；不预填、不提交 DMS 订单
- **不承诺到货时间**；不把基地未来排产或客户提报说成已承诺供给
- 未授权客户的名称、数值不得出现在结论、排行、明细与引导中
- 不合并「已下单未发货」与「已发货未入库」；不用在途充当当前可用库存
- 不修改公式、目标库存、补货周期、权限规则；不做报废、降价、清仓结论
- P1 不做待办、事件、反馈闭环、定责、升级与责任角色推荐；建议只到方向与建议责任角色
- 缺数按 0；分母为 0 或无数显示「—」；证据状态标记全篇最多 3 处；不出现表名、字段名、工具名

## P2 承接

客户库存主账接入（含客户侧库存与提报质量治理）、客户侧自动触达与提醒、客户信号转待办与事件、冲突升级与审批闭环、客户与分仓责任判定、客户信号命中率与准确率回评。
