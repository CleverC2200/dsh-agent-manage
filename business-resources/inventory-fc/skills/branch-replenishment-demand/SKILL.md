# 分仓补货需求 Skill

## 参考资源（按需加载）
- **先加载 `branch-policy` Skill**（共享规范：指标口径、数据边界、取数契约、证据与行动边界、输出规范；内部包，不单独回答用户）。涉口径、排名、取数、分析、报告之前必读。

- **`rules.md`**：建议补货量与紧急补货公式、构成拆解、特殊情形处理、原因线索与输出字段 → 第 2、3、4、6 步前读取
- **branch-policy 数据边界**：数据边界、补货周期与计划缺失处理 → 第 7 步前读取
- **branch-policy 证据与行动边界**：证据状态与行动边界（建议 ≠ 正式订单） → 第 5、6 步前确认
- **branch-policy 输出规范**：输出规范 → 第 8 步前读取
- **branch-policy 取数契约**：取数与知识查询契约（cube 查询模板、上卷铁律、权限、降级） → 取数前必读
- **branch-policy 指标口径**：补货与计划类指标口径、白名单 → 第 1、2 步前读取

本 Skill 只回答**建议补货量（系统建议值）**；实际补货量的维护与提交在看板完成，其差异解释与状态查询由 `branch-replenishment-confirmation-dms` 承接。

## 目标

把缺货量、库存差额、调拨中、补货周期与计划等输入，转化为可追溯、可复核的建议补货结论：建议补货量、补货 SKU 数、紧急补货、构成拆解、原因线索与数据边界；明确「建议量不是正式订单」。

## 触发场景

- 「建议补多少」「补货 SKU 有哪些」「哪些是紧急补货」
- 「为什么库存高还提示补货」「为什么要补这么多」
- 「补货量和缺货量是什么关系」「调拨中扣了没有」
- 看板补货确认主指标与明细页签的解释类问题

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 分析范围 | 分仓、区域、品类、物料组、SKU | 是 |
| 缺货量 | 按分仓 + SKU 计算的当前缺货量 | 是 |
| 目标库存 | 目标库存量及其补货周期、计划版本 | 是 |
| 订单扣减后可供库存 | 当前可用库存 − 备单中剩余未占用量 | 是 |
| 调拨中 | 已下单未发货量 + 已发货未入库量 | 是（缺失须标注未扣减） |
| 补货周期 | 分仓已生效周期（未配置默认 7 天） | 是 |
| 计划数据 | 本月出货计划、目标月份与版本、来源 | 是 |
| 基地可供 | 基地可用库存、基地在途、未来 7 日排产 | 否 |
| 动销与货龄 | 近 30 日动销、60 天以上与 91 天及以上库存 | 否 |

**不使用金额口径；不重新测算目标库存与安全库存以外的口径；不承诺到货时间。**

## 执行步骤

### 第 1 步：校验输入口径与计划版本
确认缺货量、库存差额、调拨中的取数口径与数据时间；确认补货周期是否已配置（未配置按默认 7 天并标注）；确认计划版本（月初 / 滚动）与来源（人工 / BI）及是否预览。

### 第 2 步：计算库存差额与建议补货量
按 `rules.md`：
`库存差额（净额）= 订单扣减后可供库存 − 目标库存量`（正数高于目标、负数低于目标）
`低于目标量 = max(0, 目标库存量 − 订单扣减后可供库存量)`
`建议补货量 = max(0, max(缺货量, 低于目标量) − 调拨中)`
**订单缺口先独立计算，不在缺货量中扣调拨中；调拨中只在最终建议量统一扣减，结果不小于 0。必须先按 分仓 + SKU 计算再汇总。**

### 第 3 步：识别紧急补货
紧急补货 = 同时满足「存在缺货」且「当前库存低于目标库存」的 SKU 建议补货量之和；同时输出紧急补货 SKU 数。补齐补货 SKU 数（建议补货量 > 0 的 SKU 数）。

### 第 4 步：构成拆解与排序
逐 SKU 输出缺货量、库存差额、调拨中与建议补货量的关系，说明建议量由哪一项驱动。排序：紧急补货 → 建议补货量 → 缺货量。

### 第 5 步：冲突检查
按 `rules.md` 检查冲突：同一 SKU 同时存在 91 天及以上或动销偏慢库存 → 先提示「先去化再补」；高于目标但仍提示补货 → 核查规格、批次、提货点需求；客户库存信号高但分仓仍建议补货 → 标注冲突待确认。

### 第 6 步：关联基地可供与在途（如有数据）
计算基地可供能否承接本次建议量（参考 `branch-upstream-base-availability` 口径），说明调拨中已扣除的部分；**不给到货时间**，只说明是否存在预计到货数据。

### 第 7 步：整理数据边界
按 **branch-policy 数据边界** 整理：数据时间、补货周期来源、计划版本与来源、缺失字段（特别注明调拨中是否已扣除）、不可判断项。

### 第 8 步：形成交付结果
按 **branch-policy 输出规范** 输出；必须写明「建议量不是正式订单，需业务确认」。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 建议补货量 = max(0, max(缺货量, 低于目标量) − 调拨中)
- 订单缺口独立计算；调拨中只在最终建议量统一扣减；结果不小于 0
- 库存差额基准是订单扣减后可供库存，不是现库存
- 调拨中 = 已下单未发货量 + 已发货未入库量；缺失时按 0 处理**必须标注**
- 紧急补货 = 存在缺货且当前库存低于目标库存
- 必须先按分仓 + SKU 算再汇总；不做金额口径
- 建议 ≠ 正式订单；不给到货时间；不自动创建补货单或调拨单

## 默认交付

1. 核心结论（建议补货总量、补货 SKU 数、紧急补货量与 SKU 数）
2. 分析范围、数据时间、补货周期、计划版本与来源
3. 建议量构成（缺货量、库存差额、调拨中三者的汇总关系）
4. 补货 SKU 清单 TOP 10（含建议补货量、驱动项、风险等级）
5. 紧急补货清单
6. 冲突提示（先去化再补、高于目标仍补货、客户信号冲突）
7. 基地可供提示（不给到货时间）
8. 建议动作（标注待人工确认与建议责任角色）
9. 数据边界

## 边界与禁止动作

- 不生成正式补货单、不提交 DMS、不调拨、不承诺到货时间、不定责、不推荐责任人（P1）
- 建议量 ≠ 已确认量 ≠ 正式订单；实际补货量由业务确认
- 不用缺货量替代建议补货量；不用库存差额替代缺货量
- 不重新定义安全库存与目标库存口径；不使用金额口径
- 目标库存或计划缺失时不给精确建议量，只给可判断部分
