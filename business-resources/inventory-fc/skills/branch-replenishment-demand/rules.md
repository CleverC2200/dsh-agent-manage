# 分仓补货需求 — 规则与阈值

## 1. 计算公式

| 指标 | 公式 | 说明 |
|---|---|---|
| 备单中剩余未占用量 | max(备单中订单需求量 − 备单中已占用量, 0) | 已扣减部分不得重复扣减 |
| 订单扣减后可供库存量 | 当前可用库存量 − 备单中剩余未占用量 | 可为负数 |
| 缺货量 | max(0, 备单中剩余未占用量 − 当前可用库存量) | 统一按正数 |
| 安全库存周转天数 | 已生效补货周期 + 3 天备货期 | 周期按分仓配置，未配置默认 7 天 |
| 日均出货计划 | 基准出货计划 ÷ 基准月自然日数；基准按计算日切换：1–20 日用本月出货计划、21 日及以后用次月出货计划；出货计划导入版优先，无导入用系统版 | 计划缺失或为 0 时不给精确目标 |
| 目标库存量 | 安全库存周转天数 × 日均出货计划 | — |
| 库存差额（净额，主口径） | 订单扣减后可供库存 − 目标库存量；正数高于目标、负数低于目标；汇总直接相减、允许正负抵消 |
| 低于目标量（补货用） | max(0, 目标库存量 − 订单扣减后可供库存量) | **基准是订单扣减后可供库存** |
| 调拨中 | 已下单未发货量 + 已发货未入库量 | 只含仍会到达分仓的有效调拨，同一批供给只计一次 |
| **建议补货量** | max(0, max(缺货量, 低于目标量) − 调拨中) | 订单缺口独立计算，调拨中只在最终建议量扣减 |
| 补货 SKU 数 | 建议补货量 > 0 的 SKU 数 | COUNT DISTINCT |
| 紧急补货量 | 同时满足存在缺货且当前库存低于目标库存的 SKU 建议补货量之和 | 与建议补货量区分 |
| 紧急补货 SKU 数 | 同时满足存在缺货且当前库存低于目标库存的 SKU 数 | COUNT DISTINCT |

禁止口径：建议补货量 = 缺货量 + 库存差额 + 调拨中；把调拨中直接加进需求；先汇总总量再算建议量；用现库存替代订单扣减后可供库存。

## 2. 构成拆解规则

输出建议补货量时必须同时给出驱动关系，说明本次建议量由哪一项决定：

| 情形 | 说明口径 |
|---|---|
| 缺货量 ≥ 库存差额 | 建议量主要由当前订单缺货驱动 |
| 库存差额 > 缺货量 | 建议量主要由目标水位缺口驱动 |
| 调拨中 ≥ max(缺货量, 低于目标量) | 建议量为 0，缺口由在途覆盖，标注在途覆盖 |
| 缺货与库存差额同时存在 | 取两者较大值，说明为什么不是两者相加 |

## 3. 特殊情形处理

| 情形 | 处理 |
|---|---|
| 调拨中数据缺失 | 按 0 处理但**必须标注**「未考虑调拨中，实际建议量可能更低」 |
| 目标库存缺失 | 只按缺货量给参考量，标注「目标缺失，建议量仅按缺口测算」 |
| 计划结果缺失或人工计划不完整 | 不给精确目标库存与建议补货量，说明缺失范围 |
| 补货周期未配置 | 按默认 7 天计算并标注 |
| 前端临时修改周期 | 只影响预览，标注为预览，不影响定时预警 |
| 库存差额为 0（当前已高于目标水位） | 建议量只由缺货量驱动；若缺货也为 0，则建议量为 0 |
| 同一 SKU 存在 91 天及以上或动销偏慢库存 | 先提示「先去化再补」的冲突，不直接给建议量 |
| 同一 SKU 高于目标但仍提示补货 | 说明订单扣减后可供库存不足，并建议核查规格、批次与提货点需求 |
| 客户库存信号显示高库存 | 标注客户信号与分仓建议冲突，待业务确认，不用客户信号替代分仓口径 |
| 建议量为 0 但用户认为应补 | 说明缺货量与库存差额均为 0 或被调拨中覆盖，给可核对项 |

## 4. 紧急补货规则

紧急补货 = 同时满足「存在缺货」且「当前库存低于目标库存」的 SKU 建议补货量之和。两个条件缺一不可：

| 情形 | 是否计入紧急补货 |
|---|---|
| 存在缺货，且当前库存低于目标库存 | 计入 |
| 存在缺货，但当前库存不低于目标库存 | 不计入（属结构性或规格错配，需核查） |
| 无缺货，但低于目标库存 | 不计入（属水位补货） |

紧急补货处理时限属业务维护规则包受控参数；未维护时只做方向性提示，不自行编造时限。

## 5. 排序与筛选

排序：紧急补货 → 建议补货量 → 缺货量 → 库存差额。
按品类 / 物料组汇总时先按分仓 + SKU 计算再汇总，分项不抵消。只问一个 SKU 时直接回答。

## 6. 原因线索（最多 5 条，标注证据状态）

| 方向 | 子原因 | 触发条件 | 证据状态 |
|---|---|---|---|
| 需求端 | 订单缺口抬升 | 缺货量在建议量中占主导 | 已验证 |
| 水位端 | 目标水位缺口 | 库存差额高于缺货量 | 已验证 |
| 供给端 | 调拨不足 | 调拨中显著低于需求 | 已验证（有在途数据时） |
| 配置端 | 补货周期变长 | 周期近期由小变大 | 已验证（有变更记录时） |
| 计划端 | 计划量上升 | 日均出货计划明显上升 | 有支撑未验证 |
| 数据端 | 在途或库龄数据缺失 | 调拨中缺失或库龄未接入 | 数据缺失 |

不做目标设置合理性的推断。

## 7. 输出字段清单（补货 SKU 清单）

分仓 / 品类 / 物料组 / SKU / 当前可用库存 / 订单扣减后可供库存 / 缺货量 / 目标库存 / 库存差额 / 调拨中（已下单未发货 + 已发货未入库）/ 建议补货量 / 驱动项 / 紧急标记 / 风险等级 / 建议责任角色 / 状态【待人工确认】。

## 8. 约束

- **不给到货时间**（缺乏可靠测算依据），只说明是否存在预计到货数据
- 不生成正式补货单、不提交 DMS、不指定生产批次、不调整排产
- 建议量与实际补货量必须分开保存；实际量由业务确认，可低于、等于或高于建议量，调整须记录原因
- 与滞库结论不冲突：既缺货又高货龄时先提示冲突再给建议
- 建议总数 ≤5 条，短期优先，只给建议责任角色不写姓名

## 9. 数据完整性校验

必备字段：分仓、SKU、缺货量、当前可用库存、目标库存量或其输入（补货周期与计划量）、数据截止时间。缺字段时按指标分别处理，**不整行作废**：缺货相关字段缺失按 0 参与并标注，目标或计划缺失不给精确建议量，其余指标照常输出。

可选字段缺失时：无调拨中 → 标注未扣减在途；无基地可供 → 不给承接判断；无货龄 → 不给先去化提示。

## 10. P2 承接

待办 / 事件闭环、历史反馈闭环、责任判定与协同角色推荐、升级审批、到货时间承诺、自动创建补货单与调拨单、排产与调拨执行闭环。
