# 分仓库存 Agent 共享规范（branch-policy）

本 Skill 是**内部规范包**：不作为对外能力单独触发，不直接产生面向用户的回答。它只回答一件事——「**不管做什么任务、不管加载了哪个业务 Skill，都必须遵守什么**」。

## 一、职责边界（唯一权威，已冻结）

| 文件 | 唯一负责 | 明确不负责 |
|---|---|---|
| `metric-catalog.md` | 指标定义与公式、统一口径取值规则、上卷与汇总铁律、数据形态与时间能力、支持与不支持问题、口语消歧、关键消歧对照、引导问题白名单、同义词映射、冲突与待确认、指标与数据映射、取数通道可达性与标准降级表述 | 不写输出格式；不写取数调用参数结构；不写证据标记规则；不写业务动作边界 |
| `data-boundary.md` | 必须标注的信息、计划版本与来源取值规则、补货周期与目标库存的数据边界、数据缺失处理原则与标准表述、数据时间不一致处理、数据质量分级、分仓与基地阈值对照 | 不定义指标公式；不写取数调用方式；不写行动边界 |
| `data-access-contract.md` | 工具清单与分工、取数调用顺序、查询契约与模板、上卷落到查询层、权限两层与只读、规则与语义冲突裁决、失败与降级、溯源要求 | 不定义指标口径本身；不写输出格式；不写业务动作边界 |
| `evidence-and-action-boundary.md` | 证据状态四级标准、AI 可做与不可做清单、P1 阶段不做清单（八件事）、只读与写入边界（含看板侧写入动作分工）、P1/P2 边界、必须人工确认事项、建议与执行的措辞区分、业务判断边界 | 不定义指标公式；不写取数参数；不写排版格式 |
| `output-guide.md` | 语言与文风、数字与单位、结构与排版、时间锚定、引用与来源、四档输出结构、行动建议与风险提示写法、风险等级与优先级、数据说明写法、计划与版本表述要求 | 不定义指标口径；不写取数方式；不裁决业务规则冲突 |

**边界冻结**：上表「唯一负责」栏即该文件的内容上限。新增公共规则必须且只能归入这 5 个文件之一；出现在「明确不负责」栏的内容不得写入该文件。

## 二、加载序（按场景决定读哪几个）

| 场景 | 必读 | 按需 |
|---|---|---|
| 单指标 / 单对象问数（「长沙分仓目标库存多少」） | output-guide（6.1.1） | metric-catalog（第十一节引导白名单） |
| 口径解释、「怎么算」、两个数为什么对不上 | metric-catalog（第十、十二、十六、十七节） | output-guide |
| 任何取数动作之前 | data-access-contract | metric-catalog（第十四、十五节） |
| 排名、下钻、排序 | metric-catalog（第十、十一、十二、十七节） | data-access-contract |
| 原因分析、给建议、涉及行动 | evidence-and-action-boundary | output-guide、data-boundary |
| 生成报告 | output-guide（6.4 节） | metric-catalog、data-boundary |
| 涉及四个计划、目标库存、补货周期 | data-boundary（第二、三节） | metric-catalog（第五、十六节） |
| 涉及货龄、大日期、阈值判定 | data-boundary（第七节）+ metric-catalog（第三、十六节） | — |
| 任何面向用户的输出 | output-guide | — |
| 数据缺失、刷新过期、多源时间不一致 | data-boundary（第四、五、六节） | data-access-contract（第七节） |

**前置加载要求**：涉口径、排名、取数、分析、报告之前，先加载本 Skill，再加载对应业务 Skill。业务 Skill 规则与本 branch-policy 冲突时，以本 branch-policy 为准。

## 三、冲突裁决顺序（从高到低）

1. **固化规则包 V1.0**：指标定义、公式、计划版本优先级、权限、人机边界
2. **业务维护规则包 V0.7**：补货周期、阈值、特殊业务标记、处理时限、话术
3. **本 branch-policy**（上述 5 个文件）
4. **业务 Skill 自身的 `SKILL.md` / `rules.md`**
5. **说明书语义**（`mcp__gea-gateway__inspect_cube_model`）与企业知识（`mcp__gea-gateway__weknora_ask`）

裁决结果必须提示冲突来源，不得静默择一。

## 四、与业务 Skill 的分工

| 维度 | 本 branch-policy | 业务 Skill |
|---|---|---|
| 内容性质 | 所有业务 Skill 共用的公共规则 | 本场景独有的执行流程、口径实例、判定分支、输出模板 |
| 指标公式 | 定义**唯一权威**的公式与统一口径取值规则（metric-catalog 第十六节） | 只保留本场景用到的公式实例与带入说明，不重写公式定义 |
| 阈值 | 定义分仓与基地**阈值对照**这一唯一权威表（data-boundary 第七节） | 保留本场景所需的**一行最小锚点**（如「分仓大日期 91 天及以上，见 branch-policy 指标口径」），供 branch-policy 未加载时降级使用；**不得展开成完整对照表** |
| 修改影响 | 一处修改，全部业务 Skill 生效 | 只影响本 Skill |

业务 Skill 引用本 branch-policy 时写**按名字的指针**（如「见 branch-policy 指标口径 第十一节」），不写文件路径、不写目录名。

## 五、禁止事项

- 不把本 branch-policy 内容复制进业务 Skill；同一公共规则出现两份即视为缺陷
- 不使用任何目录路径或上级目录跳转引用（形如「上级目录 + 文件名」）指向本 branch-policy 或其他 Skill
- 不把本 Skill 当作面向用户的回答入口或能力清单

## 六、验收口径

本 branch-policy 生效的判定标准：

1. 全包检索「上级目录跳转引用」与「目录名 + 文件名引用」形态为 **0 命中**（检索方式见《块一现状审计与归位记录》第 6 节）
2. 公共规则（统一口径取值、版本取值、缺失处理、证据标准、输出规范）在全包内只有一份定义
3. 任取一个业务 Skill，仅凭「本 Skill 规则 + 本 branch-policy」即可完成该场景完整输出
4. 本 branch-policy 未加载时，业务 Skill 依靠自身最小锚点仍能给出方向正确、但明确标注降级的回答
