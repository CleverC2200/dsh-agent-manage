# 分仓库存数据与知识访问契约（MCP）

## 当前宿主接线

- 当前业务工具由 GEA Host 提供，使用本轮工具清单中的 `mcp__gea-gateway__inspect_cube_model`、`mcp__gea-gateway__query_business_data`。角色、Skill 和页面可见性不授予权限，不能自行传入身份、凭据或直连地址。
- 当前订单与缺货优先使用 `gea_current_shortage`，保留当前有效未备单完成订单，不加本月或近 60 天创建时间限制。`view=summary` 取完整范围，`view=locations` 取地点排行，`view=detail` 按地点与 SKU 分页；基地用 `base`，分仓用返回的 `location_code` 传 `warehouseCode`，商品用 `sku`。数量按返回单位，当前已确认 1 件等于 1 箱。固定工具不拼 Cube 时间条件，不自行重建其 SQL。
- 其余指标按本文的语义与查询契约读取。表名仅是预期来源，说明书与实际授权均通过后才能查询；字段局部缺数与来源、快照、权限或映射失败分别处理，后者保持未知。
- 企业知识先用 `mcp__gea-gateway__weknora_list_knowledge_bases` 取得当前可用库，再用 `mcp__gea-gateway__weknora_ask` 传 `query` 和已返回的 `knowledgeBaseIds`。不猜知识库 ID，不调用旧的独立知识服务或改写知识。
- 业务行已完整展示时直接使用；只在返回的 `nextRead` 非空时按其参数调用 `gea_evidence_read`。读取完制品不代表源数据全量。授权或来源失败保留原错误，相同条件下不切换身份或通道重试。

所有 Skill 取数与查规则都必须遵守本文件。主提示词只写「用哪个工具、什么时候用、禁止什么」，字段级细节在本文件与 branch-policy 指标口径。

> 契约版本：2026-10-14（对齐 Cube-New 网关 MCP：语义查询与取数拆分为两个工具）。

## 一、工具清单与分工

| 工具 | 用途 | 边界 |
|---|---|---|
| `mcp__gea-gateway__inspect_cube_model` | 查指标语义：枚举已发布 View，读取说明书（度量、维度、单位、粒度、业务时间、`required_scope`、原值范围、`aliasMember` 底层成员映射） | 只读；默认列 View，传 `model` 看完整说明书；**不返回全模型目录**；**说明书可见 ≠ 有权取数**；不得凭猜测编造度量名 |
| `mcp__gea-gateway__query_business_data` | 按底层 model 成员名取数（`action` 只能为 `"query"`、`response_mode` 只能为 `"inline_complete"`） | 只读；不得反写；不得绕过该工具自行推数；不接受 SQL、身份、库地址或凭证 |
| `gea_evidence_read`（按结果的 `nextRead` 回读） | 读取查询返回的 `resource_link` 制品 | 只读；制品与内联结果同等效力，均须落溯源 |
| `mcp__gea-gateway__weknora_ask` | 查企业内部知识与规则：口径解释、业务规则、业务逻辑、SOP、例外场景 | 只读；**禁止反写、修改、删除企业内部知识**；只引用要点，不复述整篇 |

第三方规则边界：指标定义、公式、计划版本优先级、权限与人机边界以**固化规则包 V1.0** 为准；业务维护规则包 V0.7 只提供补货周期、阈值、特殊业务标记、处理时限和话术；branch-policy 指标口径 提供支持与不支持问题、引导白名单。三者冲突时以固化规则包优先，并提示冲突来源。说明书语义或 企业知识 知识与上述规则包冲突时，同样以固化规则包优先。

## 二、取数调用顺序（每次都要走）

1. **定问题与指标**：按主提示词的问题分类确定指标（查 branch-policy 指标口径）。
2. **取语义**：用 `inspect_cube_model` 确认该指标所在 View、度量名、单位、粒度、业务时间（`primary_time`）与 `required_scope`，并取 `aliasMember` 作为**底层 model 成员名**（查询只能用这个名称，不能带 View 名前缀）；必要时用 `weknora_ask` 查对应业务规则。
3. **拼查询**：按第三节契约构造；`action` 与 `response_mode` 为固定值，每条 query 必须带 `name`；度量与维度名必须来自说明书，**不确定就先取语义，不要猜**。
4. **加权限与时间**：分仓权限过滤与业务时间条件（`timeDimensions`，按说明书 `primary_time`）一并写入；时间口径（当前快照 / 本月已发货 / 近 30 日窗口 / 未来 7 或 14 日窗口 / 计划目标月份与版本）随查询声明。
5. **汇总**：按第四节上卷铁律；需要「先算后汇总」的指标必须分组查询后在本地计算。
6. **输出与溯源**：结论 + 数据依据（用了哪个度量、什么时间口径、哪个版本、哪条规则来源）；必须读取返回的 `warnings`、`dataStatus` 与字段单位，来源可达且字段局部缺数时按指标规则参与计算并标注；来源、权限或映射失败不补 0。

## 三、cube 查询契约

```json
{
  "action": "query",
  "response_mode": "inline_complete",
  "queries": [
    {
      "name": "q1",
      "query": {
        "measures": [],
        "dimensions": [],
        "timeDimensions": [],
        "filters": [],
        "limit": 60,
        "total": true
      }
    }
  ]
}
```

| 字段 | 说明 | 使用规则 |
|---|---|---|
| `action` | 固定 `"query"` | **常量**；本工具只接受 `"query"`，语义查询改用 `inspect_cube_model`（传 `"inspect"` 会直接报错） |
| `response_mode` | 固定 `"inline_complete"` | **常量**；结果过大时可能以 `resource_link` 返回，按第一节用资源读取 |
| `queries` | 1–8 条查询 | 每条必须带 `name`（用于结果对位）；一次可同时取「高于目标量」与「低于目标量」，或同时取已下单未发货量与已发货未入库量 |
| `measures` | 指标度量名（**底层 model 成员名**，来自说明书 `aliasMember`） | 最多 32 个；一次可放多个度量；名称必须已定义，禁止臆造；不得使用 View 名前缀 |
| `dimensions` | 分组维度（分仓 / 区域 / 品类 / 物料组 / SKU / 客户 / 订单 / 批次 / 目标月份 / 版本等） | 最多 32 个；排名、下钻、分项汇总必须给维度；只问一个总值时才留空 |
| `timeDimensions` | 业务时间条件（按说明书 `primary_time`） | **必填**；缺业务时间报 `CUBE_BUSINESS_TIME_REQUIRED`；跨月份 / 快照日按 `granularity` 分组，不跨期累加 |
| `filters` | 过滤条件（等值 / 区间 / 集合，或 and/or 组合） | 最多 100 条；**分仓权限过滤必填**；对象范围（分仓、客户、品类、SKU）、时间口径、订单状态、目标月份与版本放这里；不得写 SQL 或函数 |
| `limit` | 返回行数上限 | 工具默认 200、上限 1000；本项目约定默认 60、明细下钻最多 200；超过时应改用分组聚合或补过滤条件 |
| `total` | 是否返回总计 | 本工具固定为 `true`；**只用于取总值**；禁止用 total 替代分项结果（见第四节） |

补充约束（实测）：

- 查询只用底层 model 成员名；View 名不能直接用于取数。
- 值 / 原值类度量必须与说明书 `required_scope` 声明的粒度维度同时查询，否则报 `CUBE_VALUE_GRAIN_REQUIRED`。
- 不接受 `ungrouped`、`joinHints` 等旧参数（schema 严格校验，未知字段直接报错）。
- 时区按模型声明的源时间规则；源时区未确认的模型仅使用 UTC 以保留源日历值。

## 四、上卷与聚合铁律（落到查询层）

| 场景 | 查询方式 | 禁止 |
|---|---|---|
| 可加和量（库存、订单量、计划量、出库量） | 按维度分组后 SUM | — |
| 比率 / 天数类（周转天数、满足率、健康库存占比、增长率） | 分别取分子与分母，再计算 | 对下级比率或天数取平均 |
| 缺货量 / 建议补货量 | 先按 分仓 + SKU（+ 订单交付范围）分组，本地 max(…, 0) 后汇总 | 先汇总总量再算 |
| 库存差额（净额） | 汇总 Σ可供库存 − Σ目标库存，直接相减（允许正负抵消）；缺失按 0 参与 | 把分项数字当净差额用；对明细差额取平均 |
| SKU 个数 / 缺货 SKU 数 / 大日期 SKU 数 | COUNT DISTINCT；区域/全国按 SKU 去重 | 各分仓相加 |
| 平均货龄 | Σ(数量 × 货龄) ÷ Σ数量 | 简单平均 |
| 风险库存量 | 大日期与滞库风险同一批次重叠只计一次 | 两段直接相加造成重复计数 |
| 在途 | 已下单未发货量与已发货未入库量分别取数、分别展示 | 合并为一个在途量 |
| 计划版本与来源 | 先按 分仓 + 目标月份 整体选定版本（月初优先滚动）与来源（人工优先 BI），再按 SKU 取数 | 按 SKU 混用版本或来源 |
| 满足率 | 分别取本月已发货订单量与本月有效订单总量 | 用当前未发货订单推算 |
| 值 / 原值类度量（比率、天数、单值） | 与说明书 `required_scope` 的粒度维度一起查询 | 只取总值（缺粒度）→ `CUBE_VALUE_GRAIN_REQUIRED` |
| 快照类数量（库存类） | 单日取值或按月分组 | 跨快照日直接累加 |

total 只能用于「确实只要一个总数」的场景（如某分仓当前可用库存）；上面这些「先算后汇总」的指标必须给 dimensions 分组查询。

## 四·五、表选择铁律（防同一指标查不同表）

| # | 铁律 |
|---|---|
| 1 | **一指标一主表**：现库存 / 当前可用库存 / 占用量 / 货龄 / 批次默认取 `agents_scm_inventory_sku_data_d`（映射见 metric-catalog 14.0） |
| 2 | **不得按表名或字段名相似度自选表**；说明书出现多张候选表时按主表取 |
| 3 | **禁止表**：当前库存不得取产销存协同宽表（只含非出口）或目标库存表（仅有目标 SKU） |
| 4 | **降级必须声明**：主表不可达改用备用表时写明「主表不可达，本次改用 X，口径差异为 Y」，不得静默换表 |
| 5 | **不跨表混算**：同一回答内同一指标只能来自一张表；两表数值不一致时先说明差异原因，无法解释标「数据待复核」 |
| 6 | **快照不累加**：批次库存为单快照日取值，跨日相加会重复计算 |

## 五、权限与只读

- 权限是两层：**角色**决定能执行什么动作；**DMS 用户与分仓关系**决定能访问哪些数据。两者不能相互替代；前端传入的分仓参数不作为唯一权限依据。
- 每次查询前先按分仓权限过滤。「全部分仓」= 用户授权分仓集合，不等于系统全部分仓。
- 无权限的分仓、基地、客户、品类和 SKU 不得出现在名称、数值、排名、明细和引导中；结果可能通过汇总值反推出无权限对象时，降低粒度或拒绝回答。
- 排行只在权限范围内排序，不能用全量结果再过滤名称。
- 导出、明细展开与右侧问答使用同一权限范围，不能出现看板可见而问答不可见或反向绕过。
- **说明书可见 ≠ 有权取数**：`inspect_cube_model` 不按数据权限裁剪，权限在取数时校验；被拒绝时按第七节处理，不自行补权限、不改字段映射、不绕路直连。
- 所有工具只读：不写库、不改配置、不删知识、不建事件与任务。
- **本 Agent 的右侧问答没有任何写入例外**：不保存实际补货量、不保存草稿、不形成提交备份、不生成 DMS 预填上下文、不打开 DMS。补货确认的写入动作全部在看板通过接口完成（看板侧负责留痕：操作人、时间、原值、新值、原因）；正式订单创建、校验与提交仍由 DMS 完成。

## 六、规则与语义冲突

| 情况 | 处理 |
|---|---|
| 说明书语义与固化规则包不一致 | 以固化规则包优先，回答中提示冲突来源，建议人工确认 |
| 企业知识 知识与固化规则包不一致 | 同上；不要用模型记忆替代任一方 |
| 数据说明 V0.4 与固化规则包不一致（满足率口径、补货量是否扣调拨中） | 以固化规则包为准，并在回答中标注口径差异 |
| 同一指标存在多个候选度量 | 先取语义比对口径，选与 branch-policy 指标口径 一致的那个；仍不确定则说明并给两种口径的差异 |
| 度量或维度不存在 | 说明该指标当前不可取数，给可替代指标（不要用相近指标冒充） |

## 七、失败与降级

| 情况 | 处理 |
|---|---|
| 工具不可用 / 超时 | 说明本次未能取到数据，不输出估算值；可给已缓存或用户提供的数据，并标注来源 |
| 权限不足 | 说明只能回答权限范围内数据，不暗示无权限对象存在 |
| 必填字段缺失 | 输出可判断部分 + 说明缺失字段及影响（缺数按 0，不臆造） |
| 数据刷新失败或结果过期 | 说明当前结果不是最新，展示最近有效快照与数据时间，提示刷新后重试 |
| 返回行数达到 limit | 说明结果被截断，改为分组聚合或增加过滤后重查 |
| 时间口径不匹配 | 明确说明用的是快照 / 本月已发货 / 近 30 日窗口 / 未来窗口 / 计划版本，不给跨口径结论 |
| 没有该分仓的客户覆盖 | 说明客户库存信号未覆盖，只给已覆盖客户信号与分仓口径数据 |
| 同一指标两次取数不一致 | 先比对口径、快照时间与过滤条件并说明差异原因；无法解释时标注「数据待复核」，**该数字不得用于排名、建议或对外结论** |
| 缺业务时间被拒（`CUBE_BUSINESS_TIME_REQUIRED`） | 按说明书 `primary_time` 补业务时间条件后重查；属用法问题，不上报为系统故障 |
| 缺粒度维度被拒（`CUBE_VALUE_GRAIN_REQUIRED`） | 按说明书 `required_scope` 补粒度维度后重查；仍失败则说明该指标当前不可取数 |
| 参数不符合契约（`AI_SCHEMA_INVALID`） | 按第三节重构后重查；连续 2 次仍失败即停止，交开发排查，不换写法凑结果 |
| 字段未映射 / 成员未发布（`AI_GATEWAY_DATA_PERMISSION_DENIED`、`DATA_QUERY_MEMBER_NOT_PUBLISHED`） | 属平台侧发布与字段映射配置：说明该指标当前不可取数并给替代指标，转数据资源管理员；**换凭证无效**，不自行补权限 |
| 取数会话失效（`AI_GATEWAY_SESSION_INVALID`、`AI_GATEWAY_SESSION_MAX_LIFETIME_EXCEEDED`、`AI_GATEWAY_POLICY_CHANGED`，约 3~4 天或平台改策略后需刷新） | 说明本次未取到数据，不输出估算值；通知运维刷新取数会话（refresh），不改任何配置、不改提示词 |

## 八、溯源要求

每次回答的数据依据至少包含：数据来源工具（cube 语义 + 取数）、所用度量与维度、数据时间（快照时间 / 本月已发货 / 窗口 / 目标月份）、计划版本与来源（月初或滚动、人工或 BI，如涉及计划）、规则来源（固化规则包章节或 metric-catalog 条目）。

建议一并记录（便于复核）：返回的 `dataStatus` 与 `warnings`、`modelContext` 中的口径说明、字段单位（`unit` / `display_unit`）、`lastRefreshTime`。
