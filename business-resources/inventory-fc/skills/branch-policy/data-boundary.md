# 分仓库存数据边界规范

所有分仓库存分析必须遵守的数据边界和数据质量要求。

## 一、必须标注的信息

| 信息项 | 说明 | 示例 |
|---|---|---|
| 分析范围 | 分仓、区域、品类、物料组、SKU | 河南分仓 / 冷冻面点 / 全 SKU |
| 数据截止时间 | 库存、订单、在途、货龄、动销、计划各自的时间点 | 库存与订单 2026-10-10 08:00；动销截至 2026-10-09 |
| 计划版本与来源 | 目标月份 + 版本（月初 / 滚动）+ 来源（人工 / BI）+ 是否预览 | 2026 年 10 月月初版本（人工提报完整） |
| 目标库存输入 | 补货周期、3 天备货期、基准出货计划（本月/次月）、日均出货计划 | 补货周期 7 天（分仓配置） |
| 数据完整性 | 是否有缺失，缺失在哪 | 基本完整 / 17 个 SKU 无补货周期配置 |
| 不可判断项 | 哪些结论因数据不足无法下 | 某 SKU 周转天数不可计算（近 30 日无出库） |

## 二、计划版本与来源取值规则（按「分仓 + 目标月份」整体确定）

```text
目标月份存在月初版本 → 使用月初版本
目标月份不存在月初版本 → 使用滚动版本
选定版本存在完整有效人工计划 → 使用人工提报
选定版本不存在完整有效人工计划 → 使用 BI 计划
```

- 9 月的次月计划保存为 10 月滚动计划；10 月的本月计划保存为 10 月月初计划。
- **不能按 SKU 混用人工计划与 BI 计划**；人工计划缺 SKU 时标记「人工计划不完整」，不自动按 SKU 回退 BI。
- 计划量整行为空或 0 时不形成有效提报；业务明确填写 0 时按有效 0 处理。
- 页面临时修改只影响预览；保存或导入后才形成人工计划结果。
- Agent 不判断「是否最新版本」，只按上述优先级取值并展示所选版本与来源。
- **各基地版本不同步的处理（业务待确认，暂按以下保守方式执行）**：同一目标月份下，分仓侧所选版本与基地侧供给计划（基地可用库存、在途、未来 7 日排产）的版本或数据时点不一致时，本 Agent **不自行推断同步关系、不自行补配**，一律按三条处理：① 分仓侧与基地侧分别标注各自的版本与数据时间；② 数据说明中明确写出「分仓与基地版本不同步」；③ 涉及基地承接能力的结论一律标注【待人工确认】并提示业务复核。**同步口径本身属新增业务规则，需业务确认后另行补入本节，不得由模型拟定。**

## 三、补货周期与目标库存的数据边界

| 情况 | 处理 |
|---|---|
| 分仓已维护并生效补货周期 | 按该周期计算安全库存周转天数（周期 + 3 天备货期） |
| 未维护或已失效 | 使用系统默认 7 天，并在数据说明中标注「按默认 7 天」 |
| 前端临时修改周期 | 只影响当前预览，不影响定时预警，必须标注为预览 |
| 缺少生效计划或计划日均量为 0 | **不给精确目标库存与建议补货量**，说明缺少生效计划，只给缺货量与可判断部分 |
| 目标库存缺失 | 只按缺货量给参考量，并标注「目标缺失，补货量仅按缺口测算」 |

补货周期变化不修改历史计划和历史补货结果。

## 四、数据缺失处理原则

### 4.1 缺数按 0，分母不强算

- **通用口径**：明细缺数按 0 显示、不留空白；汇总按列求和（有值加、0 或无数不加）；比率 / 天数先汇总分子分母再计算，分母为 0 或无数显示「—」；**不因个别行缺数把整行或整个品类置空**
- **两个输入都缺不参与**：库存与目标、或订单需求与占用量两个输入都缺失时，该行不参与对应指标计算并单列，不按 0 硬算
- **全量缺失 = 数据异常**：整个分仓全部 SKU 的库存或目标都缺失时判数据异常，不出该分仓结论，标「数据异常，待核查」，其余分仓照常
- **计划结果缺失**：不计算目标库存、调拨计划与建议补货量；说明缺失范围
- **补货周期缺失**：按默认 7 天计算并标注，不声称是业务配置结果
- **订单或占用量缺失**：缺的那个按 0 参与缺货计算（缺口即剩余需求），并标注缺失字段
- **可用库存缺失**：按 0 参与缺货计算并标注「可用库存缺失，缺口按需求量计」；若整批库存数据不可达，按第十五节可达性阻断处理，不出缺货结论
- **在途数据缺失**：补货建议量中调拨中按 0 处理，但**必须标注**「未考虑调拨中，实际建议量可能更低」
- **动销或出库缺失**：不给回顾周转天数（分母无数显示「—」），只输出库存与货龄事实
- **货龄 / 批次缺失**：该部分不计入平均货龄与货龄结构，**必须标识未覆盖数量**（参与计算库存 < 当前可用库存），不给完整结构结论
- **客户提报缺失**：不纳入客户信号判断，不对未覆盖客户外推
- **库龄结果缺失**：不自行设置风险阈值，标记库存结构无法完整判断

### 4.2 标准表述

- 「XX SKU 因缺少生效计划，不参与目标库存与建议补货量计算」
- 「因近 30 日无出库记录，该 SKU 回顾周转天数不可计算」
- 「调拨中数据缺失，本次建议补货量未扣除在途，实际需求可能更低」
- 「客户库存信号未覆盖该客户，本次不纳入客户侧判断」
- 「数据刷新未完成，当前展示为最近有效快照，时间见数据说明」

## 五、数据时间不一致处理

1. 分别标注各数据源时间（库存、订单、在途、库龄、动销、计划各不相同）；
2. 说明时间差异可能带来的影响；
3. 以最接近分析时点的数据为主；
4. 建议用户在数据时间一致时再次确认。

刷新频率参考：分仓库存与订单约 2 小时且至少每日一份快照；调拨在途约 2 小时；基地资源（库存、在途、未来 7 日排产）约 6 小时；库龄结果以大数据结果为准；计划结果 BI 按日、人工保存后即时生效；运营数据约 12 小时或每日。

## 六、数据质量分级

| 等级 | 含义 | 输出要求 |
|---|---|---|
| 完整 | 数据齐全，时效正常 | 可正常输出全部结论 |
| 基本完整 | 局部缺失，不影响整体判断 | 输出结论 + 标注缺失项与影响范围 |
| 不足 | 缺失较多，影响核心判断 | 只输出可判断部分并说明限制 |
| 不可用 | 关键数据完全缺失 | 说明不可用，无法分析 |

## 七、口径阈值必须区分（分仓 vs 基地）

| 项目 | 分仓口径 | 基地口径（不得混用） |
|---|---|---|
| 大日期 / 超龄 | 货龄 **≥91 天（超过 90 天）** | 货龄 ≥61 天（超过 60 天） |
| 货龄分段 | 0-30 / 31-60 / 61-90 / 91 及以上 | 0-30 / 31-40 / 41-60 / 61 及以上（超过 60 天） |
| 平均货龄阈值 | 健康 < 20 天；预警 61-90 天；严重 ≥91 天 | 只输出数值，不设阈值（业务暂无基地平均货龄阈值规则） |
| 目标库存 | （补货周期 + 3 天）× 日均出货计划；日均出货计划 = 基准出货计划 ÷ 基准月自然日数（1–20 日用本月出货计划、21 日及以后用次月出货计划；导入版优先），按分仓生效周期实时测算 | 大数据落表最终目标库存 |
| 建议补货量 | max(0, max(缺货量, 低于目标量) − 调拨中) | max(0, max(当前订单缺口, 库存差额) − 在途量) |

回答涉及大日期、货龄或目标库存时，必须标明本次使用的是分仓口径。

## 八、标准数据边界模板

```text
数据边界：
- 分析范围：XX 分仓 / XX 品类 / 共 XX 个 SKU
- 库存与订单：2026-10-10 08:00（最新快照）
- 在途与调拨：2026-10-10 08:00（已下单未发货 / 已发货未入库）
- 库龄：2026-10-10 每日快照
- 动销：截至 2026-10-09，近 30 日窗口
- 计划版本与来源：2026 年 10 月月初版本（人工提报完整）
- 目标库存输入：补货周期 7 天（分仓配置）+ 3 天备货期；基准出货计划：本月出货计划（计算日 1–20 日口径）
- 数据完整性：基本完整（17 个 SKU 无补货周期配置，按默认 7 天）
- 不可判断项：XX SKU 回顾周转天数（近 30 日无出库）；客户库存信号未覆盖 XX 客户
```
