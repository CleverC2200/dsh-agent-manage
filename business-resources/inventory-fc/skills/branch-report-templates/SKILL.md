# 固定报告模板 Skill

分仓库存运营监控 Agent 的固定报告能力。命中报告需求即调用本模板；模板段落、顺序与段落内要素不得自行增删改；缺必需数据时在对应段落写「数据不足，需人工确认」，不生成伪完整报告。

## 触发场景

- 「生成今日分仓库存日报」「出今天的日报」「出一份分仓库存报告」
- 「出大日期报告」「大日期专项报告」「91 天及以上库存报告」
- 「出补货确认清单」「生成补货确认表」「整理建议补货量」
- 看板「今日优先处理」区域或消息中的报告入口跳转

命中即调模板；模板段落不得删改；缺必需数据时提示缺失，不生成伪完整报告。不用相近指标顶替缺失指标，不把缺失数据显示为 0，不编造趋势。四档输出中的固定报告结构见 **branch-policy 输出规范** 第六节 6.4。

## 模板一：分仓库存运营日报（每日）

```text
# {分仓范围}分仓库存运营日报（{报告日期}）

## 一、今日结论
    2-3 句：当日最需处理的结论 + 关键数字 + 风险等级；不写套话，不写「存在风险，请关注」

## 二、五个主指标
    库存水位：当前可用库存量（件）+ 已下单未发货量 / 已发货未入库量（两类在途分开列，不合并为一个数）+ 回顾周转天数 / 展望周转天数
      （回顾周转天数 = 当前可用库存量 ÷ 近 30 日日均出库量；展望周转天数按含在途口径，必须标明「含在途」；分母为 0 显示「—」）
    库存结构：健康库存占比 + 大日期库存量 / 大日期 SKU 数 + 滞库风险库存量 / 滞库风险 SKU 数
      （健康库存量 = max(当前可用库存量 − 风险库存量, 0)；风险库存量 = 大日期库存量 + 滞库风险库存量，同一批次重叠只计一次；
        当前可用库存量为 0 时占比显示「无库存」或「—」；大日期按分仓货龄 91 天及以上口径）
    订单满足率：本月已发货订单满足率（= 本月已发货订单量 ÷ 本月有效订单总量，订单张数口径，主 KPI）+ 本月已发货订单量 + 本月已发货量（件）
      （数量满足率作辅助，须另行标注口径，不得替换主 KPI；当前备单满足率口径不同，须分别标注）
    补货确认：建议补货量（件）+ 补货 SKU 数（建议补货量大于 0 的 SKU 数）+ 紧急补货量 / 紧急补货 SKU 数
      （建议补货量 = max(0, max(缺货量, 低于目标量) − 调拨中)；紧急补货 = 同时满足「存在缺货」且「当前库存低于目标库存」）
    客户订单：当前未发货订单量（件）+ 缺货量 / 缺货 SKU 数 + 缺货订单数 / 总订单张数
      （缺货量 = max(0, 备单中剩余未占用量 − 当前可用库存量)，统一按正数表示；不得用「订单总量 − 当前库存」近似）
    每个主指标标注风险等级：高风险（红）/ 关注（橙）/ 正常（绿）

## 三、货龄结构
    0-30 天正常 / 31-60 天关注 / 61-90 天重点消化 / 91 天及以上大日期重点：各段数量（件）与占比，边界日不重复计入两个区间
    平均货龄（加权：Σ(批次数量 × 批次货龄) ÷ Σ批次数量，禁止简单平均）与健康阈值对照：健康 < 20 天 / 预警 60-90 天 / 严重 > 90 天
    未来 7 日 / 14 日预计超龄：单独列出，标明窗口、是否扣减预计消耗、是否排除当前已超龄；不与当前 91 天及以上相加

## 四、重点风险
    缺货对象、紧急补货对象、91 天及以上库存对象、滞库风险对象、满足率偏低对象；
    每类给对象与关键数值，按风险等级 → 货龄 → 库存量排序

## 五、原因线索（标注证据状态）
    业务层线索与数据层线索分开写；关键结论后标【已验证】/【有支撑未验证】/【推测】/【数据缺失】，全篇最多 3 处

## 六、建议动作（标注待人工确认与建议责任角色）
    不超过 5 条、短期优先；每条写清动作 + 对象 + 时间窗，统一标注【待人工确认】，并标注建议责任角色（只写角色，不写人名与升级路径）

## 七、今日优先处理
    80-180 字：昨日处理情况 + 今日需处理方向；须包含 1-3 个支撑判断的关键数值、涉及的分仓/SKU/订单/库存结构/基地资源、下一步动作与责任方向、数据不完整时的影响说明
    默认分析顺序：补货确认 → 客户订单缺口 → 库存结构/货龄 → 基地资源协同

## 八、需重点跟进清单
    对象（分仓 / 品类 / SKU / 批次）+ 风险等级 + 关键数值 + 建议动作 + 建议责任角色

## 九、数据说明
    数据时间（库存与订单快照时间、在途同期、库龄结果日期）、计划版本与来源（目标月份 + 月初/滚动 + 人工/BI，是否为预览值）、
    缺失字段与影响范围、不可判断项；不超过 4 行
```

## 模板二：大日期报告

```text
# {分仓范围}大日期报告（{报告日期}）

## 一、专项结论
    2-3 句：大日期规模、最需处理对象、60-90 天重点消化区间的压力、未来 7 日 / 14 日新增超龄方向判断

## 二、范围与判定口径
    分仓大日期阈值：货龄 91 天及以上，按批次判定（统计日 − 批次生产日期或统一约定的库存起始日期）；
    基地口径为 60 天以上，引用基地或其他平台数据时必须标明平台口径，两个口径不得混用
    61-90 天作为重点消化区间单列，不计入大日期；60 天以上不等于全部滞库
    未来 7 日 / 14 日预计超龄单独列出，标明窗口、是否扣减预计消耗、是否排除当前已超龄，不与本表相加
    大日期与滞库风险以大数据标准库龄结果为准，Agent 不自行制定或重算风险阈值

## 三、大日期批次明细
    分仓 / 仓库 / SKU / 批次 / 数量（件）/ 货龄（天）；超过 7 列时拆表或改列表

## 四、重点对象排序
    排序规则：风险等级 → 货龄 → 库存量；给出前 N 个对象及其关键数值（批次数、SKU 数、数量、平均货龄）

## 五、原因线索（标注证据状态）
    业务层线索（活动备货、节令切换、新品铺货、大单等需业务确认，不得直接判为异常）与数据层线索分开写；
    关键结论后标【已验证】/【有支撑未验证】/【推测】/【数据缺失】，全篇最多 3 处

## 六、消化方向建议（待业务确认）
    不超过 5 条：动作 + 对象 + 时间窗，统一标注【待人工确认】与建议责任角色（只写角色，不写人名与升级路径）；
    临期与大日期的效期、可售性由品控确认，Agent 不自行判定可售，不自动报废、不自动创建专项或处置任务

## 七、数据说明
    数据时间、库龄结果状态（有无结果、是否为最近快照、是否过期）、计划版本与来源、缺失字段与影响范围、不可判断项；不超过 4 行
```

## 模板三：补货确认清单

```text
# {分仓范围}补货确认清单（{报告日期}）

## 一、本次确认范围
    分仓、目标月份、数据时间、补货周期（已生效补货周期；未配置时按默认 7 天计算并标注）、
    安全库存周转天数（= 已生效补货周期 + 3 天备货期）、基准出货计划（计算日 1–20 日用本月出货计划、21 日及以后用次月出货计划；导入版优先）、计划版本与来源（月初/滚动 + 人工/BI，是否为预览值）、紧急筛选条件

## 二、建议补货汇总
    建议补货量（件）、补货 SKU 数、紧急补货量与紧急补货 SKU 数；
    与上期或上一版本的差异说明（无历史快照时不给趋势结论）；建议量为系统建议值，不得表述为已确认量或正式单据

## 三、明细
    分仓 / 品类 / SKU / 当前可用库存 / 目标库存 / 订单扣减后可供库存 / 缺货量 / 库存差额 / 调拨中 / 建议补货量 / 实际补货量 / 调整原因 / 风险等级
    口径：缺货量 = max(0, 备单中剩余未占用量 − 当前可用库存量)；订单扣减后可供库存 = 当前可用库存 − 备单中剩余未占用量（可为负，用于解释缺货）；
    库存差额（净额）= 订单扣减后可供库存 − 目标库存量；低于目标量 = max(0, 目标库存量 − 订单扣减后可供库存量)（基准是订单扣减后可供库存，不是物理现库存）；
    建议补货量 = max(0, max(缺货量, 低于目标量) − 调拨中)；先按 分仓 + SKU 算 max(…, 0) 再汇总，禁止先汇总总量再算；
    实际补货量为业务确认值，可低于、等于或高于建议量，不覆盖系统建议量；超过 7 列时拆表或改列表

## 四、建议量与实际量差异说明
    逐条说明差异对象、差异量、调整原因；实际补货量低于建议量时必须有原因，不得绕过业务确认

## 五、基地可供提示
    基地当前可用库存、基地调拨在途、未来 7 日排产结果；
    未来排产是计划供给，不是已承诺库存，也不是本分仓已锁定的可得库存；存在分仓需求与基地供给冲突时说明冲突对象，不承诺到货时间

## 六、待确认项
    逐项列出：人工计划不完整、补货周期未配置、库龄结果缺失、BI 目标缺失、数据过期或刷新失败等；
    每项写明影响范围与需要确认的角色；不省略该项，不自行编造阈值或时限

## 七、数据说明
    数据时间（库存、订单、在途、库龄各类结果的时间必须能区分「没有结果」「结果为 0」「结果过期」）、
    计划版本与来源、缺失字段与影响范围、不可判断项；不超过 4 行
```

## 输出约束

- 必须带：分析范围（用户权限范围内的分仓）、数据时间、计划版本与来源、缺失说明
- 每段只写结论与关键数字，明细放表格；对比表格最多 7 列，超过拆表或改列表
- 风险等级统一：高风险（红）/ 关注（橙）/ 正常（绿），不新创等级
- 取数与知识查询遵守 **branch-policy 取数契约**（只读、权限过滤、上卷铁律）
- 「全部分仓」指用户权限范围内的全部分仓，不等于系统全部分仓
- 库存口径为当前可用库存，不含在途；在途分「已下单未发货」与「已发货未入库」两类展示，禁止合并为一个数
- 周转天数区分回顾与展望；展望周转天数含在途，必须标明含在途；天数与比率汇总一律「汇总分子 ÷ 汇总分母」，禁止对下级天数或比率取平均
- 缺货量 = max(0, 备单中剩余未占用量 − 当前可用库存量)，统一按正数；库存差额（净额）= 订单扣减后可供库存 − 目标库存量；低于目标量 = max(0, 目标库存量 − 订单扣减后可供库存量)；建议补货量 = max(0, max(缺货量, 低于目标量) − 调拨中)
- 满足率主 KPI 为「本月已发货订单量 ÷ 本月有效订单总量」（订单张数口径），数量满足率仅作辅助，不得替换主 KPI
- 分仓大日期阈值为货龄 91 天及以上（基地为 60 天以上），回答与报告须标明平台口径；货龄分段 0-30 / 31-60 / 61-90 / 91 及以上，边界日不重复计入两个区间；平均货龄加权计算，阈值 健康 < 20 天、预警 60-90 天、严重 > 90 天
- 推演类数字必须标注窗口与扣减口径（未扣减预计消耗时标注保守口径），未来 7 日 / 14 日预计超龄不与当前 91 天及以上相加；30 日窗口属 P2，不输出
- 计划版本与来源：月初优先滚动、人工优先 BI，按 分仓 + 目标月份 整体选定，不按 SKU 混用；人工计划不完整时标记「人工计划不完整，不作为有效人工版本」，不按 SKU 回退；页面临时修改只形成预览，须标注
- 补货类内容只给 SKU 与建议补货量，不给到货时间，不生成正式单据，不写成已提交或已执行
- 建议统一标注【待人工确认】，并标注建议责任角色（只写角色，不写人名）；P1 不写责任人与升级路径
- 缺必需数据时在对应段落写「数据不足，需人工确认」，不省略该段；不把缺失显示为 0，不给趋势结论，不把估算写成确定值
- 不出现表名、字段名、工具名、模型名、SQL；不使用动销率，用近 30 日动销量、日均动销等数量口径；不使用金额口径（金额只出现在分仓整体增长率解释中，且不做金额到件数换算）

## 参考
- **先加载 `branch-policy` Skill**（共享规范：指标口径、数据边界、取数契约、证据与行动边界、输出规范；内部包，不单独回答用户）。涉口径、排名、取数、分析、报告之前必读。

- **branch-policy 指标口径**：指标口径、上卷铁律、计划版本优先级、引导白名单
- **branch-policy 输出规范**：四档输出结构、风险等级、数据说明写法、计划与版本表述要求
- **branch-policy 取数契约**：取数与知识查询契约
- 固化规则包 V1.0（五个主指标、整体分析、明细页签、数据异常与解释规则）与业务维护规则包
