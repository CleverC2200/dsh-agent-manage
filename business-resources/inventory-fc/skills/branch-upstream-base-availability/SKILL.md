# 分仓上游基地可供信号 Skill

## 参考资源（按需加载）

  → 第 2、3、4、5、6、7 步前读取
- **branch-policy 数据边界**：数据边界、缺失处理、刷新频率与分仓/基地口径区分 → 第 8 步前读取
- **branch-policy 证据与行动边界**：证据状态与行动边界 → 第 7、8 步前确认
- **branch-policy 输出规范**：输出规范 → 第 8 步前读取
- **branch-policy 取数契约**：MCP 取数与知识查询契约（cube 查询模板、上卷铁律、权限、降级）
  → 取数前必读
- 与 `branch-replenishment-demand` 配合：先由补货需求得出建议补货量，再判断基地侧能否承接
- 与 `branch-shortage-monitoring` 配合：缺货量来自缺货口径，本 Skill 不重新定义缺货，只承接其结论并补基地侧视角

## 目标

把基地当前可用库存、基地调拨在途（基地在途未入库）与未来 7 日排产，和权限范围内各分仓的缺货量或建议补货量做比对，判断基地资源能否承接分仓需求，识别分仓需求与基地供给的不足或竞争冲突，输出带证据状态的原因线索与协同建议，全程不承诺到货时间。

## 触发场景

- 「基地能不能供上」「这批补货基地能不能接」
- 「基地缺货时分仓要不要提前补」「基地缺货时哪些分仓需要提前补」
- 「基地库存够，为什么分仓还缺货」
- 「好几个分仓缺口都压在一个基地上，先保谁」
- 「基地未来 7 日有排产，分仓能按时到货吗」
- 日报 / 今日优先处理中的基地资源协同段

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 基地可用库存 | 基地当前可用于对外供给的库存 | 是 |
| 基地在途未入库 | 基地调拨在途（在途未入库） | 是 |
| 未来 7 日排产 | 基地未来 7 日排产 SKU 与数量 | 是 |
| 分仓缺货量 / 建议补货量 | 两者至少一项；无则先取缺货口径，仍无则标记数据缺失 | 是 |
| 调拨中 | 已下单未发货量与已发货未入库量，分开取数 | 否（缺失时标注未扣除） |
| 分析范围 | 基地、提货点、品类、物料组、SKU、分仓 | 是 |
| 数据截止时间 | 基地资源、分仓库存与订单各自时间 | 是 |

**可选数据处理**：调拨中缺失时按未扣除处理并显式标注「本次未扣除调拨中，实际缺口可能更低」；提货点缺失时按分仓整体判断，不给提货点级结论；**字段级缺失按 0 参与并标注；整批数据不可达时说明缺少的数据源**。

## 执行步骤

### 第 1 步：校验输入与权限
确认基地、提货点、品类、SKU、分仓需求量与数据截止时间齐备；按角色与 DMS 用户-分仓关系过滤数据范围，「全部分仓」只代表授权分仓集合。缺字段时按指标分别处理，**不整行作废**：该指标缺数按 0 参与并标注，两个输入都缺的行单列；其余指标照常输出。

### 第 2 步：取三类供给口径
分别取基地当前可用库存、基地调拨在途（在途未入库）、未来 7 日排产，三类分开列出不合并。明确写出：未来排产是计划供给，不是已承诺库存，也不是某分仓已锁定可得库存。

### 第 3 步：计算分仓需求侧
按 分仓 + SKU 先算缺货量与建议补货量，再汇总到需求合计；建议补货量 = max(0, max(缺货量, 低于目标量) − 调拨中)。公式详见 `rules.md` 第 2 节。

### 第 4 步：承接判断（可供 vs 需求）
按 基地 + SKU 比对基地可供与权限范围内分仓需求合计，输出「可承接 / 部分可承接 / 不足以承接」三档，并显式说明同一基地资源在多分仓之间的竞争关系。

### 第 5 步：冲突判定
按 `rules.md` 第 4 节现象规则匹配，识别基地库存高但分仓仍缺货、未来有排产但当前缺货、基地在途未按计划入库等冲突，给出判定与处理方向。

### 第 6 步：优先级建议
按「存在缺货 + 调拨中不足 + 未来需求较近」排序分仓优先级，并说明排序口径；不承诺到货时间、不给到货日期。

### 第 7 步：生成原因线索
按 `rules.md` 规则生成，每条标注证据状态，最多 5 条；证据状态标记在本回答内合计不超过 3 处。

### 第 8 步：输出协同建议与数据边界
协同方向只给角色不给姓名，全部标注【待人工确认】；整理数据边界与输出字段清单，按 **branch-policy 输出规范** 形成交付结果。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 基地可供三口径 = 基地当前可用库存 + 基地调拨在途（在途未入库）+ 未来 7 日排产；三者分开列出，禁止合并，禁止把排产当已入库或已承诺
- 需求侧两项 = 缺货量与建议补货量；先按 分仓 + SKU 算再汇总；缺货量 = max(0, 备单中剩余未占用量 − 当前可用库存量)
- 建议补货量 = max(0, max(缺货量, 低于目标量) − 调拨中)；调拨中 = 已下单未发货量 + 已发货未入库量
- 承接判断 = 可承接 / 部分可承接 / 不足以承接；同一基地资源在多分仓间存在竞争，必须显式说明
- 停用近似口径：基地库存高 ≠ 某分仓可得；未来有排产 ≠ 分仓按时到货；基地在途未入库 ≠ 分仓已入库
- 排序口径 = 缺口量降序 → 需求临近度（未来 7 日计划）；分母为 0 显示「—」，缺数按 0
- 分仓大日期阈值为 91 天及以上（基地为 61 天及以上），货龄分段为 0-30 / 31-60 / 61-90 / 91 及以上，两套口径不得混用
- 只读工具：`mcp__gea-gateway__inspect_cube_model`、`mcp__gea-gateway__query_business_data`、`mcp__gea-gateway__weknora_ask`；文中不出现表名、字段名、工具名

## 默认交付

1. 核心结论（一句话：基地可供能否承接、缺口量级、涉及基地与 SKU 数）
2. 分析范围、数据时间与供给口径说明
3. 基地可供清单（基地 / 提货点 / 品类 / SKU / 基地可用库存 / 基地在途未入库 / 未来 7 日排产）
4. 需求侧清单（分仓 / SKU / 缺货量 / 建议补货量 / 调拨中）
5. 承接判断与竞争关系（可承接 / 部分可承接 / 不足以承接）
6. 冲突清单（现象 / 判定 / 处理方向）
7. 优先级分仓清单与协同建议（按角色，标注【待人工确认】）
8. 数据边界与不可判断项

## 边界与禁止动作

- 不把未来排产当已入库库存或已承诺库存；不把基地可用库存直接等同于某分仓已锁定可得库存
- 禁止承诺到货时间、禁止自动创建调拨单、禁止自动创建事件或待办
- 禁止对无权限或未覆盖的分仓、基地、提货点做外推；排行只在权限范围内排序
- 建议 ≠ 执行：只输出协同方向与角色，P1 不写责任人姓名、不定责、不做升级判断
- 缺数按 0；整批不可达时只输出可判断部分并说明影响

## 与其他 Skill 的边界

| 场景 | 本 Skill 输出 | 转其他 Skill |
|---|---|---|
| 只问「哪些分仓缺货最多」 | 只补一句基地侧提示 | `branch-shortage-monitoring` |
| 只问「为什么要补货」「补多少」 | 只补一句基地可供提示 | `branch-replenishment-demand` |
| 「基地有货但分仓还缺」 | 冲突判定 + 验证方向 + 协同建议 | 规格/批次/提货点与订单结构侧需业务确认 |
| 「未来 7 日排产能否覆盖」 | 给计划供给信号与承接分档，不给到货承诺 | — |
| 「要不要提前补」 | 给优先级与协同方向 | `branch-replenishment-demand`（形成建议量） |
| 「基地无法承接怎么办」 | 给协同建议方向，标注【待人工确认】 | 事件与升级属 P2 |
| 已缺货且已定位具体订单/客户 | 只补基地侧视角 | `branch-shortage-monitoring`（订单缺口明细） |

## P2 承接

自动创建调拨单、到货时间承诺与到货计划锁定、跨基地替代方案审批、基地资源无法承接紧急补货的事件创建与升级闭环、责任角色推荐与历史反馈回流。
