# 分仓货龄与滞库监控 Skill

## 参考资源（按需加载）

- **`rules.md`**：货龄计算与四段划分、大日期判定、动销与滞库判定、健康库存占比、原因线索与消化方向规则 → 第 2、3、4、5、6 步前读取
- **branch-policy 数据边界**：数据边界与分仓 / 基地阈值区分 → 第 9 步前读取
- **branch-policy 证据与行动边界**：证据状态与行动边界 → 第 7 步前确认
- **branch-policy 输出规范**：输出规范 → 第 10 步前读取
- **branch-policy 取数契约**：取数与知识查询契约（cube 查询模板、上卷铁律、权限、降级） → 取数前必读
- **branch-policy 指标口径**：货龄与结构类指标口径、白名单 → 第 2 步前读取

## 目标

把库存批次、货龄、动销、计划与库龄结果等输入，转化为可追溯、可复核的货龄与滞库结论：四段货龄分布、大日期对象、滞库风险、健康库存占比、原因线索、消化方向和数据边界。

## 触发场景

- 「货龄分布怎么样」「平均货龄多少」「健康库存占比多少」
- 「60 天以上有多少」「91 天及以上（大日期）有多少」
- 「哪些 SKU 卖不动」「高库存低动销」
- 「滞库风险怎么看」「为什么库存超过目标还提示去化」
- 「未来 7 日 / 14 日哪些库存会超龄」→ 由 `branch-future-aging-projection` 推演，本 Skill 先给当前货龄结构

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 分析范围 | 分仓、区域、品类、物料组、SKU、批次 | 是 |
| 分析粒度 | 分仓 / 品类 / 物料组 / SKU / 批次 | 是 |
| 库存数据 | 当前可用库存、批次数量、生产日期或统一约定的库存起始日期 | 是 |
| 库龄结果 | 大日期库存量与 SKU 数、滞库风险库存量与 SKU 数、平均货龄 | 是 |
| 动销数据 | 近 30 日动销量、日均动销、近 30 日实际出库量 | 是 |
| 数据截止时间 | 库存 / 动销 / 库龄 / 计划各自时间 | 是 |
| 目标库存与差额 | 目标库存量、订单扣减后可供库存 | 否 |
| 计划与客户信号 | 出货计划、客户库存信号 | 否 |

**本 Skill 不涉及保质期与效期数据**（公司产品保质期统一 12 个月），不做效期比例推算。**不自行制定风险阈值**，滞库风险与平均货龄以大数据标准库龄结果为准。

## 执行步骤

### 第 1 步：校验批次与动销数据
确认批次粒度、生产日期完整性、动销数据时间范围与口径，并记录。无生产日期的批次标注「货龄未知」，不参与货龄排名。

### 第 2 步：计算货龄与四段结构
按 `rules.md`：批次货龄 = 统计日 − 批次生产日期（或统一约定的库存起始日期）；平均货龄按数量加权。按 **0-30 正常 / 31-60 关注 / 61-90 重点消化 / 91 天及以上大日期重点** 分段统计数量与占比，**边界日不得重复计入两个区间**。

### 第 3 步：识别大日期
筛选货龄 91 天及以上的批次与 SKU（分仓口径），输出数量、占比、SKU 数。60 天以上 = 61-90 天 + 91 天及以上两段之和，是风险区间但**不等于全部滞库**。

### 第 4 步：计算健康库存占比
按 `rules.md`：风险库存量 = 大日期库存量 + 滞库风险库存量（**同一批次重叠只计一次**）；健康库存量 = max(当前可用库存量 − 风险库存量, 0)；健康库存占比 = 健康库存量 ÷ 当前可用库存量。库存为 0 时显示「无库存 / —」。

### 第 5 步：动销与滞库风险判定
按 `rules.md` 结合库存差额、货龄结构、近 30 日动销与计划消化能力综合判定，输出 高风险 / 关注 / 正常；**不用单一指标定滞库**。动销量为 0 的单列「无动销」，先确认是否停产、未上市或统计不适用，不直接判滞库。

### 第 6 步：大日期专项输出（P1）
按货龄降序输出 91 天及以上清单（数量、占比、所在分仓与仓库、批次、动销情况）与消化方向。明确标注：「大日期按分仓货龄 91 天及以上判定，处理方案需业务确认」；P1 **不做专项台账与锁定**。

### 第 7 步：生成原因线索
按 `rules.md` 触发条件生成，每条标注证据状态，最多 5 条。不做责任判定，不推断目标或阈值设置合理性。

### 第 8 步：生成消化方向建议
按 `rules.md` 给出方向性建议（优先消化 60-90 天、控制新增补货、分仓内调剂、评估跨分仓或基地调拨、关注客户信号），标注【待人工确认】与建议责任角色；涉及报废、降价、清库等重大决策必须业务确认，P1 不给结论。

### 第 9 步：整理数据边界
按 **branch-policy 数据边界** 整理：数据时间、批次完整性、库龄结果来源、动销口径、缺失字段、不可判断项，并标明使用分仓 91 天阈值。

### 第 10 步：形成交付结果
按 **branch-policy 输出规范** 输出。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 货龄 = 统计日 − 生产日期；平均货龄按数量加权，禁止简单平均
- 货龄分段：0-30 正常 / 31-60 关注 / 61-90 重点消化 / 91 天及以上大日期重点（**分仓口径**）
- 大日期 = 91 天及以上（超过 90 天）；基地为 61 天及以上（超过 60 天），**不得混用**
- 平均货龄阈值：健康 < 20 天；预警 61-90 天；严重 ≥91 天
- 风险库存量重叠批次只计一次；健康库存占比分母为当前可用库存
- 滞库需同时看库存差额、货龄、动销与计划，不用单一指标
- 动销只用数量口径，不用动销率；消化建议 ≠ 处理指令；缺数按 0，分母为 0 或无数显示「—」

## 默认交付

1. 核心结论（一句话：大日期库存量、滞库高风险对象数、动销偏慢对象数）
2. 分析范围、粒度、数据时间与库龄结果来源
3. 货龄四段分布（数量与占比）
4. 健康库存占比与风险库存量
5. 大日期清单（91 天及以上，按批次）
6. 滞库风险对象 TOP 10（按风险等级 → 货龄 → 库存量）
7. 原因线索（带证据状态）
8. 消化方向建议（待人工确认与建议责任角色）
9. 数据边界

## 边界与禁止动作

- 不决定报废、不发起促销、不调价、不调拨、不定责、不推荐责任人（P1）
- 高于目标 ≠ 滞库；货龄长 ≠ 一定有问题；动销偏慢 ≠ 一定滞库
- 不做效期比例判断；不做大日期专项锁定与台账（P2）；不自行制定风险阈值
- 不把基地 60 天口径用于分仓；不把未来预计超龄当作当前大日期
- 处理建议 ≠ 正式处理指令
