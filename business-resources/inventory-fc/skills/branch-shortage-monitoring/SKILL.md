# 分仓缺货监控 Skill

## 参考资源（按需加载）
- **先加载 `branch-policy` Skill**（共享规范：指标口径、数据边界、取数契约、证据与行动边界、输出规范；内部包，不单独回答用户）。涉口径、排名、取数、分析、报告之前必读。

- **`rules.md`**：缺货量公式、订单状态与占用处理、缺货分层默认阈值、影响评估、原因线索规则 → 第 2、3、4、5、7 步前读取
- **branch-policy 数据边界**：数据边界与缺失处理 → 第 8 步前读取
- **branch-policy 证据与行动边界**：证据状态与行动边界 → 第 7 步前确认
- **branch-policy 输出规范**：输出规范 → 第 9 步前读取
- **branch-policy 取数契约**：取数与知识查询契约（cube 查询模板、上卷铁律、权限、降级） → 取数前必读
- **branch-policy 指标口径**：订单与履约类指标口径、白名单 → 第 1 步前读取

本 Skill 只回答**当前订单缺货**；建议补货量由 `branch-replenishment-demand` 承接，事后满足率只做口径解释。

## 目标

把当前可用库存、备单中订单需求与已占用量、需发货订单、在途与基地可供等输入，转化为可追溯、可复核的缺货结论：缺货量、缺货 SKU 与订单、影响范围、原因线索、可补方向与数据边界。

## 触发场景

- 「现在缺什么货」「缺多少」「哪些订单发不出去」
- 「哪些分仓缺货最高」「这个分仓缺货 SKU 明细」
- 「为什么库存不少还缺货」「为什么库存高还提示补货」
- 「缺货量和低于目标库存有什么区别」「缺货和订单满足率是一回事吗」

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 分析范围 | 分仓、区域、品类、物料组、SKU、客户、订单 | 是 |
| 备单中订单 | 需求量、已占用量 | 是 |
| 当前可用库存 | 分仓可用库存（不含在途） | 是 |
| 订单状态 | 备单中 / 备单完成 / 已发货，作废、无效、短拨剔除规则 | 是 |
| 数据截止时间 | 订单与库存各自时间 | 是 |
| 在途与调拨 | 已下单未发货量、已发货未入库量 | 否 |
| 基地可供 | 基地可用库存、基地在途、未来 7 日排产 | 否 |
| 动销与计划 | 近 30 日动销、出货计划 | 否 |

**不使用金额口径；不使用「订单量 − 库存」近似算法；可用库存或占用量缺失按 0 参与缺货计算并标注。**

## 执行步骤

### 第 1 步：校验订单与库存口径
确认订单状态范围、备单中已占用量的扣减程度（是否已扣到可用库存）、可用库存口径与数据时间，并记录。备单完成状态已占用库存并下发 WMS，**不得再次计入缺货需求**。

### 第 2 步：计算缺货量
按 `rules.md` 分三层计算：

```text
① 订单层（只取备单中订单）：订单还需满足量 = max(需求量 − 该订单已占用量, 0)
② 分仓 + SKU 层：缺货量 = max(Σ 订单还需满足量 − 当前可用库存, 0)
③ 分仓层：缺货量 = Σ 各 SKU 缺货量（不二次截零）
```

截零只能出现在①②两层：①截「扣占用后的负数」（改单 / 超额占用），②截「扣可用库存后的负数」；**可用库存不能摊到订单层**，否则富余订单的余量会被丢掉。禁止先汇总总量再算。
判定：缺货量 = 0 → 「当前订单可满足」；可用库存 = 0 且存在需求 → 「完全缺货」；有库存但不足 → 「部分缺货」。

> **可达性阻断（2026-10-14 实测，必须遵守）**：本指标按主口径需要**当前可用库存**与**备单中剩余未占用量**两类状态数据，两者在本次取数通道内**均不可达**（无分仓 / 基地库存快照与备单占用量模型）。因此**不输出当前缺货量结论**，改为按 branch-policy 指标口径 第十五节 15.3 的标准降级表述说明缺少的数据源，并给同通道内已验证的可代替指标；**严禁**给状态量套时间窗、或用订单归属月份口径回答「当前缺货」；阻断针对**整批数据不可达**，单个字段缺失按 0 参与并标注，两者不得混用。

### 第 3 步：缺货分层与排序
按 `rules.md` 默认阈值分为 一般 / 关注 / 紧急，并用「存在缺货且当前库存低于目标库存」识别紧急补货对象。排序：风险等级 → 缺货量 → 影响订单数。

### 第 4 步：关联影响范围
统计缺货 SKU 数、缺货订单数、影响客户数、总有效订单张数与缺货订单占比；有客户优先级信息时标注重点客户。

### 第 5 步：关联在途与基地可供（如有数据）
计算调拨中可覆盖量（**不推算到货时间**），区分「在途可覆盖缺口」「在途不足」与「无在途安排」；基地可供信号只作为承接参考，不等于分仓已锁定可得。

### 第 6 步：区分三个容易混淆的口径
用户问「低于目标」「满足率」时按 `rules.md` 第 5 节说明：低于目标是水位偏差；满足率是本月已发货订单的事后口径；缺货量是当前交付风险。三者不得互相倒推。

### 第 7 步：生成原因线索
按 `rules.md` 触发条件生成，每条标注证据状态，最多 5 条，无数据支撑的不列。

### 第 8 步：整理数据边界
按 **branch-policy 数据边界** 整理：数据时间、订单状态范围、库存与在途口径、缺失字段、不可判断项。

### 第 9 步：形成交付结果
按 **branch-policy 输出规范** 输出；缺货是当前快照，不得给趋势结论。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 缺货量 = max(0, 备单中剩余未占用量 − 当前可用库存量)：先订单层 max(需求 − 占用, 0)、汇总到分仓+SKU 再减一次可用库存，最后汇总到分仓
- 备单完成的占用量已扣减，不得重复计入缺货需求；已扣减到可用库存的部分不得重复扣减
- 缺货量统一按正数表示；订单扣减后可供库存可为负数，用于解释原因
- 缺货 ≠ 低于目标 ≠ 建议补货量 ≠ 事后满足率
- 缺货分层按数量与影响面，不用金额
- 紧急补货 = 存在缺货且当前库存低于目标库存，量由补货 Skill 计算
- 预计到货时间 ≠ 实际到货时间；缺数按 0

## 默认交付

1. 核心结论（缺货 SKU 数、缺货总量、缺货订单数）
2. 分析范围、粒度、数据时间与订单状态口径
3. 缺货汇总（按分仓 / 品类，分项不抵消）
4. 重点缺货 TOP 10（按风险等级 → 缺货量）
5. 影响范围（缺货 SKU 数、缺货订单数、影响客户数、缺货订单占比）
6. 在途与基地可供（如有数据）
7. 原因线索（带证据状态）
8. 可用方向建议（标注待人工确认与建议责任角色）
9. 数据边界

## 边界与禁止动作

- 不生成正式补货单、不调拨、不承诺到货时间、不定责、不推荐责任人（P1）
- 低于目标 ≠ 缺货；缺货 ≠ 建议补货量；缺货 ≠ 事后满足率
- 不使用金额口径；不用现库存替代当前可用库存；不对缺货量先汇总再算
- 缺失可用库存时不给确定缺口结论；无历史快照时不回答缺货趋势
