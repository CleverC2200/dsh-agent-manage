# 分仓缺货监控 — 规则与阈值

## 1. 计算公式

| 指标 | 公式 | 说明 |
|---|---|---|
| 订单还需满足量（订单层） | max(该订单需求量 − 该订单已占用量, 0) | 只取备单中订单；改单 / 超额占用出现负数按 0；已占用部分不得重复扣减 |
| 备单中剩余未占用量（分仓 + SKU 层） | Σ 订单还需满足量 | 逐单相加，不再截零 |
| 订单扣减后可供库存量 | 当前可用库存量 − 备单中剩余未占用量（Σ 订单还需满足量） | 可为负数 |
| 缺货量 | 分仓+SKU 层：max(备单中剩余未占用量 − 当前可用库存量, 0)；分仓层：Σ 各 SKU 缺货量（不二次截零） | **统一按正数**；唯一口径；可用库存只在这一层减一次 |
| 缺货 SKU 数 | 缺货数量 > 0 的 SKU 数 | COUNT DISTINCT |
| 当前未发货订单量 | 备单中未发货量 + 备单完成未发货量 | 看板客户订单主值 |
| 缺货订单数 | 存在缺货的订单张数 | 与缺货量分开统计 |
| 缺货订单占比 | 缺货订单数 ÷ 总有效订单张数 | 分母为 0 显示「—」 |
| 紧急补货 SKU 数 | 同时满足存在缺货且当前库存低于目标库存的 SKU 数 | 量由补货 Skill 计算 |

禁止口径：缺货 = 订单总量 − 当前库存；缺货 = 订单总量 − 已占用量；**把可用库存摊到订单层再截零**（富余订单余量被丢掉，缺货低估）；**分仓层对汇总缺货二次截零**；用当前缺货倒推订单满足率。

## 2. 订单状态与占用处理

| 订单状态 | 库存处理 | 缺货计算处理 |
|---|---|---|
| 备单中 | 可能只有部分数量已占用库存 | 计算剩余未占用量 |
| 备单完成 | 已占用库存并下发 WMS | **不再重复计入缺货需求** |
| 已发货 | 已完成发货，已发货数量从库存扣减 | 不计入当前未发货缺口 |

若数据服务已将某部分备单中订单量扣减到当前可用库存，则**只扣减尚未扣减的部分**，不能重复扣减。有效订单必须剔除作废、无效与短拨订单；订单状态口径由大数据统一处理，Agent 不自行判断。

## 3. 特殊情况处理

| 情况 | 处理 |
|---|---|
| 当前可用库存缺失 | 按 0 参与缺货计算，标注「可用库存缺失，缺货按需求量计」；整批库存不可达时按可达性阻断处理 |
| 备单中已占用量缺失 | 按 0 参与，标注「占用量缺失，缺货按需求量计」 |
| 无未完成订单 | 标注「当前订单可满足」，不计算缺货 |
| 数据服务已部分扣减占用 | 只扣未扣减部分，并在数据说明中写清 |
| 目标库存缺失 | 不影响缺货量计算，但不可据此给建议补货量 |
| 订单快照不完整 | 结果标记「部分数据」，说明覆盖范围 |

## 4. 缺货分层（受控配置默认值，待业务确认）

| 层级 | 缺货量参考 | 附加条件 | 标记 |
|---|---|---|---|
| 一般 | 相对低位 | — | 绿 / 橙 |
| 关注 | 中等 | 或多订单受影响 | 橙 |
| 紧急 | 相对高位 | 或影响重点客户、交付临近、同时低于目标库存 | 红 |

自动升级条件：涉及重点客户；缺货持续且在途不足；缺货同时低于目标库存；缺货订单占比偏高。阈值属业务维护规则包受控参数，未维护时只做方向性提示，不自行编造阈值。

## 5. 与相近指标的边界

| 指标 | 回答什么 | 不能替代 |
|---|---|---|
| 缺货量 | 当前未完成订单还差多少库存 | 不能替代库存差额与建议补货量 |
| 库存差额 | 订单扣减后可供库存距离目标水位的差距 | 不能说明当前交付风险 |
| 建议补货量 | 覆盖订单缺口与库存差额并扣调拨中后的建议量 | 不是正式订单，也不能说明当前缺了多少 |
| 本月已发货订单满足率 | 本月已发货订单量 ÷ 本月有效订单总量（事后） | 不能用于判断当前缺货 |
| 数量满足率 | 本月已发货量 ÷ 本月有效订单需求量（事后） | 不能替换主 KPI，也不能替代缺货量 |
| 当前备单满足率 | 已备量 ÷ 当前备单量 | 与本月已发货满足率口径不同，必须分别标注 |

## 6. 影响评估

| 指标 | 计算 |
|---|---|
| 缺货 SKU 数 | 存在缺货的 SKU 去重数 |
| 缺货订单数 | 存在缺货的订单张数 |
| 影响客户数 | 去重客户数 |
| 缺货订单占比 | 缺货订单数 ÷ 总有效订单张数 |
| 预计影响天数 | 缺货量 ÷ 近 30 日日均出库量（无出库数据时不计算） |

发货优先级仅为建议：重点客户优先、先到订单优先、小批量优先；不自动调整分配。

## 7. 原因线索（最多 5 条，标注证据状态）

| 方向 | 子原因 | 触发条件 | 证据状态 |
|---|---|---|---|
| 需求端 | 订单突增 | 近期订单量高于近 30 日日均明显幅度 | 有支撑未验证 |
| 需求端 | 客户集中拉货 | 前几大客户拉货占比偏高 | 有支撑未验证 |
| 库存端 | 备单占用偏高 | 备单中剩余未占用量接近或超过当前可用库存 | 已验证 |
| 库存端 | 现库存高但可供不足 | 现库存显著高于当前可用库存 | 已验证 |
| 库存端 | 结构错配 | 高库存与缺货并存 | 有支撑未验证 |
| 供给端 | 调拨未按时到达 | 已下单未发货或已发货未入库量高于缺口量 | 已验证（有在途数据时） |
| 供给端 | 基地资源未承接 | 基地可供不足或无排产 | 有支撑未验证 |
| 数据端 | 数据未刷新或部分覆盖 | 数据时间滞后或覆盖不全 | 数据缺失 |

## 8. 可用方向建议（标注【待人工确认】与建议责任角色）

| 情形 | 方向建议 | 建议责任角色 |
|---|---|---|
| 有在途调拨 | 核实在途是否可覆盖缺口并跟进调拨节奏（不承诺到货时间） | 分仓计划员 |
| 无在途、基地可供充足 | 建议评估补货与调拨安排 | 分仓计划员 + 基地协同人员 |
| 基地可供不足 | 建议协同替代基地或调整实际补货量 | 基地协同人员 |
| 高库存与缺货并存 | 建议核查规格、批次、提货点需求匹配 | 分仓计划员 + 区域计划 |
| 数据不完整 | 建议数据复核与补齐 | 数据负责人 |

**不给到货时间**（缺乏可靠测算依据）；不生成正式补货单、不指定生产批次。

## 9. 数据完整性校验

必备字段：分仓、SKU 或品类、备单中订单需求量、当前可用库存、数据截止时间。缺字段时按指标分别处理，**不整行作废**：可用库存或占用量缺失按 0 参与缺货计算并标注；两者都缺的行不参与缺货、单列；其余指标照常输出。

可选字段缺失时：无占用量 → 不作确定结论；无在途 → 不给可补判断；无动销 → 不判断影响天数。

## 10. P2 承接

待办 / 事件闭环、历史反馈闭环、责任判定与协同角色推荐、升级审批、缺货历史趋势、DMS 提交失败与处理闭环。
