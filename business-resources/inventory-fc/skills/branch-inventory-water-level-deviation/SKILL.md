# 分仓库存水位与偏差 Skill

## 参考资源（按需加载）
- **先加载 `branch-policy` Skill**（共享规范：指标口径、数据边界、取数契约、证据与行动边界、输出规范；内部包，不单独回答用户）。涉口径、排名、取数、分析、报告之前必读。

- **`rules.md`**：库存水位公式、目标库存测算、差额与偏差率、健康库存占比、周转天数与风险分层默认阈值 → 第 3、4、5、6、8 步前读取
- **branch-policy 数据边界**：数据边界、补货周期与计划缺失处理、分仓与基地阈值区分 → 第 9 步前读取
- **branch-policy 证据与行动边界**：证据状态与行动边界 → 第 8 步前确认
- **branch-policy 输出规范**：输出规范 → 第 10 步前读取
- **branch-policy 取数契约**：取数与知识查询契约（cube 查询模板、上卷铁律、权限、降级） → 取数前必读
- **branch-policy 指标口径**：库存水位、周转与结构类指标口径与白名单 → 第 2 步前读取

## 目标

把当前可用库存、现库存、在途、目标库存、计划与出库等输入，转化为可追溯、可复核的库存水位结论：水位高低、库存差额、周转能力、健康库存占比、重点对象、原因线索、建议与数据边界；保留补货周期、计划版本、数据时间、粒度与证据状态。

## 触发场景

- 「库存水位怎么样」「库存够不够」「现库存和可用库存差在哪」
- 「目标库存是多少」「为什么补货周期变了目标就变了」
- 「库存符合率多少」「库存结构和发货结构匹配吗」
- 「哪些分仓低于目标」「库存差额排行」
- 「周转天数多少」「能卖多少天」「回顾和展望周转有什么区别」
- 「健康库存占比多少」「大日期和滞库风险扣了多少」

## 输入契约

| 输入项 | 说明 | 必填 |
|---|---|---|
| 分析范围 | 分仓、区域、品类、物料组、SKU | 是 |
| 分析粒度 | 分仓 / 品类 / 物料组 / SKU / 分仓×SKU | 是 |
| 库存数据 | 现库存、当前可用库存、批次 | 是 |
| 在途数据 | 已下单未发货量、已发货未入库量（**分别取数**） | 是 |
| 补货周期 | 分仓已生效补货周期（未配置按默认 7 天） | 是 |
| 计划数据 | 本月出货计划、次月出货计划、本月已发货量（用于目标与展望周转） | 是 |
| 出库数据 | 近 30 日实际出库量 | 是（缺失则周转不可计算） |
| 库龄结果 | 大日期、滞库风险、平均货龄 | 否 |
| 目标周转天数 | 前端配置值 | 否 |

缺可选字段时继续输出可判断部分，并在数据边界说明限制。**不使用金额口径**（金额只用于分仓整体增长率解释）。

## 执行步骤

### 第 1 步：校验库存与在途口径
确认现库存、当前可用库存、订单扣减后可供库存的区别与取数口径；在途必须分为已下单未发货与已发货未入库两类并分别记录时间。

### 第 2 步：确定补货周期与计划版本
读取分仓已生效补货周期；未配置时按默认 7 天并标注。涉及计划时按「分仓 + 目标月份」整体确定版本（月初优先滚动）与来源（人工优先 BI），记录是否为预览。

### 第 3 步：测算目标库存
按 `rules.md`：安全库存周转天数 = 补货周期 + 3 天；日均出货计划 = 基准出货计划 ÷ 基准月自然日数（计算日 1–20 日用本月出货计划、21 日及以后用次月出货计划；出货计划导入版优先，无导入用系统版）；目标库存 = 安全库存周转天数 × 日均出货计划。缺少生效计划或基准出货计划为 0 时**不给精确目标**。

### 第 4 步：计算库存差额
按 `rules.md`：库存差额（净额）= 订单扣减后可供库存 − 目标库存量；低于目标量 = max(0, 目标库存量 − 订单扣减后可供库存量)。**基准是订单扣减后可供库存，不是现库存**；汇总直接相减、允许正负抵消，需分项时再补「高于目标量 / 低于目标量」。

### 第 5 步：计算周转天数
回顾周转天数 = 当前可用库存 ÷ 近 30 日日均出库量；展望周转天数 = (当前可用库存 + 有效在途) ÷ 展望 30 日日均出货量。分母为 0 显示「—」。两者必须分别标注，禁止混称。

### 第 6 步：计算健康库存占比与结构
健康库存量 = max(当前可用库存 − 风险库存量, 0)；风险库存量 = 大日期库存量 + 滞库风险库存量，**同一批次重叠只计一次**；库存为 0 时显示「无库存 / —」。

### 第 7 步：风险分层与排序
按 `rules.md` 默认阈值分为 正常 / 关注 / 高风险，区分高于目标与低于目标。排序：先按风险等级，再按差额量，周转与货龄作补充。业务维护阈值未生效时只做方向性提示。

### 第 8 步：生成原因线索与建议
按 `rules.md` 触发条件生成原因线索，每条标注证据状态，最多 5 条；建议标注优先级与【待人工确认】，只给建议责任角色，不写人名。

### 第 9 步：整理数据边界
按 **branch-policy 数据边界** 整理：数据时间、补货周期来源、计划版本与来源、缺失项、不可判断项，并标明使用分仓阈值。

### 第 10 步：形成交付结果
按 **branch-policy 输出规范** 输出（快速问数档 / 分析档 / 看板档）。

## 规则与阈值

详细规则见 `rules.md`。核心摘要：

- 库存水位主值是**当前可用库存量**，不含在途；在途两类分别展示
- 目标库存 = (补货周期 + 3 天) × 日均出货计划；日均出货计划按计算日取基准（1–20 日用本月出货计划、21 日及以后用次月出货计划）；周期未配置默认 7 天
- 库存差额基准是订单扣减后可供库存，不是现库存
- 回顾周转 ÷ 近 30 日日均出库量；展望周转含有效在途，必须标明
- 天数与比率一律用汇总分子 ÷ 汇总分母，禁止对下级天数取平均
- 分仓大日期阈值 91 天及以上（超过 90 天）、货龄分段 0-30 / 31-60 / 61-90 / 91 及以上
- 风险库存量重叠批次只计一次；缺数按 0；分母为 0 显示「—」
- 库存结构符合率 = 1 − Σdᵢ ÷ 2（只纳入库存≠0 且 日均发货≠0 的 SKU，单品层算偏差、目标层算符合率，不可上卷）

## 默认交付

**先判问法**：用户只问**一个指标或一个分仓**（「长沙分仓目标库存多少」「某分仓库存差额多少」「周转几天」）时，走 **branch-policy 输出规范 6.1.1 单指标问数**——只答被问的那个指标，≤200 字、最多 3 段、不套小标题、默认不用表格，不输出下面的 9 段。下面 9 段只在用户问「库存水位怎么样」「整体情况」这类**综合水位**问题时使用。

综合水位问题的交付顺序：

1. 核心结论（一句话：水位高低、库存差额、周转能力）
2. 分析范围、粒度、数据时间、补货周期与计划版本
3. 水位与在途（当前可用库存、现库存、已下单未发货、已发货未入库）
4. 目标库存与差额（含测算依据，高于 / 低于分项）
5. 周转能力（回顾 / 展望 / 目标周转对比）
6. 健康库存占比与结构摘要
7. 重点对象 TOP 10（按风险等级 → 差额 → 周转）
8. 原因线索（带证据状态）与建议（待人工确认）
9. 数据边界

## 单指标问答示例（目标库存，照此密度，不套小标题）

```text
长沙分仓目标库存 8.6 万件，按补货周期 7 天加 3 天备货期、日均出货计划约 8,600 件测算；
周期是该分仓已生效配置，计划用 10 月月初版本、人工提报，不是预览值。
当前库存差额 −1.2 万件，属低于目标，基准是订单扣减后可供库存，不是在库实物；在途另算，未并入目标口径。
要看基准计划与补货周期怎么来的、哪些 SKU 拉低了水位、按缺口该补多少，我可以继续拆。
```

要点：数在段一、依据压成一句、限制只在会被误解处补一句、引导 2-3 个；**不写现库存、缺货量、货龄、周转、TOP10**，用户追问再展开；不出现表名与字段英文名。

示例数字只示意形态，**必须替换为本次实际取到的数**；取不到就按数据缺失说明，不得沿用示例数字。缺生效计划或日均量为 0 时，不给精确目标库存，改说「缺少生效计划，目标库存无法给出」并只答可判断部分。

## 边界与禁止动作

- 不修改补货周期配置、不调整目标库存、不生成补货单、不定责、不推荐责任人（P1）
- 低于目标 ≠ 当前缺货；高于目标 ≠ 滞库；周转天数高 ≠ 动销量最少
- 不使用金额口径；不对下级天数或比率取平均；不用现库存替代订单扣减后可供库存
- 计划缺失时不给精确目标库存与建议补货量
- 临时修改补货周期只影响预览，不影响定时预警

## 与其他 Skill 的边界

| 场景 | 本 Skill 输出 | 转其他 Skill |
|---|---|---|
| 问是否缺货、缺多少 | 水位与差额 + 标注需结合订单判断 | branch-shortage-monitoring |
| 问要不要补、补多少 | 库存差额 + 标注需结合缺货与在途 | branch-replenishment-demand |
| 高于目标且动销偏慢、货龄长 | 差额 + 标注滞库风险 | branch-aging-stagnation-monitoring |
| 问未来是否会超龄 | 当前货龄结构 + 标注可转推演 | branch-future-aging-projection |
| 问计划为什么变了 | 目标输入摘要 + 标注可转计划解释 | branch-plan-version-explain |
| 只问一个指标或一个对象（如「长沙分仓目标库存」） | 直接按单指标问数回答（数 + 一句口径 + 引导），不启动 9 段完整流程 | — |
