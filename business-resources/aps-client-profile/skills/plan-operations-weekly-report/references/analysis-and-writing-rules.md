# 分析与写作规则

## 1. 状态表达

业务正文可使用：

- `✅ 达标/改善`；
- `⚠ 预警/需关注`；
- `🔴 严重/未达成`；
- `📋 待核查/推进中`；
- `— 数据不足或不可计算`。

图标只辅助阅读，必须同时保留文字状态。阈值未确认时不得使用正式红黄绿灯。

## 2. 摘要写法

摘要使用“变化 + 对象 + 影响”表达：

```text
正向：<指标>达到<结果>，较<基准>改善<差异>，主要由<对象>贡献。
风险：<指标>未达<目标>，缺口为<差异或影响量>，集中在<对象>。
节奏：本周较上周<改善/恶化>，但<连续性或结构性风险>仍存在。
```

不要只罗列六个数值，也不要用“明显、较大、严重”等词替代量化比较。

## 3. 原因判定

每条原因区分：

- `已验证`：当期对象关联、时间关系、机制和关键记录支持；
- `待验证`：已有线索，但缺少对象关联、时间或影响量；
- `数据缺口`：缺少继续判断需要的数据或权限；
- `口径冲突`：指标、阈值、单位、时间或版本冲突。

经营报告、历史周报、会议纪要和人员判断只能提供线索。原因必须回到当期数据验证；不得复制参考报告中的具体基地、品项、产能、物流或库存故事。

## 4. 交叉指标判断

优先识别：

| 组合 | 可提示的调查方向 | 不能直接下的结论 |
|---|---|---|
| 低满足率 + 高可发货天数 | SKU、基地、渠道、效期或可用性结构错配 | 不能仅凭组合认定调拨不及时 |
| 低满足率 + 低可发货天数 | 总量供给不足、需求激增、生产/外协不足 | 不能仅凭组合认定生产原因 |
| 高满足率 + 高可发货天数 | 被动备货、需求低于计划、库存去化慢 | 不能仅凭组合认定计划过高 |
| 满足率改善 + 动作未完成 | 其他因素、时点或结构变化 | 不能把改善归因于未完成动作 |
| 准交率低 + 满足率高 | 发运、运输、签收或承诺时间问题 | 不应写成数量缺货 |

交叉指标决定下一步查什么，不单独证明根因。

## 5. 改善动作

每项行动至少写明：

- 对应问题；
- 动作对象和内容；
- 责任角色；
- 计划完成时间或触发条件；
- 前置条件；
- 完成证据；
- 验收指标和观察窗口。

“已推动、持续跟进、加强协同”等没有对象、责任和验收条件的表述不能单独作为管理动作。

执行状态必须依据台账或回执。没有真实执行证据时写“建议”或“待启动”，不得写“已落地”。

## 6. 长期机制

长期规划应解决重复发生的管理缺口，例如：

- 产能缺口前置识别；
- 产能资源与改造台账；
- 应责口径和归因分账；
- 缺货多维闭环；
- 决议编号和升级机制。

这些只是机制类别，不是每期必填项。只有当期问题和治理目标支持时才纳入，并写清里程碑或触发规则。

## 7. 文风与排版

- 中文、结论先行；
- 表格展示全量比较，文字聚焦最重要的改善、恶化和矛盾；
- 百分率差使用 `pct`，绝对变化保留原单位；
- 数字小数位同一指标内保持一致；
- 状态颜色或图标不能成为唯一信息载体；
- 长表允许跨页，但表头重复；原因卡片尽量不跨页拆分；
- 标题层级与章节编号连续，不复制参考样例中的编号错误。
