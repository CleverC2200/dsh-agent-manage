# 从原文到机制

以下是假设训练例，不能回填企业报告。

例1：同基地SKU甲产线L，三日理由分别为“熟练机手不足，开两班改一班”“人员不足降速”“机手缺岗”；计划100/100/100，实产70/80/100。程序应算3个记录日期、2个欠产日、净差50、正差50。不能说三天都欠产。

弱答案：“人员问题50件，建议增人。”

可用机制：“原文把机手岗位缺口与班次减少、降速连接起来，提示熟练岗位覆盖约束；最后一天仍记录缺岗但达到计划，不能把全部缺岗记录认定为减产。需核对排班、缺岗工时与速度。”状态supported_unverified；边界：“尚无订单需要时间和供给配对，不能确认订单损失”。行动核对同日同线排班、班次与产出，验收为记录可复核，不擅定百分比目标。

例2：理由“前处理故障，供面不及时”，只有基地×日×原因，两日净差30，无SKU/产线/单号。可以解释“前处理供面中断影响后续连续生产”的工序约束线索；不能写“SKU甲在L线故障两天损失30件订单”。两日有记录不证明整两天停机。要求核对故障时间、受影响SKU及下游等待；状态supported_unverified。

例3：甲省区缺货200、乙50，准确率与需求事件缺失。甲是优先核查对象，不能认定其预测最差；补同口径双版本提报与需求事件。不能拿纠偏总量减缺货订单子集评价准确率。

填写卡片时先读packet原文和recordRefs。程序给数量/日期，模型填有依据的解释、反证、边界、行动和建议角色。引用未出现的对象/事件先补证据。依据不足写hypothesis；记录原文是来源陈述，不自动证明真实因果。

同原因不是多次独立损失；父级/品类/SKU不累加。根级finding记录数不是原始生产单数；“—”“全部SKU”不算键。verified_cause必须有订单供给关系、时间与同口径影响量依据。
