# 结论逐项复核

1. 全国、基地、品类分别回到原始返回。列出所有计划大于实绩的基地，不能因为差额小就写成超产；同一报告的摘要、正文、行动必须一致。
2. 总量达成与SKU/日期兑现不同。提报总量大不能证明提报准确、品类生产总量超产不能排除短缺SKU欠产；不得用“更可能在发运”替代缺少证据的生产解释。仅列并列事实与下一步待核查关系。
3. 生产理由原文按业务机制分析，不只列标签。区分岗位覆盖、熟练度、前处理供料、成型/速冻/包装设备、换线换日期、排产能力；由本期实际原文决定，不强制遍历。按可用日期、SKU、产线和单号支撑，保留反证。
4. 理由数字码未映射，表述为“含义待核验”，不能断言无业务含义、擅自要求系统禁用，也不能作为业务缺货原因。其数量只在审计中说明证据覆盖。
5. 验收依据以资料、配对、计算和动作闭环为准。未经用户/制度确认，不自定下月达成率、下降幅度或100%覆盖目标。
6. 全国已知结果、哪些对象更重要、独立的供需机制和优先行动必须综合成业务段落；不要直接输出scope JSON、英文变量名、recordRefs数组。完整记录放证据附件，正文用简短证据索引。
7. 单位未确认时保留“源数量单位（待核验）”；不能因为接口默认件就把来源未知写成件。跨模型数量不做加减；日期类型分别核对。
8. 按本期有价值的对象选择深度。另一基地仍欠产且已有理由汇总时，继续解释已有原文，不把全部分析收缩到最大基地。销售准确率返回有效子级时保留并定位，不因父级NULL而停止。

程序会给businessIssues，但不能完整验证自然语言。出现这些问题不能以READY_WITH_GAPS宣布业务验收通过；应修正不成立的结论或明确降级。

运行时单位声明：生产源未提供单位证据时设置 `scope.productionUnitStatus="unverified"`、`scope.productionUnit="源数量单位（待核验）"`，自产明细与 channel=self 证据使用同一单位；不得先填件再用脚注否认。禁止与订单件数求差或计算贡献率。
