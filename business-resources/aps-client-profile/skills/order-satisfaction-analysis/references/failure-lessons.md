# 本次失败复盘与已落实改进

用于维护Skill和复跑前检查，不把历史数值当现行结果。

| 暴露的问题 | 原因 | 放置位置与已落实规则 | 验收证据 |
|---|---|---|---|
| 指标资料被说成去查飞书 | 混淆历史资料来源与当前查询入口 | SKILL/指标契约：按主提示词调用WeKnora，定义与实际查询分层 | 任务定义引用可追溯；不要求飞书权限 |
| 两类缺货缺值或换表取数 | 查询范围与表不一致 | source-to-report-map + make-query-plan：同一orders池保留原始分类，正缺货子集另算 | 全量/子集行数与合计记录 |
| 分类不勾稽后整块隐藏 | 把口径冲突当没有数据 | 保留源分类、复算、缺值、差额；卡片三标签，详细审计折叠 | 不能将发布总缺货复制给分类量 |
| 计划为空仍按0计算 | 数值兜底覆盖null | prepare-source-bundle：全空分组保持null，部分合计显示覆盖状态 | self-check缺计划用例 |
| 全国卡有值，品类列表空 | 未建立SKU映射和跨表聚合绑定 | mapping同月基地口径，sales/orders分别聚合后全外关联 | audit-bindings全国→维度→SKU→源行勾稽 |
| 连接事实表后数量变大 | 物料/组织多对多联结 | 唯一映射检查、歧义单列、编码路径匹配；不先join原始事实 | 合计守恒、单边保留测试 |
| 准确率缺失/拿错表 | 混用了销售下单和订单需求 | sales源基础量与权重定义；缺值如实显示，不平均比率 | 空值/权重/负准确率规则 |
| 有生产数据却整块空 | 只查MES，未查排程和其他来源 | 双源核查；MES无覆盖时继续查schedule，保留stock/transfer核验任务 | audit-bindings逐品类和基地覆盖表 |
| 只修调理肉，复跑仍丢数据 | 品类名特判与临时脚本未入包 | supply-scope通用SKU范围，无固定品类、月份或历史数值 | 任意新品类合成用例 |
| 点条形图下方不切换 | 选中状态只影响高亮，未重新筛供给源 | runtime同时更新SKU集合、卡片、列表、来源与范围 | 所有对象逐项切换；不得回退全国值 |
| 同SKU跨工厂被并成一条 | 主键缺来源/工厂 | schedule按来源×工厂×SKU分组，记录数与匹配SKU数分别统计 | 两个工厂同SKU用例 |
| 为补值改变了指标语义 | 把排程交付冒充自产执行 | 来源切换、独立标签和单位；不叠加MES/排程 | 计划/交付/执行字段清楚可见 |
| 样式反复偏离模板 | 另写表格和下钻，只有CSS相似 | 统一drill-row、inline-drill-row、plan-drilldown、source-record-scroll结构 | 操作列只放按钮，面板整行跨列展开 |
| 原始记录挤在最后一列 | 把details子表嵌在操作单元格 | SKU下一行colspan全表；长表局部滚动 | 展开/收起/切对象/窄屏验收 |
| 原因字典和总原因分析丢失 | 只修局部卡片，没对照全模板 | 看板绑定索引和交付模块清单；全量结论不受当前选择限制 | 原因字典、细分类、原文和第四模块逐项核对 |
| 长审计段落挤进指标卡 | 不区分紧凑提示与详细证据 | 分类标签与帮助提示；详细审计按需展开 | 首屏卡片高度与模板一致 |
| 声称“验收通过”但没点过 | 将源码/DOM通过当浏览器视觉通过 | 技术、交互、视觉、业务、目标环境实跑各自记录状态 | NOT_RUN不可被PASS覆盖 |
| 临时修复未进入可运行包 | 只改HTML/临时生成器，打包白名单漏脚本 | 可重复源处理入口、依赖打包检查、解压自检 | runtime-package哈希、self-check、无本机路径/令牌 |

本次优化重点是让数据和页面问题能被程序提前发现；仍需模型依据知识库解释机制并写综合分析，人工核验单位和正式口径。脚本不能自动把生产原因升级为订单损失归因。

## 订单品类有数但MES未匹配

订单分类与生产供给分别取数：品类由同月agents_scm_demand_sales_f基地口径映射订单SKU；分类量由agents_scm_order_plan_exe_m正缺货源行复算。MES匹配不到不影响订单分类值。MES未覆盖SKU必须继续通过Cube inspect/query排程agents_prod_schedule_detail_d，并向知识库核验字段和单位。存在其他品类的MES记录不能把排程标为not_applicable。模型不可用记录query_failed及错误证据，保留订单数值，不写已查无数据。历史直连排程仅作追查线索，不能替代本次MCP结果。
