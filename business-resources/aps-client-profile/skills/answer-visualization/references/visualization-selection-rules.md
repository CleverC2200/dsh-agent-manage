# 产销协同数字人回答可视化规范

## 1. 选择原则

先判断用户要回答的问题，再选择图表。不要因为有数据就强行画图；能够用一句话或一个数字说清的内容，不使用复杂图形。

每个图表必须同时具备：

- 明确的问题或结论标题；
- 对象、期间、单位和数据截止；
- 一句“读图结论”，说明用户应该看到什么；
- 数据状态：已验证、待验证、数据不足或口径冲突；
- 可切换的数据表，保留精确数值和无障碍读取能力。

## 2. 问题与图表映射

| 用户问题 | 首选表达 | 使用条件 | 不建议 |
|---|---|---|---|
| 当前是多少、是否达标 | KPI 卡片 | 单一指标或少量核心指标 | 为一个数字单独画柱状图 |
| 谁高谁低、对象排名 | 横向柱状图 | 类别无自然时间顺序；标签较长；强调排序 | 折线图、饼图 |
| 少量类别的并列比较 | 纵向柱状图 | 2-7 个短标签类别；基线从零开始 | 类别过多时继续用纵向柱 |
| 随时间怎么变化 | 折线图 | 连续时间序列，至少 3 个可比时间点 | 用折线连接无顺序类别 |
| 各部分由什么构成 | 堆叠柱状图 | 比较总量及构成；所有系列单位一致 | 系列过多或正负值混堆 |
| 不同对象的占比结构 | 100% 堆叠柱状图 | 各对象内部合计为 100% | 同时比较绝对总量 |
| 两个变量是否相关 | 散点图 | 至少 8 个有效对象；X、Y 都是连续数值 | 直接把相关性写成因果 |
| 基地×品项等二维状态 | 热力图 | 两个离散维度交叉，颜色阈值已确认 | 没有图例或只靠颜色表达 |
| 从基准到结果的贡献 | 瀑布图 | 有可加、互斥的增减贡献项 | 比率、重复贡献或无法勾稽的数据 |
| 需要精确查数、审计、明细 | 表格 | 多指标、多字段、长文本或需要精确值 | 把大表直接塞进图表 |
| 2-5 个部分占一个整体 | 环形图（谨慎） | 合计为 100%，只强调粗略占比 | 类别超过 5 个、精确比较、时间变化 |
| 只有结论或数据不足 | 结论卡／空状态 | 没有足够可靠的数据画图 | 编造数据完成图形 |

默认不使用 3D 图、双 Y 轴、雷达图、仪表盘和词云。只有明确业务价值且不会误导时才例外使用。

## 3. 图表选择顺序

```text
先问：是否需要图表？
├─ 一个数字或状态 → KPI 卡
├─ 精确明细或字段多 → 表格
├─ 时间变化 → 折线图
├─ 类别比较或排名 → 柱状图
├─ 构成变化 → 堆叠柱状图
├─ 两变量关系 → 散点图
├─ 二维交叉状态 → 热力图
└─ 可加贡献到结果 → 瀑布图
```

如果一个问题需要多张图，顺序固定为：

1. 先给核心结论和 KPI；
2. 再给总体趋势或比较；
3. 再给异常对象和贡献；
4. 最后给明细表、证据和行动建议。

默认只生成 `1–3` 张真正支撑答案的图，不把所有图表类型同时放进一份回答。第一张主图占整行；辅助图最多两张并排。明细表、证据与建议默认折叠，用户需要时再展开。

## 4. 视觉规范

本模板统一遵循 `plan-ops-workbench/skills/workbench-ui-style` 的 Workbench UI Style V0.3。不得另建深蓝、亮蓝或近似红主题，也不得用页面局部样式覆盖语义状态色。

### 颜色

- 品牌主色：`#df1732`；Hover：`#c91029`；Selected 浅背景：`#fff0f2`；
- 页面背景：`#f7f8fa`；内容面：`#ffffff`；表头与禁用背景：`#f5f6f8`；
- 主文字：`#20232a`；正文：`#555d68`；辅助文字：`#858c96`；
- 普通边框：`#e3e6ea`；控件边框：`#d9dde3`；
- 健康：文字 `#168e58`、背景 `#eaf7ef`；
- 预警：文字 `#956900`、背景 `#fff4d9`；
- 严重：文字 `#c8112a`、背景 `#ffe9ec`；
- 待验证／中性：文字 `#667085`、背景 `#eef1f5`。

红黄绿只能在阈值、方向、单位和版本均已确认时使用。颜色不能成为唯一状态载体，必须同时显示文字或符号。

图表填充和折线优先使用浅色系，状态文字与状态标签仍使用上面的标准语义色：

- 严重图形：`#ed999e`；预警图形：`#fff2cc`；健康图形：`#b8d9c5`；中性图形：`#d9dde3`；
- 主趋势线：`#ed999e`；目标线或参考线：`#c9ced7`；
- 不使用深红、深绿作为大面积柱形填充；深色仅用于文字、状态标签和必要的交互强调。

### 排版

- 字体栈固定为 `"Microsoft YaHei UI", "PingFang SC", "Noto Sans CJK SC", Arial, sans-serif`；
- 结论先行，页面标题只保留一个主层级；
- 模块标题 `18px`，正文 `12px`，卡片标题和控件 `11px`，辅助文字 `10px`；
- KPI 主数值 `23px`；表头 `9px / 38px`，表格正文 `10px / 43–44px`；
- 数字使用等宽数字对齐，小数位在同一指标内一致；
- 面板和卡片圆角 `10px`，按钮和输入框圆角 `8px`，状态标签使用胶囊圆角；
- 普通面板不得使用粗品牌色顶边或侧边；
- 页面最大内容宽度 `1280px`，桌面多列、移动端单列，宽表格使用内部横向滚动。

### 图表

- 柱状图默认从零开始；若不从零开始，必须明显标注截断基线；
- 折线图不补造缺失点，缺失值使用断点；
- 时间轴按真实顺序排列，不按数值高低排序；
- 排名柱状图按值从高到低或按业务约定排序；
- 图例名称包含业务含义，不使用 `系列1`、`字段A`；
- 图上只标关键值，精确值放在数据表和悬浮提示中；
- 单位必须出现在标题、副标题、轴或图例之一。

## 5. 交互规范

- 每张图提供“查看数据表／返回图表”切换；
- 支持“全部／仅风险”筛选，但筛选后必须说明当前范围；
- 目录和图表切换使用品牌红文字与 `2px` 底部选中线，不使用整块红底；
- 所有按钮、链接、Tab 和可点击图形必须有可见 `focus-visible`；
- 悬浮提示显示对象、期间、数值、单位和状态；
- 图例可切换系列时，不得默认隐藏关键风险系列；
- 支持打印，打印版隐藏操作按钮并保留标题、范围、图例和表格；
- 移动端不依赖悬浮操作，重要信息必须可直接阅读；
- 动效遵循 `prefers-reduced-motion`，不使用持续闪烁或装饰性动画。

## 6. 内容与证据规范

- 图表数值只能来自已成功返回的工具结果或用户已提供且含义明确的数据；
- 待验证数据可以展示，但必须标记状态和限制；
- 数据不足时展示缺失成员、字段、期间或对象，不生成空壳趋势；
- 口径冲突时同时展示冲突双方，不自行选择；
- 相关性图表不得直接写成根因；
- 建议必须回到具体异常对象和证据状态。

## 7. 模板使用规则

使用 `answer-visualization-template.html` 时，只替换文件底部的 `ANSWER_DATA` 配置，不改动渲染器、视觉 Token 和交互逻辑。需要新增图形类型时，应同步更新本规范、渲染函数、数据表回退和打印样式；新增视觉组件前先按 `workbench-ui-style` Skill 选择并读取对应 reference。

`sections` 中可使用：

- `layout: "full"`：主图或需要完整宽度的复杂图表；
- `layout: "half"`：可与另一张辅助图并排的简单图表；
- `collapsed: true`：默认折叠，适用于明细表、补充分析和审计数据。

首屏必须依次包含用户问题、核心结论、关键信号和 KPI，不得先展示大段过程或图表。模板虽然保留柱状图、折线图、堆叠图、热力图、散点图、瀑布图和表格渲染能力，但每次回答只配置本题需要的类型。

正式交付前必须删除或替换模板中的全部演示数据，并检查页面顶部是否仍显示“演示数据”。
