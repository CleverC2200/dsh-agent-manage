# 报告布局与交互契约

用于生成或修改交互报告，不用于强制普通问答的分析顺序。模板为 `../assets/订单满足率分析模板.html`；历史交互示例已移出运行包，模拟数值和状态不能进入真实报告。

## 页面结构

保留用户确认的模板布局与四步主线：口径审计 → 两类缺货结构 → 原因内重点定位 → 全量结论。保留顶部指标、上一步/下一步/重选、口径折叠及问号、视角切换、排序、TopN/全部、行内展开和报告下载等原有能力。四步是导航结构，不要求模型按此顺序取证。

- 需求变化：品类→大区→省区与基地→大区→省区两个视角，品类视角排在基地视角前；六张月度卡片随所选对象切换，字段和范围规则见[报告数据契约](report-contract.md)。
- 已取得基地销售提报时，基地卡及下级大区、省区同时展示初始与纠偏；源空基地单列，销售独有组织保留销售量并说明订单数据缺失。行内展开使用完整基地/品类×大区×省区路径区分，避免同名父对象的所有行一起展开。
- 计划内供给：基地→品类→SKU；四张供给卡保留当前合计，并按自产、调拨、OE、OD顺序展示四个维度行。缺少对应数据时保留“—”，不补零。
- 库存准备用于核查库存与计划是否支撑需求，不是独立缺货原因，也不在计划内缺货模块设置单独Tab。相关事实进入对象证据或全量报告的供给核查说明。公式和参数从现行指标配置取得；不再固定使用历史示例中的“下月需求÷30×11”。期末达标不能证明月初无缺货。
- 总缺货分布留在全量报告，不在两类原因内部新增“非分类量”Tab。
- 第四模块复用问题导向结论组件，章节由本期输入组织，需求、供给及必要的综合判断清晰可达，不固定六段或重复添加分布表。正文解释重要问题，关键记录折叠；长表可筛选、分批展示，下载保留全量，打印当前筛选的全部记录后恢复阅读状态。组件为 `scripts/conclusion-report.js`，视觉样式为 `assets/conclusion-report.css`。
- 可选情景参数存在时才启用第五步 What If；没有参数不加载示例恢复量，模拟不代表实际执行。

## 原因字典与明细

固定位置：**四张供给指标卡 → 原因字典汇总及细分类柱图 → 基地×品类自产计划明细**。打标与计量定义只在报告数据契约维护，此处不重复。

默认展示全部当前范围数据；点击分类联动筛选基地×品类、SKU和原始记录，再次点击或“全部”恢复。月度指标保持完整口径，筛选范围清晰标注。行内只展示当前对象的标签及记录，不重复上方原因图，也不把长明细塞入原因卡。

需求变化行内保留有依据的原因卡及其后的“需求变化明细”：当前对象×大区×省区 → SKU → 可用源记录。源数据只到日期×组织×SKU时如实标注，不冒充订单明细；明细数量不自动归入候选原因。

SKU的“查看源记录”仅作为操作入口；点击后在该SKU下一行跨列展开明细面板，不将子表嵌入操作单元格。面板按可见区域排布，宽表局部滚动；记录按需分页加载，保留关闭和翻页入口，避免撑高汇总行。

## 视觉与组件

以当前模板和 `template-components.js` 为组件基准，不仅复用 CSS 后另造通用表格。供给块保持头部、指标、正文、基地×品类表和行内下钻层级；具体字段数随有效数据契约维护，不将历史“五指标”等描述作为约束。

- 未支持的数值显示“—”，真实 0 正常显示；保留指标卡、渠道行和表头，缺数说明简短明确。
- 字典区沿用报告白底、浅边框、圆角与内容留白；SKU默认中性，仅当前选中项强调，避免全红。
- 标签和数量单位排版清晰；窄屏Tab可横向滚动，条形图不溢出，吸顶区域不互相遮挡。
- 主内容网格使用可收缩轨道（`minmax(0,1fr)`），面板及嵌套网格子项设置 `min-width:0`。宽表的最小宽度只在自身 `report-table-wrap` 内生效，不能撑宽第三模块或页面。窗口收窄时指标卡换行、图表名称及数值保持可见，不能用页面级隐藏溢出掩盖内容。
- 各模块复用同一响应式规则：指标组随可用宽度换列，名称与关键数值可读；图表名称、条形及数值在窄屏重新排布。宽表包装器保留左右边距时使用自动宽度，避免100%宽度叠加外边距。
- 需求与生产的行内下钻按外层表格的**可见滚动区域**确定宽度，而非 `colspan` 单元格/整张宽表宽度；`report-responsive.js` 监听可见区域尺寸，并在重绘时释放旧观察器。下钻内的SKU、源记录表各自局部滚动，标题、指标及关闭入口不随宽表被截断。顶部换行后，结论目录偏移随实际顶部高度同步。
- 对象切换清理旧标题及旧证据；目录状态随当前章节更新。证据对象匹配由数据契约约束。

## 性能与验收

大体量明细按需渲染：不为全部SKU递归预建完整下钻DOM，全量结论延迟至进入对应步骤。可采用缓存、分页或虚拟化等方式，只要保留全量结果及交互语义。

按改动风险验证：数据绑定检查上下级同范围、空值/零值和合计；交互检查对象切换、筛选、排序、展开及返回；视觉修改在实际浏览器覆盖桌面与窄屏（可参考1280、900、375px）。不要求纯文案改动重跑所有视觉场景。缺数与完整路径可用隔离fixture测试，不混入真实报告。记录实际通过和未执行项目，源码或DOM检查不等于视觉验收。


## 已取得数据不得因口径争议隐藏

正式metric保留其语义；口径或覆盖未通过不赋正式值，但必须用sourceMetric显示已取得的源值及source/status/note/unit。sourceViews保存完整查询行、fields、hierarchy、来源、查询时间、状态与限制，通过统一生成器提供筛选、分页、排序、路径下钻和CSV导出。正文与Markdown也须保留全量。缺失、真实零、已取得待核验分别标示；不能把待核验处理成未取到。两类不勾稽时仍显示两类源值和冲突，禁止参与正式归因或情景。只有真实查询维度才能形成下钻；全国SKU与组织分布分开查询时不伪造组织×SKU关联。
