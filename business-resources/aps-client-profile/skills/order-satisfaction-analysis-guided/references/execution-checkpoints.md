# 执行检查点与失败恢复

|阶段|落盘结果|继续条件|失败处理|
|---|---|---|---|
|定义|metric-decision.json、知识库引用、当前元数据|定义与物理实现的差异明确|冲突状态pending；不自动择一|
|查询|完整请求、工具响应、字段及模型上下文|明确每个数据集角色和期间|不能把文件名当数据集身份|
|全量|evidence-contract.json、evidence-check.json|终页、行数、键、合计同时通过|补排序重取，不静默去重|
|事实|事实工作表|数字从证据算出，分母和单位明确|不为完成卡片补值|
|分析|conclusion.sections|机制与反证都有证据边界|缺订单关联时保留生产机制，订单影响NULL|
|报告|HTML、MD、JSON、manifest|事实与显示同义|修模板绑定，不改源事实|

metric-decision.json至少记录definitionStatus（resolved/pending）、正式定义引用、分子分母源成员、来源模型、日期字段、订单池覆盖依据、单位依据、冲突说明。resolved必须附可核验依据，不以“已确认”四字代替。

evidence-gate是独立的机械检查，不代替人工核验定义。原始文件支持 `{params,response:{result:{content:[{text:JSON}]}}}` 标准MCP封装；其他返回需无损适配，不删除fields/modelContext。契约里映射角色与真实数据集名。

若工具返回 partial，检查是缺指标还是未取全：准确率NULL不意味着初始提报无效；分页未取完却意味着不能生成全量合计。两种问题分别记录。

报告叙述模板（只学结构，不复制内容）：
“A基地存在净欠产X；其Y条原文记录跨Z日出现某约束，支持优先核查该机制。X是月度净差，记录正差Q是另一度量，不能相加。缺少订单分配与需货时点，订单损失量暂不确定；下一步核对……。”

不要将基准报告固定的基地、月份、关键词写入通用规则。改变月份和数据后，事实对象、排序及分析路径必须随数据改变。
