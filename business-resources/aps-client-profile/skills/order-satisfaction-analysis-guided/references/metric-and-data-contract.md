# 指标与数据契约

## 1. 口径来源与核验

指标定义由[飞书指标清单](https://klvcodtump.feishu.cn/base/LikDby3IGaWeJUs11EucGA1LnAg?table=tblCesakUfbTtNYG&view=vewtJEea2C)及其关联 Cube 维护。优先按指标编码取得当前版本、公式、单位、维度、阈值和成员映射；本文件中的模型名与复核公式是既有线索，不是另一个固定版本。

- 已核验且范围适用的定义、元数据和查询可以复用，版本或范围变化时刷新。
- 读取指标说明不等于验证实际加工；定义与实现冲突时列出差异、受影响结果和待确认项，仅暂停相应结论。
- 无法读取现行定义时，可使用有来源和版本的快照回答历史问题，并披露时效限制；不要把历史阈值或样例参数说成现行规则。
- 本次报告记录采用的定义/版本、Cube模型、查询时间、业务截止和口径快照。尚未确认的物理字段不要猜成工具成员。
- 跨期对照保留双方期间，不把其他月份写成本期第二来源。知识库完成状态不等于有效答案，错误/输出上限提示不能作为口径证据。

## 2. 范围、单位与聚合

订单满足率回答 OMS 已开订单商品的数量满足情况，不按订单张数衡量准交。全国、基地、品类、组织及SKU层级使用同一指标定义，但分别按自身完整范围查询或聚合。

核心业务数量以件展示；源单位不同需有核验过的换算关系，不能只改单位标签。原辅料可保留原单位作为证据。初始与纠偏销售提报是独立版本，不相互代填。来源缺失为 `null`，真实零值为0。

根据任务和已知风险检查零发货覆盖、重复/拆合单、改废单、退货、超发、日期及版本归属。对比例先按正式规则聚合基础量，快照不跨期累加；不把已聚合数据当作非线性公式所需的源行。

超发情况下，以下候选口径不等价，选择取决于正式定义，不必在无冲突任务中每次并列计算：

```text
净额满足率 = SUM(发货量) / SUM(需求量)
逐行封顶满足率 = 1 - SUM(MAX(需求量 - 发货量, 0)) / SUM(需求量)
```

用户曾说明数据团队拟在底表汇总前过滤“需求量−发货量≥0”。这是待验证的加工变更，不是已完成事实，也不能通过汇总后过滤模拟修复。保留变更前后订单池和版本的可比性。

## 3. 已知数据入口

以下用于定位模型，实际使用以当前元数据及指标关联为准：

| 数据 | 已知表/字段线索 | 使用注意 |
|---|---|---|
| 已开订单 | `scm_dev.dwd_scm_execute_final`；`need_qty_origin`需求、`qtyshipped`发货、`outqty`发布缺货 | 既有来源线索；不可据此跳过当前模型及加工核验 |
| 月度订单计划执行 | `ai_db.agents_scm_order_plan_exe_m` | 用户提供的月度×大区×省区×基地×物料汇总表；不是订单商品底表 |
| 两类缺货 | `demand_change_outqty`、`plan_inner_outqty` | 优先读取查询已开订单缺货量的同一数据集中的正式度量 |
| 组织/品类 | `belong_base`、`region_name`、`province_region_name`、`product_categ_name` | 各模型分别核验支持情况、唯一性及历史映射；展示名不一定是过滤源值 |
| 日生产计划与实绩 | `ai_db.agents_mes_prod_oee_line_result_d`；`deviation_reason` | 优先用于自产取证；日期×基地×工厂×班次×产线×SKU×生产单/批次 |
| 销售提报 | `agents_scm_demand_sales_f` | 销售与基地口径不可混合，版本和成员见第5节 |

订单商品候选键如 `fromorderno + new_material_code` 必须验证，不能预设唯一。基地名称不确定时查候选源值；已核验映射可复用。销售模型是否支持基地应现场检查，不能因历史不支持便一律留空，也不能把另一表的基地字段硬拼进来。

生产计划与实际分别按正式粒度累计；不与库存表同名计划快照相加，产出、入库、质检放行是不同事件。生产模型可用吨数比较规模，但报告业务件数不得未经换算混入吨数。历史候选 `hive.dw.dwd_prod_schedule_detail` 仅在需要补充或对账时核验使用。

日跟进工作簿、会议报告等可辅助定位结构错配；混有全国、组合区域、基地、SKU层级时只选一个不重叠层级汇总。未经同口径核验，不能用其中“SAP发货/月下单”替换正式满足率。

## 4. 两类缺货复核

正式度量存在且版本/范围核验通过时直接使用，不要求同时具备所有底层字段才展示。需要本地复核时，先确认当前定义是否仍采用以下历史规则：

```text
非负缺货量 = MAX(总下单量 - 总发货量, 0)
需求变化缺货量 = MIN(MAX(总下单量 - 最终计划, 0), MAX(总下单量 - 总发货量, 0))
计划内缺货量 = MAX(MIN(总下单量, 最终计划) - 总发货量, 0)
```

复算使用完整、同单位、同期间和计划版本的源行，再汇总勾稽两类之和。不可在月度汇总值上重新套公式。源行缺最终计划时不擅自补算，但不因此抹去已核验的正式分类结果；继续已有供给证据分析。

月度计划偏差的方向、库存准备参数、生产净差或分组正差等均从当前指标定义读取，显示名称与符号一致。生产差额、库存差额不能代替订单分类缺货量。

## 5. 销售提报与准确率

### 已知成员线索

`agents_scm_demand_sales_f` 的销售口径既有筛选为 `source_flag = 销售口径`，月份字段为 `stat_month`。按请求月份取数，不固定某次报告日期。

当前模型已发布基地维度 `belong_base`（源字段 `belong_name`，无基地编码）。按当前元数据核验后，销售提报可直接按基地→大区→省区查询初始、纠偏合计，保持 `source_flag=销售口径`；不能因为历史快照缺基地便继续固定留空。优先以各层正式聚合值绑定，完整分页后核对全国与分组合计、父子合计。源空基地单列保留，不按其他组织或比例分摊；查询未返回路径与返回数值0分别处理。销售全量组织与订单缺货组织采用完整路径对齐，销售独有路径保留销售值，订单缺失不补0。

| 含义 | 既有 Cube 成员 |
|---|---|
| 初始提报 | `plan_qty_initial_total` |
| 纠偏提报 | `plan_qty_adjusted_total` |
| 实际下单 | `order_qty_origin_total` |
| 实际发货 | `act_dl_qty_total` |
| 初始/纠偏/月度准确率 | `forecast_accuracy_initial` / `forecast_accuracy_adjusted` / `forecast_accuracy_monthly` |

准确率是非加性指标，不跨月累加或平均SKU百分比。既有 Cube 返回0–1编码，报告 `accuracy` 使用0–100；核对当前编码，在绑定层只转换一次。

准确率空值须区别“尚未查询/绑定”和“正式返回NULL”。查询到NULL时结合必要基础量及分母说明原因；某组织的提报为0不代表准确率应为0。销售模型源下单量缺失时，不借用已开订单模型的下单量拼算。已有正式结果的组织独立展示，不因父级返回NULL而清空子级。

用户明确指定“纠偏提报－已开订单需求”作为本次月度计划偏差时，可显式启用报告契约的对照模式，保留符号和范围说明；提报全量与下级缺货订单子集的差额不作为完整组织偏差或准确率。

### 直接查询与必要回退

优先按当前展示范围查询正式准确率。销售数据原生品类为空时，可取得完整组织×SKU数据，经已核验的SKU→品类映射汇总；有有效原生维度或其他正式映射时无需强制走此回退。无法确定映射的记录保留并说明，不按名称或比例猜分配。

本地复算仅在取得正式公式需要的源粒度或充分聚合量时进行。既有复核公式如下，使用前对照当前版本：

```text
单行偏差 = IF(下单 > 计划, 发货 - 计划, MAX(下单, 发货) - 计划)
单版本准确率 = 1 - SUM(ABS(单行偏差)) / SUM(计划)
月度准确率 = 初版准确率 × 50% + 纠偏准确率 × 50%
```

不能用“发货÷提报”、汇总净差绝对值、SKU百分比平均或缺货量反推替代。负值、零分母和空值遵循源规则，不擅自截断、补零或丢行；规则不明时保留缺失原因，不能以能算出数为准。

组织×SKU查询若已预聚合，`record_count = 1` 可帮助验证源粒度，但还需核对唯一键和基础量语义；它不是单独的充分证明。若分组包含多行且没有正式偏差绝对值汇总等充分量，则不能用组内净额复算。可进一步查询更细粒度或使用Cube正式聚合，不限于一种方案。

### 完整性与绑定核验

- 根据工具实际分页机制取全数据，核对终止标记/行数和同范围合计，不以固定字段名作为唯一分页方案。
- 初始、纠偏、准确率及偏差量在品类/基地→大区→省区各层按适用范围绑定；不只填根节点，不复制父级值。准确率在各层按正式规则重算或查询。
- 记录未映射、歧义、缺失及预聚合影响；对受影响范围留空或标冲突，其他完整范围可继续。
- 抽查代表性对象与正式度量或源行复核一致；生成报告时检查切换、排序和展开后仍绑定当前对象。

## 6. 取证数据的选择

按机制选取最小必要记录，不要求每次拉齐所有系统：

- 订单与发货：商品键、需求/发货量、业务日期、版本及状态。
- 供需关联：分配量、供给实体、可用/承诺时间、占用与优先级。
- 库存：相关时点、仓库×SKU×批次的可用、冻结及占用。
- 生产/物料/外协：相关单据、计划与实绩、理由、承诺/收货/放行事件。
- 调拨/仓配：调出、在途、接收、上架或发运节点。
- 加工对账：只补与当前差异有关的过滤、粒度、血缘和覆盖证据。



## 未核验单位的报告兼容规则

业务目标单位为件，但元数据未声明单位时禁止改标签或换算。scope.unit/productionUnit可填写“源数量单位（待核验）”，对应unitStatus/productionUnitStatus填unverified；树中明细须同声明。销售件数使用metric.units和自身元数据。正式订单指标来源/定义未核验时保持NULL，候选原值只放审计与candidateOrderMetric。此规则补充旧模板只支持件的限制，不赋予未知单位可比性。
