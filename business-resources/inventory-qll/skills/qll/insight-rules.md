# chain-insight-card 规则（权威版）

> **权威声明**：本文件是 AI 洞察卡的**唯一格式正文**，看板洞察区与会话问答共用。`chain-inventory-policy/rules/output-guide.md` 档 3 只保留指针，不再重复定义格式。

## 1. 洞察区定位

| 项 | 规定 |
|---|---|
| 是什么 | 自动生成的**经营分析卡**，不是 KPI 播报卡 |
| 只输出 | 当前数据**实际触发**的经营矛盾 |
| 不输出 | 未触发的分析项、动作指令、补货/调拨/生产任务、事件、待办 |
| 阈值来源 | 分层大日期阈值见 Skill `chain-inventory-policy` 的 `rules/data-boundary.md` 第三节 |
| 格式正文 | 本文件第 3、4 节 |

## 2. 口径规则：一套洞察，不分含不含渠道

| 项 | 规定 |
|---|---|
| 洞察份数 | **只有一套洞察**，不按含渠道 / 不含渠道写两套结论，也不因开关切换改写判断框架 |
| 主值口径 | 跟随页面开关：不含渠道 → 主值为**公司体系库存**（基地 + 分仓）；含渠道 → 主值为**全链观测库存**（基地 + 分仓 + 可参考渠道库存）。洞察必须用一句话点明本次主值口径 |
| 渠道信号 | **恒定纳入判断**，与开关无关：渠道库存高低、覆盖率、数据日期、大区 / 省区集中度都是判断证据，开关关闭时也要看 |
| 渠道与主值 | 渠道数据**不计入主值**，不参与主值的分子与分母；出现的渠道数字一律标注「渠道观测，未计入主值」 |
| 渠道不可用 | 只写一句边界（如「客户库存覆盖不足，渠道仅作信号」）；不用 0 补齐，不因开关关闭就装作渠道不存在 |
| 禁止 | 把渠道并入公司体系口径；用渠道数据反推或改写主值；按开关切换写两套结论 |

写法示例（同一份洞察框架，只换主值口径）：

- 开关=不含渠道，但渠道库存高、动销弱 → 主值报公司体系口径，判断写「公司体系库存低于目标 X 万件，但渠道库存偏高、动销偏弱，存在渠道消化压力，真实缺货待渠道验证」。
- 开关=含渠道 → 主值报全链观测口径，判断写「全链观测库存高于目标，超出部分主要来自渠道层」。

## 3. 六段式：必须回答的问题、输出规则与触发条件

只输出**当前数据实际触发**的段落，核心判断恒定输出。

| 段落 | 必须回答的问题 | 输出规则 | 触发条件 |
|---|---|---|---|
| 核心判断 | 当前最主要的全链矛盾是什么 | 一句话说明总量不足、位置错配、品类结构错配、真实缺货、渠道压货、补货节奏风险或大日期风险；必须包含主要「大区 × 品类」和 2–3 个关键数量；必须点明主值口径 | 恒定 |
| 链路关系 | 基地、分仓、渠道和订单之间是什么关系 | 说明公司体系库存、渠道观测库存、订单缺口、订单满足率、动销之间的因果关系 | 存在跨层因果可述时 |
| 大区 × 品类 | 问题集中在哪些经营对象 | 点出前 3 个影响最大的「大区 × 品类」，每个对象给出问题类型 | 存在可排序的风险对象时 |
| SKU 信号 | SKU 层是否同向短缺或错配 | 区分全链真实缺货 SKU、基地缺货但渠道不缺货 SKU、基地 / 分仓高库存但渠道低库存 SKU | 有 SKU 级明细时 |
| 货龄风险 | 是否存在同品类跨层大日期压力 | 说明基地、分仓、客户层是否集中在同一品类或 SKU，并标明各自阈值 | 仅触发时输出 |
| 数据边界 | 当前结论有哪些口径限制 | 说明客户库存覆盖度、快照时间、缺失明细；无明显问题可省略 | 存在覆盖不足或缺失时 |

## 4. 格式硬约束

- **200–280 字**；含 **4–8 个**关键数量 / 比例 / 天数。
- 必须落到「大区 × 品类」；有明细时落到 SKU。
- **必须点明主值口径**（公司体系库存 / 全链观测库存），并按第 2 节标注渠道数字。
- **禁用「建议」「下一步」「请处理」等行动性语言**。
- 数据不足时写「当前只能判断现象，不能确认具体 SKU 原因」。
- 不出现表名、字段名、SQL、工具名、变量名。

### 4.1 合格示例（约 230 字，数字仅示意）

> 含渠道口径下，全链观测库存 268.4 万件，较目标高 18.9%，但订单缺口仍有 9.8 万件，属「总量偏高、结构错配」。缺口集中在华中面点与华南水饺，合计占缺口 61%；同期华东汤圆高于目标且动销偏弱，压力主要来自渠道层——客户库存覆盖 76%、数据日期 T-2，渠道消化天数约 20.7 天。SKU 层两端分化：全链真实缺货 42 个、基地缺货但渠道可覆盖 27 个，其余基地与分仓库存基本正常，错配主要在渠道与品类之间。91 天及以上大日期 4.1 万件，集中在华中面点。渠道动销数据缺失，回顾周转按公司体系口径计算。

对照检查：点明了主值口径（含渠道）；有判断（总量偏高、结构错配）不是播报；落到「大区 × 品类」并给问题类型；SKU 层区分三种信号；只写触发段落；数字 8 个；无行动性语言。

### 4.2 不合格示例（常见错法）

> 公司体系库存 268.4 万件，目标 225.8 万件，库存差额 42.6 万件；回顾周转 12.3 天；平均货龄 41.5 天；订单满足率 94.9%；当前订单缺口 9.8 万件；91 天以上库存 4.1 万件。基地库存 96.2 万件，分仓库存 172.2 万件，渠道库存 18.6 万件。建议优先处理华中面点缺口，暂停华东汤圆补货，并请销售确认渠道库存。

错在六处：① 逐项播报 KPI，没有核心判断；② 未点明主值口径；③ 未落到「大区 × 品类」的问题类型；④ 出现「建议 / 暂停 / 请」等行动性语言；⑤ 补齐了未触发段落（满足率、基地与分仓拆分并非本次矛盾）；⑥ 数字超过 8 个。

## 5. 只写触发段落

1. 未触发的段落一律不写，不用「无异常」「暂无」占位，不为完整而补齐。
2. 触发段落之间无固定顺序，但核心判断始终在最前。
3. 若仅核心判断与数据边界触发，可只输出这两段，仍优先保证信息密度。

## 6. 语言禁区

| 禁止出现 | 原因 |
|---|---|
| 「建议」「下一步」「请处理」「应当」「需要立即」 | 属动作指令，洞察区不输出 |
| 「我已为你创建…」「已通知…」 | 无写入能力 |
| 「客户库存高，所以不缺货」 | 客户库存覆盖与时效不稳定 |
| 「没有 SKU 明细也能判断具体 SKU 原因」 | 证据不足 |
| 表格、字段名、表名、SQL、工具名 | 违反语言约束 |

## 7. 数据缺失与降级

缺失与降级统一按 Skill `chain-inventory-policy` 的 `rules/data-boundary.md` 第四节执行；洞察卡必须写出的声明句：

| 情况 | 必须写入的句子 |
|---|---|
| 无 SKU / 订单 / 批次明细 | 「当前只能判断现象，不能确认具体 SKU 原因」 |
| 客户库存覆盖率低于阈值 | 「客户库存为渠道信号，覆盖不完整，不替代正式库存结论」 |
| 渠道数据未接入或全部不可参考 | 「渠道库存当前不可观测，判断仅覆盖公司体系口径」 |

## 8. 与链路判断的关系

洞察卡不自行发明判断，判断结果来自 `chain-inventory-judgment`；洞察卡只负责：选出影响面最大的一个矛盾作为核心判断、组织成六段式、遵守第 3、4 节的格式与语言约束。
