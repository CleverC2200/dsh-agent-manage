# 米面冻品产销协同卡点360°诊断分析

## 任务目标

贯通计划、报货、库存、生产、物流，以“需求能否按期足量交付、供给能否在可售窗口内消化”为主线，识别单环节异常与跨环节交接卡点。回答：卡在哪里、为什么、影响哪些订单和库存、何时必须处理、怎么解决、如何验证有效。

兼顾订单保障、效期、质量、仓容与成本，形成“事实核验—卡点定位—方案比较—人工决策—执行反馈”闭环；既处理当前异常，也识别反复发生的机制问题。

## 所需知识、数据

仅调用当前运行时已注册且获授权的数据、规则和模型工具，不猜测工具、字段或技能名称。

| 类别 | 必需内容 |
|---|---|
| 计划 | 销售预测、销售/需求计划、月周日分解、版本及审批记录、促销与节庆安排、历史报货/订单/发货；终端动销和渠道库存按可得性补充。区分经营目标、预测与已批准计划。 |
| 报货与订单 | 客户—SKU原始报货、期望到货日、提交与审核时间、拒绝/削减/取消记录；正式订单行、交付计划行、数量、首次及修订承诺、信用/付款冻结、改单原因与供给分配。 |
| 库存 | 基地/分仓/客户的SKU—批次库存、生产/到期日期、质量状态、冻结与预留、成本、历史出入库、调拨及在途、有效仓容；客户库存仅在授权和数据可得时使用。 |
| 生产 | 生产计划、工单、排产及变更、物料齐套、产线/速冻等瓶颈工序能力、班次、最小批量、换线清洗、实际产出、异常停机、质检放行时间。 |
| 物流 | 配货、拣货、预约、派车、装车、出库、运输、到货、合格签收、拒收/退货及对应时间；冷链运力、线路/客户收货日历、温控异常、运输费用。 |
| 规则 | 指标口径及目标、计划冻结窗、报货节奏、客户优先级、库存上下限、大日期/临期标准、客户收货最低剩余保质期、供给分配与预测冲减、调拨/替代限制、审批权限及异常响应时限。 |

## 输入内容

分析范围、诊断时点、回溯与预测周期、关注指标和重点问题。优先从上下文及主数据补全；缺少会改变结论的关键条件时集中澄清，其余缺数不阻断可验证部分。

未指定时，采用授权范围、最新可对齐快照、近90天历史和未来13周；未来前14天按日、后续按周分析，紧急交接下钻到小时，效期问题延伸至相关批次可售窗口结束。上述为分析默认值，不是企业风险阈值；披露实际覆盖范围和数据时间。

## 工作步骤

### 1. 统一指标，保留原始需求与承诺

先读取企业有效口径，明确统计粒度、应交订单队列、交付节点、时间容差、部分交付、取消和退货处理规则。准时、足量和同时准时足量分别评价，不混为同一指标。[1]

| 指标 | 计算与判断要求 |
|---|---|
| 订单准交率 | 按企业规则计算“准时的应交订单或订单行÷同期应交订单或订单行”。客户原始要求日、首次承诺日、修订承诺日分别评价；发运与签收分开，部分交付判准规则不明时不自行计算。 |
| 按期数量满足率 | 对同一应交队列，按行计算“截至基准交期的合格交付量与有效需求量取较小值”，汇总后除以有效需求总量；不能用超交抵销其他行欠交。按金额或订单行计的满足率另列。 |
| 足量准时交付率 | 同时满足数量和时间条件的应交订单或订单行占比；先按规定粒度逐项判断，不能用准交率乘满足率替代。 |
| 缺货 | 在指定地点、SKU、需求时点及客户接收条件下无法匹配有效供给的数量和订单；区分实际履约缺口与低于安全库存。 |
| 大日期与积压 | 按企业货龄阈值识别现有风险，按客户可售窗口与可匹配需求推演未来残量；大日期、临期、过期分列，库存成本暴露不等于实际损失。 |
| 协同过程 | 按规则检查计划偏差、报货节奏偏差、审核滞留、承诺后移、排产变更、生产/放行延误、待装车、运输与签收延误。 |

历史履约按基准应交日期选取截至诊断时点已到期的队列，纳入队列内逾期未完成订单，不能只统计已交付订单；未来应交单单列预测。不同日期基准的对照保留同一订单集合，不借改期移出原队列。数量跨SKU汇总须使用可比单位，分母为零不计算；规则缺失时给出待确认口径，不冒充正式KPI。

保留“原始报货→审核通过/拒绝/削减/取消→正式订单→发运→合格签收”的需求转化记录。正式KPI遵循批准口径，同时披露原始需求未满足量及原因；因缺货削单、拒单、改期不能静默抹去。信用拦截等未成单需求单列，不擅自并入正式订单分母。

### 2. 重建订单与供给的可追溯链路

以原始需求ID、订单行/交付计划行连接计划版本、库存分配、批次、生产工单、调拨、出库、运单及签收；现货单不强行关联生产工单。数量映射与事件时间同时保留，无明确关联只能标记推测，不能仅凭SKU和日期认定上下游关系。

校验快照、单位、重复、缺失、状态冲突及一对多关联膨胀；订单拆分、多次出库、多次签收回归原始粒度。同一实物数量从在制转入库存、从库存转为在途时不得重复累计；冻结与预留避免重复扣减。复盘使用当时可见的计划、规则和承诺版本，缺少历史版本须说明局限。

先查询全范围汇总定位异常，再下钻订单、客户、SKU、批次和事件。全量检查采用聚合或分页，不以样本替代整体；数据断点单列，不直接认定业务未执行。

### 3. 完成全环节与交接卡点扫描

每项输出“正常/预警/严重/无法判断”及依据。下列现象是检查方向，不是预设结论；无企业分级规则时使用说明依据的分析优先级。

| 观察面 | 典型卡点信号 | 重点核验 |
|---|---|---|
| 计划 | 漏报关键SKU、持续高估/低估、版本不一致、节庆备货与实际窗口错位 | 区分总量、结构、节奏偏差；区分需求下降与缺货压低发货，不能用受限发货直接代表真实需求。 |
| 报货 | 集中报货、临时报货、超计划报货、重复报货、报货不转订单、审批滞留 | 对照原始需求、提交/审核时点、交期要求、削减原因与信用状态，识别需求未进入正式订单的隐性卡点。 |
| 库存 | 有库存却不能发、缺货与积压并存、旧批次未消化而持续入新货、局部爆仓 | 按地点、批次、客户、质量和时间匹配；核查预留、客户效期、调拨可达性与真实仓容。 |
| 生产 | 缺货SKU未及时生产、积压SKU继续生产、频繁插单、完工/放行延误 | 核查物料、瓶颈工序、班次、换线、最小批量、工单优先级及质检等待，区分计划不可行与执行偏离。 |
| 物流 | 有货无车、有车无货、等拼车错过交期、准时出库却晚到、拒收退货 | 拆分配货、预约、派车、装车、运输和收货等待；核查运力、温区、效期、客户窗口及异常反馈。 |
| 计划↔报货 | 月度总量吻合，但周/日集中报货击穿库存与产能 | 比较计划分解与实际报货节奏，检查提前期、峰值和版本变更，不能直接归因为预测总量不准。 |
| 订单↔供给 | 承诺早于可行到货日、库存或产能重复承诺、优先订单挤占其他承诺 | 追溯承诺时点的可用资源与分配规则；区分客户要求不现实、承诺不合理和承诺后供给变化。 |
| 生产↔仓运 | 完工不等于可发运、集中入库超仓容、放行时间赶不上班车/收货窗口 | 串联完工、质检、入库、拣装、运输及预约日历，识别上游准时但下游无法接续的情况。 |
| 异常↔决策 | 同类问题反复发生、信息回传慢、无人牵头、方案久未审批或执行 | 检查首次发现、反馈、决策、执行与验证时间，以及冻结窗和例外处理记录；不凭岗位名称认定责任。 |

### 4. 联动推演订单、供给、效期和仓容

需求侧按企业冲减规则合并预测、报货和订单，同一需求在不同阶段不重复计量；规则缺失时分开测算情景，不能直接相加。

供给侧区分现货、已确认在途、可按时放行的生产供给与未确认计划。调用可信计算/模型工具按物料、有限产能、瓶颈工序、运输及工作日历推算数量和可达日期；无相应工具或数据时仅给条件分析，不编造精确可交日。

按客户—SKU—地点—日期—批次分配供给，遵循有效订单绑定和企业优先级，一份供给只能承诺一次。由客户最低剩余保质期、运输和企业缓冲倒推最后可发运日，在满足客户条件的批次中按先到期先出分配需求；账面有货不等于可履约，未过期不等于客户可接收。

输出不采取新增动作的基线：预计缺货首日、缺口与受影响订单，无法按期交付的对象，跨越大日期阈值及可售窗口后的残量，分温区仓容峰值和发生时间。跨基地调拨校验调出承诺、调入需求及到达时效；不能用月末总量平衡代替期间逐日可行。

### 5. 从异常追到可验证卡点

对延期/欠交订单逆向追溯“签收←运输←装车←可用批次←放行/生产←物料/排产←需求与承诺”；对大日期库存反向追溯“剩余批次←未消化需求←生产/调入来源←计划、报货及变更”。对候选原因再向下游验证影响范围。

逐段对照计划、实际时间与交接条件，区分等待时间、作业时间和返工；依据依赖关系识别限制最终交付的关键路径，不把并行环节延误直接相加，也不将最早异常或最长等待自动当作根因。

每个卡点形成“异常事实→约束/交接失效→影响传导→证据→待验证项”。标明已验证原因、候选原因或数据问题。可调用模型做反事实测算：解除该约束后，交期、缺口或风险残量是否改善，是否被下一约束限制；情景改善不冒充因果证明。

按影响程度、发生时间、剩余处置窗口及证据充分性排序。食品安全与质量疑点优先提交质量复核；不自创概率、行业阈值或综合分。同一订单/批次的多重风险建立关联并去重，不重复累加受影响数量、损失或改善贡献；未交订单金额、库存成本暴露与实际损失分别列示。

### 6. 形成应急处置与机制修正方案

对重点卡点比较“不处理基线”与可行候选方案；存在明显取舍时给出备选及选择条件，没有可行方案则明确升级决策，不强行推荐。

| 层次 | 可评估的措施 |
|---|---|
| 当前订单与风险处置 | 调拨/配货重分配、合规旧批次优先出库、补产或调整顺序、协同解决物料/质检/运力卡点、拆单分批、经客户确认的替代或交期协商；积压品评估减产/缓产与真实需求匹配。 |
| 周度供需修正 | 重排报货节奏与资源分配、调整周生产/调拨计划、复核安全库存及批次策略、协调仓运窗口，处理影响多订单的重复卡点。 |
| 月度机制改善 | 修订需求共识、计划分解与冻结、促销备货、订单承诺校验、跨部门交接时限和异常升级机制；明确建议变更与审批主体。 |

校验客户接收、物料、产能、换线、最小批量、库存归属、温区、运力及仓库/运输/客户日历；异地有货必须验证能否及时送达，不能只按数量推荐调拨。

每项方案列出对象、数量、动作顺序、牵头/协同角色、审批与客户确认要求、最迟行动日、预期效果、增量费用、代价及执行前提。最迟行动日按风险时点和必要提前期倒推，计入可并行关系与工作日历，不能直接取风险发生日。

对组合方案统一复算：能保障哪些订单、是否挤占其他承诺、是否增加大日期/爆仓风险及费用；同一库存、产能、车辆不能被多个方案重复占用。不得以提前压货给客户转移库存风险，也不得仅靠改交期、削单、释放质量冻结美化指标。收益未知时写待测算，不声称最优。

### 7. 定义验证与闭环

为建议指定验收指标、目标或判断条件、复查时间和升级条件，区分“待确认—已审批—执行中—已完成—效果已验证”。没有执行记录不能写已完成，没有后续业务数据不能写风险已消除。

复查沿用同一订单队列与原始基线，并展示新增需求和范围变化；检验准交、满足率、缺口、风险库存及增量费用，不能把业务量变化误当改善。无任务调度能力时只输出复查安排，不声称已经持续监控。

## 输出规范

按“结论→全链诊断→卡点与行动→方案比较→证据缺口”输出，重点展开异常，不复述全部取数过程。

**结论摘要：**说明分析范围、数据时点及覆盖率，覆盖分母未知时仅报告可见范围；用3—5条结论回答当前最大卡点、紧迫风险和优先决策；事实、预测和候选原因分开。

**全链诊断表：**观察面、状态、核心指标/比较基准、关键卡点、证据编号；所有观察面均覆盖，不能评估的写明原因。

**卡点—行动卡：**每项包含卡点ID、环节/交接点、订单/客户/SKU/批次等对象、异常与原因验证状态、影响数量/金额/时间、优先级、行动及数量、牵头/协同角色、最迟行动日、审批前提、预期效果、复查指标及升级条件。多对象可关联明细，不强塞进一张超宽表；未知字段明确标记，不填虚构值。

**方案比较：**同一基线下展示候选及组合方案对履约、效期、仓容、成本的净影响与取舍，区分应急措施、周度调整和月度机制建议。全部严重风险必须列出，其他明细按需展开。

**证据与缺口：**证据编号对应数据源/工具结果、查询及快照时间、过滤范围、指标/规则/计划版本；列明缺数对哪些判断有影响、需要补什么和建议由谁提供。

## 异常与约束

工具失败、权限不足、空结果或数据延迟如实说明；不绕过权限，不把无数据当作无需求、无库存或无风险。仅有出库数据时只评价发运，不能声称客户准时签收；没有渠道动销数据不能认定终端滞销，缺少温控/质检证据不能认定质量正常。

本技能负责诊断和建议，不自行修改计划、安全库存、订单数量/交期、生产工单、库存状态或运输指令。执行须另行获得授权、审批与必要的客户确认；不得建议交付过期、未放行或未经质量确认的异常产品。“加强协同、优化计划、加快发货”不能单独作为解决方案。
