# 订单履约销售确认自动化 Skill

## 具体内容

### 1、适用边界

- **做**：由有权限人员手动发起一次订单销售确认流程；计算当前订单版本是否满足；向指定飞书群发送结构化确认卡片；未确认时每小时提醒；在授权确认后更新 OMS 和下发 WMS/TMS。
- **不做**：监听新订单、库存变化或排产变化后自动发起确认；销售未确认时自动修改订单或自动下发；根据自然语言“好的”执行订单变更；自行确认替代商品、价格、交期或下发权限。
- 每次执行以 `订单号 + 订单版本号 + 流程类型` 建立唯一流程实例；订单版本变化后，旧实例及其确认结果失效。
- 本 Skill 是受控执行流程。飞书消息、OMS 更新、WMS/TMS 下发均是外部写操作，必须分别满足对应授权与确认条件。

### 2、输入（触发范围）

- 授权用户明确发起：“向销售确认订单 XXXX”“发起订单满足确认”“请求销售确认替代商品”。
- 订单号或可唯一定位订单的业务标识；必要时包含指定销售群、销售组织或确认人。
- 缺货场景可由用户指定待确认的替代 SKU 和数量，也可由系统读取已配置且有效的替代商品规则。

不用于：页面演示数据、未能唯一定位的订单、没有授权的飞书群、没有配置确认人的订单，或要求绕过销售确认直接下发的请求。

### 3、工作步骤

1. **人工发起与权限校验**：核验触发人具有该订单/销售组织的发起权限，并记录触发人、触发时间、订单号和当前订单版本。未收到明确人工触发不得启动流程。
2. **读取当前订单快照**：从 OMS 获取订单头、订单行、状态、版本、客户、销售组织、基地、需求量、已满足量、缺货量及订单有效性；确认订单未取消、未作废且未处于已下发终态。
3. **核算满足情况**：调用 `order-fulfillment-risk` 和 `sku-inventory-shortage`；如需供应判断，再调用 `production-fulfillment-progress`。结果必须基于同一订单版本和数据快照。
4. **分支处理**：
   - **订单满足**：生成“确认下发”飞书卡片，展示订单号、版本、客户、SKU 明细、订货数量、可满足量、缺货量、订单满足率、基地、数据时间；销售可选择“确认下发”或“暂不下发”。
   - **订单缺货**：生成“确认替代商品”飞书卡片，展示缺货 SKU、原数量、可满足量、缺货量、订单满足率和可用替代 SKU；销售必须结构化确认替代商品名称/SKU、数量，以及规则要求的包装单位、价格或交期变更。
5. **飞书确认与每小时提醒**：卡片发送成功后写入 `待销售确认` 状态与首次发送时间。若流程仍待确认，每经过 1 小时发送一次提醒；提醒携带相同流程实例、订单版本和确认入口。每次提醒前重新读取订单版本和流程状态。
6. **销售确认校验**：只接受卡片按钮或表单字段形成的结构化回调。校验确认人权限、流程实例、订单版本、卡片有效期、确认动作和必填字段；不接受普通群聊文本作为执行指令。
7. **缺货订单变更**：销售确认替代商品后，校验替代规则、SKU 有效性、数量/单位、价格/交期权限及替代后供应。通过后调用 OMS 更新订单，保存变更前后订单行、确认人和确认时间；OMS 成功回写后重新从步骤 2 核算。
8. **下发 WMS/TMS**：仅对当前版本满足业务规则、且销售点击“确认下发”的订单执行。先按已确认集成顺序下发 WMS，再下发 TMS；每次请求使用幂等键 `订单号 + 订单版本号 + 目标系统`。写回下发结果、执行单号/运单号、时间和失败原因。
9. **闭环与审计**：流程在“已下发”“销售暂不下发”“替代未通过”“订单版本已变化”“订单取消/作废”或“人工终止”时关闭，并保留完整审计链路。

### 4、异常处理

- **订单版本变化**：立即停止旧流程及提醒，标记“订单已变更需重新发起”；不得沿用旧卡片确认或继续下发。
- **销售未确认**：每小时最多提醒一次，直到确认、拒绝、订单失效、人工终止或达到已配置的流程失效时间；不得因超时自动确认或自动下发。
- **飞书发送失败/群映射缺失**：不进入待确认状态；记录失败原因并提示发起人补充群或确认人映射。有限重试按集成策略执行，不能造成重复群消息。
- **销售拒绝或暂不下发**：停止提醒和下发，记录原因；只有授权人员重新手动触发，才可创建新流程实例。
- **替代商品校验失败**：不更新 OMS；向销售返回具体失败项，例如替代关系不存在、单位不一致、数量超限、价格/交期未确认或供应不足。
- **OMS 更新失败**：不进入下发阶段；保留原订单版本，记录接口请求标识和错误信息，转人工处理。
- **WMS/TMS 下发失败**：不重复盲目下发；先按幂等键查询目标系统处理结果。WMS 成功、TMS 失败时标记“下发异常待处理”，只补偿失败系统并保留已成功结果。
- **数据不足或演示数据**：不能发起真实飞书确认、OMS 更新或 WMS/TMS 下发；明确提示需接入真实订单、库存、权限和接口数据。

### 5、输出规范及安全约束

- 每次卡片、提醒和接口调用必须展示或记录：订单号、订单版本、流程实例 ID、数据时间、发起人/确认人、当前状态和操作时间。
- 飞书卡片中的订单明细至少包括 SKU 名称/编码、订货数量、可满足数量、缺货数量及订单满足率；数量须标明单位。
- 订单满足率、缺货量和替代后结果必须按已确认口径计算，不得使用页面演示数据作为真实执行依据。
- 销售确认只授予本订单版本的一次对应动作权限。确认下发不等同于确认替代商品；两类动作必须独立校验。
- OMS、WMS、TMS 调用前需再次校验订单状态与版本，防止并发修改后向旧版本下发。
- 不展示或写入超过当前用户和群成员授权范围的客户、价格、人员或订单信息；敏感字段按权限脱敏。
- 所有外部写操作必须可审计、可查询、可追踪；撤销/补偿须使用业务系统正式接口，不能通过修改审计记录实现。

### 7、业务字段、公式、案例

#### 核心字段

`order_id`、`order_version`、`order_status`、`sales_org`、`customer_id`、`base_id`、`sku_id`、`ordered_qty`、`allocatable_qty`、`shortage_qty`、`fulfillment_rate`、`replacement_sku_id`、`replacement_qty`、`feishu_chat_id`、`confirmer_id`、`flow_instance_id`、`confirmation_status`、`first_sent_at`、`next_remind_at`、`reminder_count`、`wms_request_id`、`tms_request_id`、`idempotency_key`。

#### 核心口径

- 订单满足率 = `min(实际/确认可满足量 ÷ 订单需求量, 100%)`；实际使用“发货量”还是“按规则确认可满足量”必须在卡片中注明。
- 缺货量 = `max(订单需求量 − 按已确认分配规则的有效供应量, 0)`。
- 待确认提醒条件 = `confirmation_status = 待销售确认` 且 `当前时间 >= next_remind_at` 且订单版本未变化。
- 下一次提醒时间 = `上一次成功发送时间 + 1 小时`；每个流程实例在任意 1 小时窗口内最多成功发送 1 次。
- 幂等键 = `订单号:订单版本:目标动作:目标系统`，例如 `SO-10001:V3:dispatch:WMS`。

#### 示例

订单 `SO-10001` 的 V3 版本由履约专员手动发起确认，计算满足率 100%。系统在销售群发送确认下发卡片；销售 1 小时未确认，则发送第 1 次提醒。销售点击“确认下发”后，系统再次读取 V3，确认版本仍有效，先下发 WMS；获得 WMS 执行单号后再下发 TMS。若下发前订单变为 V4，V3 卡片失效，流程停止，须对 V4 重新人工发起。

### 8、输出样式

#### 满足订单确认卡片

标题：`待销售确认下发｜订单 {order_id}`  
内容：客户、订单版本、基地、SKU 明细、订货数量、可满足数量、缺货数量、订单满足率、数据时间。  
操作：`确认下发`、`暂不下发`、`查看明细`。

#### 缺货订单确认卡片

标题：`待确认替代商品｜订单 {order_id}`  
内容：缺货 SKU、原订货数量、可满足数量、缺货数量、订单满足率、允许替代项。  
操作：填写/选择替代 SKU 与数量后点击 `确认修改订单`，或点击 `转人工处理`。

#### 提醒消息

`订单 {order_id}（{order_version}）仍待销售确认；本次为第 {reminder_count} 次提醒。请通过卡片确认或暂不下发。`

#### 执行结果

`订单 {order_id} 已下发` 或 `订单 {order_id} 下发异常待处理`，并列出 OMS/WMS/TMS 各阶段状态、单号、失败环节和下一步处理人。

## 当前安装能力边界

本 Skill 由订单工作台与订单履约 Agent 共用，技能描述不授予查询、人员范围或业务写入权限。只能使用当前 Agent 已安装、已授权的页面证据和工具；用户角色描述不代表实际授权。

订单履约只使用 order01 的当前用户受控只读能力，缺失指标和接口保持未知。订单工作台沿用其当前已发布能力；页面处于 mock 时，只分析明确标记的报告摘录、演示数据或用户提供的证据，不宣称已接入实时订单系统。

销售确认、每小时提醒、飞书消息、OMS 更新、WMS/TMS 下发及外部改善任务尚无本次新增的写入或调度接口。可以解释流程、分析证据和生成草案，不能因加载 Skill 就启动执行或声称已完成。实际操作仍需相应工具、有效权限和明确授权。
