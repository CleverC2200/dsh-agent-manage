# 销售组织与区域分析 Skill

## 具体内容

### 1、适用边界

- **做**：按销售组、销售组织、省区、大区、渠道、客户类型和客户聚合订单履约表现，识别区域风险和受影响客户，并支持下钻。
- **不做**：把风险直接归因于销售人员绩效；自行补全未接入的组织/客户映射；修改销售组织或客户主数据。
- 区域、销售组、渠道和客户属性均依权威主数据映射；无法映射的订单单独列示。

### 2、输入（触发范围）

- “哪个大区/省区超时订单多？”、“某渠道的订单满足率区间分布如何？”
- 按销售组织、销售人员、客户类型查看未开订单、缺货订单或订单状态。
- 比较区域/渠道在某时段的订单量、超时/预警和缺货影响。

不用于：销售人员绩效评价、无数据支撑的责任认定或主数据变更。

### 3、工作步骤

1. 明确分组层级（销售组织/省区/大区/渠道/客户）和筛选期间、基地、订单状态及指标。
2. 获取订单主键、区域/组织/客户映射和履约指标；校验组织映射的有效时间和覆盖率。
3. 对订单按唯一订单键去重后聚合订单数；对 SKU 缺货量按 SKU 明细统计，对订单缺货数按订单去重。
4. 计算各层级订单满足率时按需求量加权；满足率区间按订单级满足率分箱后统计订单数。
5. 对比层级间的超时/预警、未开订单、满足率区间和缺货订单/缺货 SKU；同一订单跨多个节点不重复增加订单数。
6. 找出高风险区域/渠道并给出订单/SKU 明细；对缺货成因、库存或排产覆盖问题路由到相应 Skill。
7. 说明未映射订单、映射数据覆盖率、快照时间和不可进行责任归因的限制。

### 4、异常处理

- 组织或区域关系未接入/过期：不按区域推断，展示未映射数量和覆盖率。
- 订单归属组织变更：按订单创建时、履约时或当前组织统计需遵循业务确认规则；未确认时不可混用。
- 分组基数小：展示原始订单数和样本范围，不仅展示百分比，避免误导。
- 缺货 SKU 重复出现在多张订单：缺货 SKU 数按唯一 SKU 编码去重；缺货订单数按唯一订单号去重。
- 查询区域无订单：明确是 0 张还是区域映射/数据缺失。

### 5、输出规范及安全约束

- 分组层级及归属口径必须写清；百分率旁同时提供分子、分母或订单数。
- 不将相关性描述成责任因果，不对销售人员做绩效判断。
- 涉及客户、人员信息遵循权限与最小必要原则；明细提供范围受限时只给汇总。
- 使用真实数据时标注快照时间；演示数据必须明确标注。

### 7、业务字段、公式、案例

### 字段

订单号、订单创建时间、客户编码、销售组、销售组织、省区、大区、客户类型/渠道、销售人员、基地、SKU、订单需求量、实际发货量、缺货量、状态、节点时间。

### 公式与口径

- 区域订单数 = 按指定时间有效范围内的唯一订单号计数。
- 区域满足率 = `min(区域实际发货量合计 ÷ 区域需求量合计, 100%)`，不能把各订单满足率简单平均。
- 满足率区间订单数 = 按订单级满足率落入互斥区间的去重订单数。
- 区域超时/预警订单 = 命中对应规则的去重订单数；可额外展示节点命中次数，但分开标识。
- 缺货订单数按订单去重；缺货 SKU 数按 SKU 编码去重；缺货数量按统一单位加总。

### 案例

某省区 A 订单需求 100 件、发货 100 件；B 订单需求 900 件、发货 720 件。区域满足率为 820/1000=82%，不是 (100%+80%)/2=90%。

### 8、输出样式

| 区域/组织 | 订单数 | 超时/预警订单 | 未开订单 | 加权满足率 | 满足率区间分布 | 缺货订单/SKU/数量 |
| --------- | -----: | ------------: | -------: | ---------: | -------------- | ----------------: |

表后列出风险最高的区域和可下钻订单，并注明区域映射覆盖率、统计周期和数据更新时间。

## 当前安装能力边界

本 Skill 由订单工作台与订单履约 Agent 共用，技能描述不授予查询、人员范围或业务写入权限。只能使用当前 Agent 已安装、已授权的页面证据和工具；用户角色描述不代表实际授权。

订单履约只使用 order01 的当前用户受控只读能力，缺失指标和接口保持未知。订单工作台沿用其当前已发布能力；页面处于 mock 时，只分析明确标记的报告摘录、演示数据或用户提供的证据，不宣称已接入实时订单系统。

销售确认、每小时提醒、飞书消息、OMS 更新、WMS/TMS 下发及外部改善任务尚无本次新增的写入或调度接口。可以解释流程、分析证据和生成草案，不能因加载 Skill 就启动执行或声称已完成。实际操作仍需相应工具、有效权限和明确授权。
