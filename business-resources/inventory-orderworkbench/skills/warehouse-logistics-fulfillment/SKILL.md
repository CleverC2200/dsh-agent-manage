# 仓配与物流履约 Skill

## 具体内容

### 1、适用边界

- **做**：基地/仓库汇总、物流商和运单状态分析，关联订单、客户、销售组织及履约节点，定位仓配延误与待处理环节。
- **不做**：根据计划推测真实 GPS 位置；将运单创建视为实际发车；代替物流商确认签收；创建运单、派车或改派。
- 订单一单一物流商等关联约束应依据系统主数据，异常关联须标记。

### 2、输入（触发范围）

- 查询某基地、仓库或物流商的订单/运单、状态、超时和预警数量。
- 查询多少订单尚未生成运单、未发车、运输中、已签收或预计延迟。
- 按订单号查询其基地、提货点、物流商、运单和关联客户。

不用于：没有运单事件时预测实时位置；对客户库存进行补货判断。

### 3、工作步骤

1. 识别查询对象和粒度：基地、仓库、物流商、运单、订单、时间范围和节点。
2. 查询仓库、订单、运单及物流事件，核验订单—运单—物流商—基地关联键和数据更新时间。
3. 将状态映射为已下单/待拣货/待出库/待发车/运输中/派送中/签收等；使用系统状态字典，不以文本相似度擅自合并状态。
4. 按确认的节点承诺时间和预警规则识别超时/预警；分别报告订单去重数、运单数和事件数。
5. 汇总基地/仓库/物流商的订单量、运单量、未下运单、运输中、签收、超时和缺货情况。
6. 下钻到具体运单和订单，展示事件时间、当前状态、最后回传时间及客户/区域；识别缺少轨迹或异常关联。
7. 如风险来自缺货或排产不足，分别路由到库存或生产 Skill；只建议跟进，不执行派车/改派。

### 4、异常处理

- 订单无运单：显示“未关联运单/待接入”，不把空值算作运输延迟。
- 运单状态长时间未更新：仅报告最后回传时间和数据时效，无法证明车辆停滞。
- 一个订单多运单或多订单共用运单：按关联规则分别计数，并显式说明粒度。
- 缺少承诺到达时间：不判定准时/延迟；可展示当前节点和最后事件时间。
- 基地/仓库映射缺失：汇总到“未映射”并提供数量，不强行归属。

### 5、输出规范及安全约束

- 运单号和订单号脱敏规则服从用户权限；结果标注订单数、运单数或事件数的统计粒度。
- 显示数据源与最后回传时间；预计到达、计划发车与实际签收必须区分。
- 不声称已派车、联系物流商、改派或签收；所有此类操作需单独授权。

### 7、业务字段、公式、案例

### 字段

基地、仓库、提货点、物流商、运单号、订单号、客户名称/编码、销售组、省区、大区、订单状态、运单状态、节点承诺/实际时间、GPS/温控事件（如已接入）、事件回传时间、异常原因。

### 公式与口径

- 未下运单订单数 = 符合订单范围且不存在有效关联运单的去重订单数；排除取消/作废订单的规则需确认。
- 超时运单数 = 超过已确认节点承诺时间且未达到目标节点的去重运单数。
- 超时订单数 = 关联到任一超时运单/节点的去重订单数；一个订单多个超时节点仍计一张。
- 物流准交率 = 按业务定义的签收订单中，实际签收不晚于承诺签收时间的订单数 ÷ 有有效承诺与实际签收时间的订单数。未闭环订单不应默认算准时。

### 案例

某基地 12 张有效订单：9 张已关联运单，2 张未下运单，1 张状态映射失败。应分别报告 9、2、1，不把状态映射失败的订单归入“未下运单”。

### 8、输出样式

先给基地/物流商汇总，再列风险运单：运单号｜关联订单｜基地/仓库｜物流商｜当前状态｜最后回传时间｜超时/预警节点｜待核查事项。

在末尾说明订单/运单计数口径和轨迹数据更新时间。

## 当前安装能力边界

本 Skill 由订单工作台与订单履约 Agent 共用，技能描述不授予查询、人员范围或业务写入权限。只能使用当前 Agent 已安装、已授权的页面证据和工具；用户角色描述不代表实际授权。

订单履约只使用 order01 的当前用户受控只读能力，缺失指标和接口保持未知。订单工作台沿用其当前已发布能力；页面处于 mock 时，只分析明确标记的报告摘录、演示数据或用户提供的证据，不宣称已接入实时订单系统。

销售确认、每小时提醒、飞书消息、OMS 更新、WMS/TMS 下发及外部改善任务尚无本次新增的写入或调度接口。可以解释流程、分析证据和生成草案，不能因加载 Skill 就启动执行或声称已完成。实际操作仍需相应工具、有效权限和明确授权。
