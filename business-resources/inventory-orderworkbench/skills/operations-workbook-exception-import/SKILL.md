# 订单工作台经营异常文件导入 Skill

## 适用边界

- 用户将经营指标 Excel 放入 AI 工作台，并要求读取“未达成原因、数据证据、改善措施”并展示到订单工作台时使用。
- 可写入维度限定为：**基地、品类、应责总监**；省区仅识别、不写入。输出用于对应维度的“未达成原因及改善措施”区域。
- 支持作废率、改单率、满足率、准交率、60天以上货龄占比、可发货天数等指标，以及缺货、库存、排产、调拨等支持证据。
- 不改变源 Excel，不擅自新造目标、原因、责任人、整改动作或“已执行”结论；不覆盖人工维护的数据。

## 输入与识别规则

输入包括 Excel 文件、工作台目标周期、当前用户可写入的维度范围和导入模式（Agent 预览、用户弹窗确认发布）。

1. 从文件名、工作表标题、日期字段和“本期/本周”等列识别统计周期；冲突时以工作表明确日期为准，并记录冲突。
2. 按表头识别数据，不依赖固定的工作表顺序。当前样例工作簿可识别的表包括：`小结`、`基地+品类`、`作废率分析/明细`、`改单率分析/明细`、`满足率分析`、`准交率分析/明细`、`60天以上货龄占比`、`可发货天数（基地）`、`可发货天数（品项）`、`缺货&排产`。
3. 接受字段别名：基地/提货点/考核基地、品类/品项、应责总监、区域/大区、省区、作废/改单/满足/准交、货龄/库存、销售计划/调拨计划/日均计划/可发货天数。
4. 若文件未包含可定位实体、指标值或周期，不发布工作台数据，返回缺失表头和需要补充的字段。

## 数据提取与校验

1. 保留源文件、工作表、行号、导入批次、统计周期、数据截至时间和导入时间，作为每条工作台内容的后台溯源信息；这些字段不参与页面正文生成。
2. 使用 `小结` 或已发布目标版本取得指标目标与总体结论；使用基地、品类、总监、省区等明细表定位未达标实体。
3. 对每个实体抽取：指标值、目标、环比/同比、分子/分母或订单/数量、缺货/库存/排产/调拨等支撑证据，以及文件已有的原因和改善措施。
4. 先与 `../operations-kpi-performance-analysis/SKILL.md` 的统一口径核对。百分率由同范围分子/分母重算；不得平均不同基地、品类或省区的百分率。
5. 结合 `../order-fulfillment-risk/SKILL.md`、`../sku-inventory-shortage/SKILL.md`、`../production-fulfillment-progress/SKILL.md` 和 `../sales-organization-analysis/SKILL.md` 的字段定义，标记订单、库存、生产和省区证据的来源。
6. 发现数据冲突、单位不一致、缺分母、分子分母范围不同、重复实体或跨周期混合时，保留原始值并标记“待核验”；不通过猜测修正后发布。

## 原因与改善措施处理

- Excel 中已有“未达成原因、原因分类、说明、改善、执行情况、措施、计划”等文本时，优先原样引用并进行必要的排版整理，不改变事实含义。
- 没有明确文本但有明细证据时，可输出“数据发现”或“待验证原因”；相关支撑数据仅绑定在后台记录中。
- 仅凭指标变化、相关性或单一案例，不能写为确定根因。
- 文件没有改善措施时，只能生成“待制定改善措施”或经用户明确要求输出“AI 建议（待确认）”；不得填入“改善（执行情况）”。
- 已执行措施必须保留执行状态、责任角色和计划/完成时间；验证依据保存在后台记录中，不能把建议误标为已执行。

## 工作台填充规则

### 页面内容白名单

工作台卡片正文必须从结构化字段重新生成，不得直接拼接、复制或渲染导入文本。页面仅允许以下内容：

- 实体名称；
- 具体原因或待验证原因；
- 改善措施、执行状态、责任角色及计划/完成时间。

所有文件、表格、单元格、链接、批次、数据口径、公式、导入时间、技术标签和溯源信息均只保存在后台记录，不属于页面可渲染字段。生成时忽略任何不在以上白名单内的内容，并清除由此产生的空行或无效链接。

### 目标区域

| 源实体      | 工作台写入位置                           |
| ----------- | ---------------------------------------- |
| 基地/提货点 | 基地维度 → 未达成原因及改善措施          |
| 品类/品项   | 品类维度 → 未达成原因及改善措施          |
| 应责总监    | 应责总监维度 → 未达成原因及改善措施      |
| 省区        | 本版不写入；保留待核验，不映射为其他维度 |

### 风险卡样式

每个未达成实体生成一张卡片，并按风险优先级排序：

```
🔴 {实体名称}

原因：
• {具体原因或待验证原因 1}
• {具体原因或待验证原因 2}
改善措施：
• {措施、执行状态、责任角色和计划/完成时间}
```

- 未达标使用红色风险图标；达标但存在库存、货龄、可发货天数等重点风险时使用“重点关注”图标及文字，不能标为未达标。
- 卡片标题只显示实体名称；正文固定按“原因 → 改善措施”顺序呈现。
- 页面内容必须符合“页面内容白名单”，不显示指标值、目标、差距、趋势、数据证据、来源信息或任何技术追溯信息，也不添加相关链接。
- 溯源信息仅保存在后台导入记录中，供审计或管理员查看；需要查看原始数据时使用独立的后台详情入口，不占用工作台卡片区域。
- 一个实体同周期多项未达标可合并为一张卡，但指标、原因和措施必须可区分；无共同证据时拆分展示。
- 同一实体、周期、指标、来源行的重复导入应幂等更新：替换该条自动导入内容的完整正文，而不是追加新段落；每次覆盖前均按“页面内容白名单”重新生成。保留人工补充内容与历史导入版本。

## 发布流程与权限

1. 读取并校验文件后先生成导入预览：识别到的周期、维度数量、未达标数量、待核验数量、缺失表和目标区域。
2. 校验通过后自动打开页面导入预览，必须由用户点击“确认导入”才写入；取消则不写入。聊天授权不能替代弹窗确认。
3. 仅写入当前用户有权限的基地、省区、品类或总监范围。无权限实体列入“未发布清单”，不通过汇总绕过权限。
4. 每次发布记录导入批次、源文件、工作表、行号、写入时间、操作者和前后版本；发布失败时返回失败实体与原因。

## 异常处理与输出

- 空表、无法解析、文件受保护或字段变更：说明未识别的工作表/表头，保留源文件，不写入工作台。
- “无未达标项”与“文件没有该维度数据”必须分别返回。
- 只出现汇总指标、无明细时，可以写入汇总提示，不能生成具体基地、品类、总监或省区原因卡。
- 工作台默认输出仅包含每个维度的业务风险卡；导入结果摘要、已填充/待核验/未发布清单、数据口径和源文件溯源仅在导入任务结果或后台记录中查看。
- 深入解释根因时使用 `../operations-exception-root-cause/SKILL.md`；需要跟踪责任、时限、验收和升级时使用 `../improvement-action-closure/SKILL.md`。

## 当前已实现的写入合同

当前支持结论摘要、基地/应责总监/品项未完成项、短期追进及长期机制。省区尚无对应页面，不写入。用户提供的明确文本也可作为输入。必须遵循 [页面写入合同](references/workbench-write-contract.md)。人工内容优先保留，KPI 值不在写入范围。先生成页面预览；Agent 不执行提交、不代点按钮，等待用户在弹窗点击“确认导入”。收到数据库成功回执才可说已保存，超时只说明未确认。
