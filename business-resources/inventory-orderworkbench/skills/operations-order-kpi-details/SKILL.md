# 指标明细流程

六指标（作废率、改单率、订单满足率、准交率、货龄占比、可发货天数/周转天数）统一使用 gea_order_kpi。该工具与本地看板共用查询、计算和口径合同；不需要先打开页面。其他订单、库存和业务知识问题继续按相关 Skill 使用已授权 Cube 和知识库，不强行转成卡片指标。

1. 点击卡片时读取 metricDetails.current、contract、queries、version 和实际周期；本期、本周分别说明，不根据周标签改写主周期。
2. 独立问数使用 gea_order_kpi(metric,start,endExclusive,base,view)，日期为含开始、不含结束。先明确范围，未指定范围时只使用已有明确上下文。view=contract 返回当前定义；view=summary 返回当前计算结果；view=details 读取已发布分页明细。不得自行拼 SQL、回退旧 Cube 度量或用知识库公式重算这六项指标。
3. 数值、公式、周期归属、字段映射、筛选、单位、目标和状态都读取 current/contract，不在 Skill 固定另一套业务规则。回答保留 version/revision，版本不一致时刷新，不能把旧快照当当前结果。
4. 分子、分母、待判定及单位直接展示返回值；未返回的计数写未提供，不能由百分率反推或把 pending 当剔除。样本、暂算、完整集合分别按返回标记说明。率值为0不等于无订单；0分母不适用，查询失败与空集合分开。
5. 明细仅代表返回的页；没有同口径明细接口不等于底表没历史数据。未取得全量排序/分组统计时，不宣称集中于某基地、客户或SKU。知识库只补业务背景，不覆盖当前代码合同；无依据的原因、建议和责任人不补写。

## 环比同比与维度分组

- 用户要求同比时，必须分别读取本期、上期同长度和去年同期；月报使用 `yearMonth`，周报使用 `yearWeek`，三次调用使用相同 `metric`、`base`、`view`、版本和授权范围。
- 生成大区、基地、负责人或品项表时，先按维度过滤每个周期，再分别汇总分子和分母；未映射或异常行单独列示，不能让一条 `invalid` 记录阻断全部维度。
- 只有该维度在对比期确实无来源、分母为 0、分子/分母缺失或版本不一致时，才写“同比不可计算”；有有效同比值时必须输出。

## 回答格式

用户只问一个值时简答。要求完整明细时按五段输出：

1. 结论：指标值、范围及数据日期。
2. 指标公式：原样引用当前合同，不自拟阈值或筛选。
3. 公式字段值：分子、分母、单位、样本及待判定。
4. 明细表格：使用返回字段和业务标签，注明页码、全量/样本及未提供字段。
5. 证据限制：仅列与结论有关的缺口；原因和行动按需、有据输出。

列示模板：指标｜周期｜范围｜分子｜分母｜值及单位｜待判定及单位｜口径版本。当前代码返回的公式和量纲优先于表头惯例，不把商品数量写成订单张数。
