# 订单工作台指标明细 Skill

## 适用边界

- 当用户问“作废率/改单率/满足率/准交率的明细、有哪些订单、为什么未达标、查看某周期订单”时使用。
- 当用户问“订单是否拆单、这个订单拆成了哪些单、拆单后的其他单据有哪些”时使用。
- 当用户问“某订单改了什么、改单商品明细、商品数量如何变更、改单前后数量”时使用。
- 当用户问“60天以上货龄占比明细、可发货天数全国/品项明细、某基地可发货天数、日均需求怎么算”时使用。
- 在工作台中提供指标对应的订单清单与统计周期，不重新定义四项指标的汇总口径。
- 60天以上货龄占比、可发货天数的库存计算由 `../sku-inventory-shortage/SKILL.md` 提供；本 Skill 负责工作台的汇总与明细展示。
- 不修改订单、拆单、改单、作废或履约节点；仅查询与展示。

## 输入与前置条件

识别指标类型或订单号、统计周期、统计层级（全国/基地/销售省区/负责人/品项）、筛选条件、数据截至时间及当前用户权限。

- 指标明细未给出周期时，沿用用户当前打开的周报或月报周期；没有页面上下文时，追问周期。
- 单订单拆单或改单查询以订单号为必填条件；若已知订单但未指定周期，优先以该订单及其关联事件的有效时间范围查询，不因缺少报表周期拒绝查询。
- 货龄与可发货天数查询必须识别维度：全国、品项或基地；未指定维度时先按用户当前工作台筛选维度展示，并标明默认范围。
- 明细范围必须与指标卡相同：相同有效订单规则、去重键、基地/销售组织归属、目标版本及快照时间。
- 用户无明细权限时，只返回其权限范围内的汇总，明确说明限制。

## 工作步骤

1. 从 `../operations-kpi-performance-analysis/SKILL.md` 获取该指标的统计范围、分子/分母、计算口径和周期。
2. 改单率使用本页 metricDetails.queries 的日表汇总及有效明细查询，与看板复用筛选和数量公式；不得转到通用订单去重或小时表重算。准交率使用 `gea_order_ontime` 的summary/details固定查询，与看板保持实际到货周期、执行单去重及完整分母一致；其他履约指标通过 `../order-fulfillment-risk/SKILL.md` 查询同一范围的主数据与节点。
3. 订单清单按订单唯一键归并展示最新有效状态；改单率计算仍按有效商品明细数量合计，不按订单张数或SKU种类去重计数，不以归并后的展示行重算分子、分母。
4. 按所查指标筛选或排序：
   - **作废率**：展示纳入作废率口径的订单，默认按作废订单优先；
   - **改单率**：按有效明细的调整数量倒序展示，先列完整范围的数量分子、数量分母及比率；改单时间仅作可选参考，不参与过滤；
   - **满足率**：展示全部纳入统计的订单，并优先显示满足率低、缺口大的订单；
   - **准交率**：展示全部应统计执行单，区分准交、已确认逾期和待判定；待判定保留在完整分母，不标成已确认逾期。
5. 按本 Skill 的五段式问答结构返回结论、口径、明细、建议与待确认项，使结果可追溯。

### 库存指标明细模式

1. 通过 `../sku-inventory-shortage/SKILL.md` 获取同一周期、同一筛选范围内的总库存、60天以上库存、可用库存、月度需求计划、月度调拨需求出库计划、当月天数、日均需求及商品/基地归属。
2. 汇总区固定展示：`汇总总库存｜60天以上汇总库存件数｜60天以上货龄占比`；货龄占比的分子、分母必须使用同一库存范围。
3. 可发货天数严格调用已发布的计算模型，同时将公式、需求构成、系数和当月天数展示给用户；不根据页面样例值自行推导或覆盖业务公式。
4. 当前工作台已确认口径：全国/品项日均需求为月度需求计划 ÷ 当月天数，不加调拨；基地日均需求为（月度需求计划＋月度调拨出库计划 × 0.5）÷ 当月天数。可发货天数分子取当前基地覆盖的工厂仓＋工厂外租仓现存量，不用可用库存替代。
5. 用户查看某一商品的日均需求时，在该商品明细后列出月度需求计划、月度调拨需求出库计划、调拨系数、当月天数和最终日均需求。
6. 总库存、60天以上库存、日均需求或可发货天数任一字段缺失时，仅展示可用原始字段并标记“待确认”；不得用 0 补全。

### 拆单关联单据模式

1. 根据当前订单号查询拆单关系记录、拆单组 ID、父子订单/来源订单关系及生效状态；不得仅凭“是否拆单=是”推断具体关联单据。
2. 返回同一拆单组内的全部有效订单：当前查询订单必须排在第一行并标识为“本单”，其余订单标识为“关联单据”。
3. 若业务模型存在来源单、拆出单、合并单等方向，显示关系类型；没有可靠关系方向时仅显示“同一拆单组关联”，不虚构父子关系。
4. 同一订单在不同拆单组或发生多次拆单时，按拆单时间分组展示，不将不同批次的拆单关系混在一张表中。
5. 没有关系记录时明确显示“未发现拆单关系”；关系数据未接入或无权限时显示“暂无法判断”，不等同于“未拆单”。

### 历史改单事件追溯模式（仅用户明确询问变更历史时）

本节用于历史事件追溯，不是改单率汇总或明细的前置条件。查询当前改单率时直接使用文末数量口径，不要求存在改单事件、版本、原因或时间。

1. 根据当前订单号查询有效改单事件、改单版本及订单商品行；一个订单存在多次改单时，默认展示最新有效版本，并说明可按改单时间或版本继续查询历史。
2. 对每个 SKU 关联改单前后的数量与商品信息；商品新增、删除、替换和数量变更都应明确区分，不以当前订单商品清单替代历史变更事实。
3. 商品行按 `订单号 + 改单版本 + SKU/商品行标识` 去重；同一商品多次变更时，展示当前查询版本对应的变更，并提示该 SKU 的变更次数。
4. 原始数量、调整数量、实占数量、发货数量和下单数量必须来自各自业务定义；字段定义或单位不一致时，保留原值并标记“口径待确认”，不得自行相减或汇总。
5. 没有有效改单事件时显示“该订单未发现有效改单记录”；事件数据缺失或无权限时显示“暂无法判断”，不可误报“未改单”。

## 准交率当前口径

当前准交率以看板执行单到货口径为准：按COALESCE(gpsisinraildate_to,arriveconfirm_time)实际到货时间归属周期，执行单号去重，单位张。分子为已确认准交执行单数，分母为全部符合筛选的候选执行单数，待判定保留在分母且不视为已确认逾期。基准为MAX(客户期望到货、开单确认到货、系统计算到货)，kamd/dc晚满18小时、其他客户晚满12小时为逾期，严格早于才准交。系统交期缺失时仅能严格证明早于已有两交期最大值+对应时限的单确认准交，否则待判定。直接报告页面或gea_order_ontime返回的numerator、denominator、pending、known、late和value，不从样本率反推计数。独立查询调用gea_order_ontime，复用看板固定SQL和全部剔除条件，不用旧Cube的fromorderno_month或SUM(is_ontime)/COUNT(is_ontime)替代。

完整合同见[准交率当前合同](../operations-kpi-performance-analysis/references/ontime-contract.md)。明细分页不代替全量汇总。

## 口径与异常处理

- 作废、改单、准交的规则必须使用已发布版本；规则缺失时可展示原始状态，但不可计算或判断指标。
- 满足率 = 实际满足数量 ÷ 订单需求数量；合计必须由数量重算，不平均订单百分率。
- 最后一次发货时间不等于签收时间；准交率的实际完成节点必须与业务规则一致。
- 查询结果为 0 时显示“本统计周期内无匹配订单”；数据源未接入时显示“无可用明细数据”，两者不得混淆。
- 订单属于多个基地、销售组织或周期边界不清时，显示归属规则与待确认项，禁止重复计入。
- 拆单关系以订单关系表或经确认的拆单事件为准；订单号相近、客户相同或创建时间接近都不能作为关联依据。
- 仅历史改单事件追溯以事件及版本为准；当前改单率明细按日表数量公式计算，不因缺少事件、版本或时间而排除。后续发货、占用及备注不能替代公式字段。
- 60天以上货龄占比 = 60天以上纳入统计的库存 ÷ 同一范围的纳入统计库存；汇总占比必须由汇总分子/分母重算，不平均商品或基地占比。
- 可发货天数的库存分子、需求口径与调拨折算系数必须与查询维度一致。若公式字段与页面展示值无法对账，展示原始字段、公式版本与差异，标记“待核验”，不输出伪精确天数。

## 输出样式

所有指标查询均按以下五段输出；单订单拆单、改单商品或库存指标明细可在“指标具体明细”中使用相应表格。

### 一、结论

- 说明指标值、达成状态、统计范围和统计周期；存在数据截至时间时一并说明。
- 用户未提供范围或周期时，明确本次使用的默认范围和周期。
- 所有比例指标、环比/同比变化和与目标差距均使用 `%` 表示，例如“未达标 1.41%”；不得使用英文百分点缩写。天数差使用“天”，数量差使用对应业务单位。

### 二、基本信息

1. **指标定义**：说明指标统计对象、纳入/排除规则和单位。
2. **指标公式**：展示已发布的业务公式，不使用未经确认的简化公式。
3. **公式字段值**：逐项列出本次公式涉及的字段和值，包括分子、分母、需求、库存、系数、当月天数等；字段缺失时显示“待确认”。
4. **剔除内容说明**：列出未纳入本次统计的对象、剔除规则、剔除数量及原因；例如测试单、重复单、无效状态单、跨统计周期记录或缺少关键字段的记录。仅展示数据源或已发布口径明确支持的剔除项；若剔除规则或数量未接入，明确显示“待确认”，不得默认写为“无剔除”。

### 三、指标具体明细

- 仅展示本次所问指标对应的明细表；用户同时询问多个指标时，按提问顺序分别展示，不混合不同口径的表格。
- 使用清晰小标题和 Markdown 表格输出；不规定前端颜色、区域位置、分页、展开图标或点击交互。
- 数据较多时先列风险最高或差距最大的明细，并说明“可继续查看完整明细”；已列数据必须与当前统计范围、周期和权限范围一致。

- 查询全国/品项可发货天数时，在商品明细后列出日均需求构成：月度需求计划、月度调拨需求出库计划、当月天数及最终日均需求；基地维度额外列出当前调拨折算系数。

- 是/否、达标/未达标、准交/不准交使用清晰文字；拆单关系存在时列出本单与关联单据，不要求点击或展开交互。

### 四、建议动作

- 仅基于本次可验证的明细给出优先核查或处理建议，明确建议对象与动作。
- 不将建议写成已执行结果；涉及订单、库存、排产、调拨或任务创建的实际操作须另行取得授权。

### 五、待确认

- 列出会影响结论的缺失字段、口径冲突、映射问题、权限限制或数据时间差。
- 没有待确认项时明确写“无”。
