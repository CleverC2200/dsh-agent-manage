# 订单工作台指标达成分析 Skill

## 适用边界

- 汇总订单工作台的六项核心指标，并按全国、基地、销售省区、负责人、品项和指定周期比较达成情况。
- 支持周度、月度、本期、环比、同比、排名和阈值预警；指标计算仍使用对应业务 Skill 已确认的数据与口径。
- 不自行编造目标、阈值、历史值或实时业务数据；不直接解释异常根因、下发整改任务或修改业务数据。

## 已有指标为空时的解释

用户给定某项指标为空时，已知事实是“该率值未知”，空值原因未提供；不能把它诊断为必然缺少分子、分母、特定节点字段或数据故障。保留同时给定的订单量等规模值，它可以是待同口径确认的需求分母，不直接认定等同，也不直接否定其可作为分母。仅凭规模不能重建未知率值。

此类口径核对只列出现有事实、未知指标与能否达标，不补写题内未提供的备选公式，不展开风险排序、原因、整改和闭环。当前达标比较不要求环比同比；无有效值或适用目标就不可判定。题内同一总集合为零时，其有效或可判定子集也为零；0/0不适用，不将零样本归因为数据故障。

## 输入与前置条件

识别分析周期、统计层级、对象范围、目标版本、对比周期、指标口径和数据截至时间。若用户未指定，使用当前已发布的周/月报口径；没有已发布口径时只报告原始数据及“目标待确认”。

所需数据包括：有效订单、作废与改单记录、订单需求/发货量、承诺与实际履约节点、可用库存与货龄、日均需求，以及基地、销售组织、负责人、品项的归属关系。

## 工作步骤

1. 确认统计对象、周期、维度和数据快照；排除未说明是否纳入的测试单、取消单或重复单。
2. 通过领域 Skill 获取明细或已计算的分子、分母与去重键：
   - 订单、满足率、准交、作废/改单 → [order-fulfillment-risk](../order-fulfillment-risk/SKILL.md)；
   - 可发货天数、60天以上货龄占比 → [sku-inventory-shortage](../sku-inventory-shortage/SKILL.md)；
   - 生产影响或供给覆盖 → [production-fulfillment-progress](../production-fulfillment-progress/SKILL.md)；
   - 基地仓配与运单影响 → [warehouse-logistics-fulfillment](../warehouse-logistics-fulfillment/SKILL.md)；
   - 省区、负责人、渠道归属 → [sales-organization-analysis](../sales-organization-analysis/SKILL.md)。
3. 按同一统计范围汇总，百分率采用总分子/总分母计算，禁止平均各主体的百分率。
4. 与已确认目标及上期/去年同期比较，计算差值；明确指标为正向或反向，并标识达标、预警、未达标或待确认。
5. 输出总览、分维度明细、异常排序和数据限制；当用户要求作废率、改单率、满足率、准交率、60天以上货龄占比或可发货天数的工作台明细时，路由 [operations-order-kpi-details](../operations-order-kpi-details/SKILL.md)。

## 指标口径

| 指标 | 计算原则 | 方向 |
| --- | --- | --- |
| 作废率 | 接收至 OMS 超过12小时后、满足当前锁定口径的作废订单数 ÷ O接收订单数（剔除接收后12小时以内、含恰好12小时作废的订单）；按OMS单据新增时间归属周期、客户编码＋原订单号去重 | 越低越好 |
| 改单率 | 客户要求量≥0明细的绝对数量差合计 ÷ 全部有效商品数量合计×100% | 越低越好 |
| 满足率 | 实际满足数量合计 ÷ 订单需求数量合计 | 越高越好 |
| 准交率 | 已确认准交执行单数 ÷ 按实际到货时间归属周期的全部候选执行单数（含待判定；实际到货即证明已发货，无需lastshipmenttime） | 越高越好 |
| 60天以上货龄占比 | 货龄 age_days≥60 的 inv_qty 合计 ÷ 同范围 inv_qty 合计 | 越低越好 |
| 可发货天数 | 当前基地覆盖仓现存量 ÷ 已确认日均需求 | 按目标阈值判定 |

- 改单定义、作废状态、准交规则、库存范围和日均需求窗口必须采用已发布版本；版本缺失时不得擅自设定。
- 环比/同比 = 本期指标 − 对比期指标。百分率差使用 `%`，天数差使用“天”；不可将二者写成百分比增长率。
- 统计粒度不一致时分开列示，例如订单层满足率与 SKU 层货龄占比不可相加或直接比较。

## 异常处理与输出

- 数据缺失、快照不一致、分母为零、映射缺失或目标未发布时，明确标为“不可计算/待确认”，不要补零。
- 全国/合计指标应由明细分子和分母重算，不能平均基地或省区百分率。
- 输出顺序：**结论总览 → 六项指标卡 → 基地/省区/负责人/品项明细 → 未达标与变化最大项 → 数据时间、目标版本、口径与缺项**。
- 指标异常需要解释时，使用 [operations-exception-root-cause](../operations-exception-root-cause/SKILL.md)；需要责任、时限和闭环时，使用 [improvement-action-closure](../improvement-action-closure/SKILL.md)；订单与库存指标的周期明细使用 [operations-order-kpi-details](../operations-order-kpi-details/SKILL.md)。

## 当前安装能力边界

本 Skill 由订单工作台与订单履约 Agent 共用，技能描述不授予查询、人员范围或业务写入权限。只能使用当前 Agent 已安装、已授权的页面证据和工具；用户角色描述不代表实际授权。

订单履约只使用 order01 的当前用户受控只读能力，缺失指标和接口保持未知。订单工作台沿用其当前已发布能力；页面处于 mock 时，只分析明确标记的报告摘录、演示数据或用户提供的证据，不宣称已接入实时订单系统。

销售确认、每小时提醒、飞书消息、OMS 更新、WMS/TMS 下发及外部改善任务尚无本次新增的写入或调度接口。可以解释流程、分析证据和生成草案，不能因加载 Skill 就启动执行或声称已完成。实际操作仍需相应工具、有效权限和明确授权。

### 十月指标核对补充

- 可发货天数的计划按库存快照日切换：1–16日初版、17–20日纠偏、21–26日滚动、27日起下月初版；零值不回退，空值不擅换版本。下月计划对应日数分母待确认。
- 成都分仓、上海分仓货龄归西南，按数量加权，不平均百分比。
- 准交率按当前看板的执行单、实际到货周期和完整分母计算；待判定留分母，不用可判定样本率代替。详细规则见[准交率当前合同](references/ontime-contract.md)，独立回源调用 `gea_order_ontime`。
- 改单率按商品明细数量合计，不按订单张数或SKU种类去重计数；客户要求改单量change_order_qty≥0时计算ABS(change_order_qty－有效量)，真实0保留。有效量优先dms_last_update_qty，否则need_qty_origin，再为空取0；客户要求量为空或负值的有效明细仍计入分母。三个数量全空剔除。取消锁定期、交期和实际改单时间条件。

- 基地归并不扩大覆盖仓范围：成都A170、上海Y204当日库存分类为20，货龄维表02与快照冲突时按既定工厂仓范围剔除；不得纳入后再汇总。缺货龄基地仅可用同日仓库库存中完整且唯一的基地回补，冲突保持未知。

### 日表创建队列与完整性纠偏

改单率只用agents_scm_execute_detail_d，按header_addtime归属周期、按当前状态剔除作废及无效明细；仅createsource=20，剔除虚拟出1/2和超时原因14/16。发货仓、收货仓同pickup_point且双方类型均为工厂成品仓或工厂外租库才剔除短拨，映射来自agents_dim_bas_warehouse_d；仓库所属提货点未发布时报告缺口，不以旧is_short_transfer标记冒充。无需custchangetime或requireddeliverytime；历史冻结报告仍需历史快照。

改单周期边界：先逐明细按header_addtime筛选，再按客户＋原订单＋SKU归并。不可因原订单在期内而带入其他创建日的拆单SKU；完整分母与数量/事件证据的完整性分别说明，未查明的分子不补0。
