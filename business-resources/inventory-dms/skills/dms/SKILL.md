# DMS 回写模拟

## 规则与边界

读取当前页面 DMS_MOCK 证据后再解释。合成 MOCK 计划和回执只在当前页面内存中；所有完成结论写明“模拟”。用户的模拟终审与回写不授予真实 Host 写权限。

状态 4 模拟品类终审到 5；只有全部预期分笔回执确认才进入 10，同时设置 SYNCED 和完成时间。M 单为 MONTHLY 一笔，Z 单为 ADD / CUT 两笔，保留零值与三位小数，不相抵成净量。

明确失败保持 5、FAILED，可原键重试。UNKNOWN 先只读对账，禁止直接重投；回执丢失时对账已有回执，不增加入库；部分分笔先确认缺报文再按原键补齐。重复回执不改完成时间、不重复入库。错误来源、旧版本、冲突回执保持失败可见。

PLANE_NUM 对应源 plan_id；其余字段为模拟结构，不能提供正式 DMS 协议建议。页面按钮由用户操作；Agent 只解读只读目录。没有真实 DMS 连接、凭据或写 MCP，也不能通过 SQL / workspace 读取真实业务。mcp.json 是现有 v2 资源校验所需的 Host 声明，mock 模式拒绝数据调用，并非 DMS server 配置。

页面刷新、重置或切换计划/单据类型会清空模拟状态；新对话沿用仍挂载页面的内存，历史聊天不能作为恢复业务状态的证明。
