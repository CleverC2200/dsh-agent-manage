# 问答可视化生成

## 目标与路由

把已经完成的数据查询和业务分析组织成“结论先行、图表支撑、明细按需展开”的独立 HTML 回答。

- 开始选图前，读取 [references/visualization-selection-rules.md](references/visualization-selection-rules.md)。
- 组装 `ANSWER_DATA` 时，读取 [references/data-contract.md](references/data-contract.md)。
- 生成文件时使用 [assets/answer-visualization-template.html](assets/answer-visualization-template.html)，不要重新设计另一套视觉风格。
- 计划运营周报使用 `plan-operations-weekly-report`。订单满足率深度诊断可先使用 `order-satisfaction-analysis`，再用本 Skill 呈现已核实结果。

简单指标值、口径解释和短答案默认直接回复文字，不为展示形式强行生成 HTML。

## 数据边界

- 数值只能来自本轮成功返回的查询结果，或用户已经提供且范围、单位、期间和含义明确的数据。
- 知识库材料只能支持口径、制度和背景，不得产生指标数值。
- 不把失败、超时、被拒绝或未执行的查询写成已核实事实。
- 数据不足、口径冲突和待验证线索必须保留原状态，不补造趋势、对象、原因或建议。
- 模板中的示例数据只用于演示结构，正式输出必须全部替换。

## 工作流

1. 先完成问题回答和证据核查，再决定是否需要 HTML。可视化不能代替分析。
2. 提炼一句核心结论、最多三个关键信号和 2–4 个直接相关 KPI。
3. 每次只选择 1–3 张支撑结论的图：主图使用 `layout: "full"`，辅助图可使用 `layout: "half"`。
4. 明细表、补充分析、证据和建议默认折叠；正文不展示“图表类型大全”。
5. 按数据契约创建 UTF-8 JSON 文件。达成状态、风险状态、证据状态和任务状态分别建模，不互相替代。
6. 运行：

   ```powershell
   python scripts/render_answer.py --data <answer-data.json> --output <result.html>
   ```

   从 Skill 目录之外调用时，使用脚本的绝对路径。脚本会复制母版并替换 `ANSWER_DATA`。
7. 检查标题、期间、范围、截止时间、单位、状态文字、折叠区和图表/数据表切换；确认页面没有遗留演示对象或演示结论。
8. 返回简短文字结论和生成的 HTML 文件。无法实际写出文件时说明限制，不得声称已经生成。

## 输出要求

- 首屏顺序固定为：用户问题、核心结论、关键信号、关键指标。
- 图表标题说明“回答什么”，图下结论说明“应该看到什么”。
- 柱状图和折线图使用模板规定的浅色系；状态标签继续使用标准语义色。
- 每张非表格图保留“查看数据表／返回图表”切换。
- 宽表格在内容区内横向滚动，不隐藏关键字段。
- 输出文件使用业务问题和日期命名，避免覆盖其他问答结果。

## 停止条件

- 没有足够可靠的数据支持图形时，输出文字结论或中性空状态，不生成虚构图表。
- 需要的字段、期间或对象无法取得时，列出缺口并停止受影响图表，继续其他有数据的部分。
- 指标口径冲突未解决时，同时说明冲突双方，停止受影响指标的正式判级。
