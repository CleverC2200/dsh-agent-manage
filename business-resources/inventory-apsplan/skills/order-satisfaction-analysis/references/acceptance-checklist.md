# 数据、模块和交互验收

每次验收同时保存输入文件哈希、生成文件哈希、工具/环境、测试范围、结果、未执行项。不能只报一个PASS。

## 程序门禁

1. raw文件存在，模型/期间/查询身份一致，分页结束或同范围COUNT匹配；同页重复与跨期输入拒绝。
2. orders完整池需求/发货/发布缺货与分组守恒；正缺货子集独立计数和复算。计划全缺值为null，真实零为0，部分缺值有覆盖审计。
3. sales与orders分别按共同维度聚合；分类映射歧义、销售独有和订单独有记录不丢失，避免多对多扩增。
4. 全国→品类/基地→组织/物料组→SKU→正缺货源行逐级数量及行数核对。`audit-bindings`不得有errors。
5. 每个品类和基地都有供给覆盖状态：订单SKU数、MES匹配数、排程匹配数、单位冲突/未查/无匹配。MES零匹配后必须检查schedule，不能直接宣称没有供给数据。
6. 来源×工厂×SKU主键不碰撞；交付null不变0；混合单位不直接求和；同一事实不在两来源重复累计。
7. packet含需求、MES和排程事实；第四模块分析覆盖本期全量主要问题和未解释部分，不能因当前选中一个品类而只输出该品类。

`self-check`验证隔离合成用例和组件逻辑，不验证真实库是否正确，也不自动确认定义、单位或原因。

## 页面模块对照

| 模块 | 必须可见/可操作 | 数据来源 |
|---|---|---|
| 顶部六卡 | 两版提报、需求、发货、满足率、缺货；缺货卡紧凑显示两类参考和差额 | metric + classificationAudit |
| 口径审计 | 原始分类、参考计算、缺值与勾稽差额按需展开 | 查询证据与审计 |
| 两类宏观结构 | 需求变更、计划内各自范围明确 | 正缺货源行复算 |
| 需求侧重点 | 品类/基地切换、六卡、完整维度列表、SKU、源行 | demandRows/crossDimensionRows |
| 计划内重点 | 品类/基地条形分布下紧接C模块 | classificationPlanDimensionRows/classificationPlanRows |
| C供给模块 | 四卡、渠道行、来源选择、匹配范围；执行和排程名称各自明确 | planRows / scheduleSupplyRows |
| MES原因汇总 | 原因字典、细分类柱图、筛选恢复、基地×品类与SKU下钻 | findings及原文 |
| 排程明细 | 原始排程记录，不凭空补原因；与MES相同整行分析面板 | schedule源行 |

| 审计导出 | 全量原始证据浏览与导出，不仅Top10 | sourceViews/随附证据 |

## 浏览器交互与视觉（环境支持时实际执行）

- 逐个点击所有品类、所有基地；记录当前对象、卡片值、首个明细对象、SKU/源行数，确认与binding-audit一致。含MES无匹配但排程有记录、有一部分匹配、全部无匹配、全计划缺值的场景。
- 供给来源切换后标题、口径、单位、数字和列表同步；切回原来源不会带入另一来源的旧原因标签。
- 点击不同列表行只有当前行展开；再次点击收起；排序、Top10/全部、返回品类后无旧对象残留。
- “查看分析”只占操作列；明细在下一行colspan全宽展开，复用红顶边标题和指标区域；原始记录在面板内局部滚动，不能撑高汇总行或被右边裁切。
- 原因标签联动筛选原始记录，恢复全部后数量回到原范围；不把父子层级或多个原因重复相加。
- 比较桌面与窄屏：卡片换行、标题和值可读、主页面不横向溢出、宽表局部滚动、顶部不遮挡下钻标题。
- 从不同品类进入第四模块，应得到相同全量报告；总原因分析与原文下钻存在；无新JS错误。
- 记录实际浏览器结果；只有HTML字符串/Node VM通过时写 `componentLogic:PASS, visualBrowser:NOT_RUN`。

## 交付状态

结构/数据绑定PASS、组件逻辑PASS、浏览器视觉PASS、业务口径已确认、目标环境实跑PASS是五个不同结论。未执行就标NOT_RUN；有数据缺口可交付带边界的报告，但不得写“完整原因已验证”。

## 程序行为核对（2026-10 补丁）

- 每份落盘的源文件都能追到 `ingest-mcp-result.cjs` 的输出摘要（行数、`totalRowCount`、`hasMorePages`、告警、sha256）；`hasMorePages=true` 的源文件不得进入 `source-bundle`。
- `grain`/`uniqueGrain` 只含编码维度；若取数时带了名称字段，需说明名称变体已合并、合并不改变合计。
- `packet` 输出的 `existingCardsFingerprint` 必须为 `MATCH` 或已按 `STALE` 处理（删除或 `--force` 后重新审阅），否则 `check` 会因指纹不匹配阻塞。
- `self-check.cjs` 的 `syntaxCheck` 为 `SKIPPED_SANDBOX` 时，须在交付说明里注明"语法自检未在沙箱内执行"，不得写成 PASS。
- `build` 若走到子进程回退路径，须记录回退原因；交付清单中同时保留 `delivery-manifest.json`（含各交付文件 sha256）。
- 单份 HTML 超过约 30MB 时，交付说明须提示打开耗时并指明 Markdown 为主要阅读格式。
