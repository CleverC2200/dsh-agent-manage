# 证据与输出契约

## 证据状态

| 状态 | 用途 |
|---|---|
| `verified_fact` | 有可追溯来源的数值、事件或分布，尚不表示因果成立 |
| `verified_cause` | 对象关联、时序、作用机制和同口径影响量有证据支持，并检查主要替代解释 |
| `supported_unverified` | 已有支持证据，因果链仍有缺口 |
| `hypothesis` | 尚无直接证据的调查方向 |
| `data_missing` | 判断所需的数据、权限或工具能力不足 |
| `definition_conflict` | 定义、单位、版本或统计范围冲突 |

历史 `verified` 保守映射为 `verified_fact`，保留原状态及来源；导入历史报告不等于重新查询。正式报告字段见[报告数据契约](report-contract.md)，不另造平行 JSON 协议。

## 从事实到根因

围绕重要结论核对：影响对象、订单—供给关联、事件与需要时间、作用机制、影响量及量化方法、主要反证。记录足以让别人复核的证据，不要求每条普通事实填满整套因果字段。

影响量可采用有依据的估计或上限，但要说明方法与不确定性，不能当作精确恢复量。若关键链路不足，保留事实或待验证线索；可以解释为何优先核查某分支，但不得把推测写成已确认或无依据排除其他原因。

例如设备故障真实发生，不代表影响了缺货 SKU；基地月度超产也不能排除需要时点或分配上的局部不足。

## 数据停止点

缺少关键关联、历史时点、事件记录或权限时，先考虑已有证据和安全可行的替代核查。确实无法继续时停止受影响结论，说明：

- 已知事实及尚不能确认的判断；
- 缺什么、影响哪里；
- 可向哪个角色取得何种记录，以及拿到后如何验证。

不必为每项缺口机械输出全部字段；其他独立分支继续，不因局部缺数停掉整个分析。

## 输出深度

简短问答直接回答问题。完整分析通常涵盖结论、范围与口径、缺口分布、原因与证据、分析边界和后续建议；可合并章节，HTML 的既定结构由[交互契约](interactive-analysis-contract.md)维护。

贡献量需说明分母和重叠；原因不能重复分摊。数据质量与覆盖限制单列，不生成业务“尚未归类”原因块。未知数值为 `null`，不存在的证据不编造 ID。

## 行动与复盘

已验证原因对应改善，待验证线索对应核查。按任务需要列对象、责任角色、前提和验收依据；用户需要执行计划时再细化期限、恢复目标和观察窗口。

动作完成不等于问题解决，后续指标改善也不自动证明单一动作有效。复盘时考虑观察期、部分恢复、新约束及原判断是否成立。未经授权仅交付建议或草稿。
