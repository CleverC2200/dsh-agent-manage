# 查询任务与最小充分输入

这里描述查询意图，不是Cube调用参数。先读工具定义和inspect返回，再组装调用。每个查询保存原始页，不把手抄TSV当原始返回。

| 任务 | 查询内容与维度 | 验收条件 |
|---|---|---|
| definition | 本期指标编码、公式、阈值、单位、日期归属、版本 | 保存定义引用及元数据，冲突登记 |
| orders | 同订单池全国需求、原始发货、发布缺货/满足率；基地→大区→省区→SKU及编码 | 全国与分层勾稽，分页终止/唯一键；月汇总不冒充订单底表 |
| classification | 同范围需求变化/计划内分类量、计划版本 | 合计与总缺货核对；范围/差异未解释标conflict |
| sales | 销售口径的全国、基地×大区×省区、品类×大区×省区双版本提报、正式准确率及基础量 | 不复制全国；父级NULL不清空子级；完整组织分页 |
| category | 本期SKU→品类映射、版本及未映射项 | 编码唯一、歧义阻断、未映射保留、合计守恒 |
| production | 全国/基地/品类计划实绩；重点对象日期×基地×SKU×产线×单号/批次×理由原文 | 保存可用细粒度；字段不支持才降级日×SKU×原因，再退日×原因，说明影响 |
| transfer | 调拨计划→发运→接收可用配对及需要时间 | 库存调拨标志不是兑现链；无计划到货配对只作库存事实 |
| oe / od | 正式含义、范围、计划和兑现节点 | 未确认含义不猜缩写，不用自产补位 |
| inventory | 缺货SKU×仓库×需要时点可用、占用、效期/质量 | 月末总量不能证明月内有货未发 |
| linkage | 重点订单商品→供给对象→需要/承诺/实际可用时间 | 生产机制可独立解释，订单损失量须关联闭环 |

已知入口：订单 `agents_scm_order_plan_exe_m` / `agents_order_execute_isontime_mi`；生产执行 `agents_mes_prod_oee_line_result_d`、生产排程 `agents_prod_schedule_detail_d`；销售 `agents_scm_demand_sales_f`；库存 `agents_scm_inventory_sku_data_d`。入口随权限/版本变化，不硬编码某月一定无数据。

订单需求、发货、总缺货及两类分类源字段，先在 `agents_scm_order_plan_exe_m` 用**完全相同的月份和业务过滤条件**分别取 SUM；不要仅对分类加 `outqty>0`，却与全量订单指标直接勾稽。若为了逐条诊断另取正缺货子集，保存子集行数及需求、发货、总缺货的对账结果，并标为另一查询范围。销售计划量与准确率统一以 `agents_scm_demand_sales_f` 的 `stat_month` 和 `source_flag=销售口径` 查询；`agents_sales_plan_demand_m.plannum/allnum` 仅作为另表对账，先比全国，再比基地和空基地。按指标查询知识库定义，字段映射与实际值仍须由表结构、模型及查询结果验证。

跨表品类下钻：`agents_scm_order_plan_exe_m` 有物料编码、大区/省区编码与名称，但无品类、物料组；`agents_scm_demand_sales_f` 的 `销售口径` 行有初始/纠偏提报及物料/组织键，2026-09 样本中品类与物料组字段为空。可从**同月** `基地口径` 行按物料编码建立品类/物料组映射，再分别聚合销售与订单，按品类→物料组→大区→省区并列，必要时下钻物料。先检查一物料是否多组；多值归“物料组待确认”，未映射归待映射，不作任选或比例分摊。优先共同编码核验组织，编码缺值时仅在名称路径唯一且完全相同的情况下用名称匹配。记录双表覆盖、单边分组、映射覆盖和全国回算；销售提报与订单需求只是同维度对照，未证明逐订单商品血缘。已查询到的分组值要填到指标与列表，不能因缺直接品类列而整组留空。

分页保持稳定排序和完整编码粒度，按工具游标/hasMore/offset协议迭代。保留每页行数、终止凭据及同范围合计。刚好limit条不算全量；无终止标记时用末页、独立记录数或合计核验，说明不能证明的部分。汇总勾稽不证明实体粒度完整。

数量用原值计算，展示才舍入；比率按契约只转换一次。零分母/NULL保留，定义未知不强行复算。源单位写“源数量单位”时不能仅凭同表其他指标标件就认定全部单位已核验。

## 保存与验收工具返回
原始证据必须保存完整返回：name、rows、rowCount、offset、hasMorePages、fields（含单位/公式）、modelContext、刷新时间及指纹。禁止只复制 rows 后称为原始页；规范化数据另存。每页使用独立文件，禁止复用文件名覆盖另一查询。保存后运行 `node scripts/query-evidence.cjs <文件> <查询name> <offset> <模型名>`，校对身份、行数和元数据。先看文件内部身份，再判断缺页；可从实际会话日志恢复原始返回，保留来源位置与哈希，不把错误文件名当数据事实。
