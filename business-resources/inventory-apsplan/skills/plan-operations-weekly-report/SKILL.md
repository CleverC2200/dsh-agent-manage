# 计划运营周度管理报告生成

## 目标与资料路由

生成一份面向计划运营例会的周度管理报告，使管理者能够在同一份报告中看到核心指标状态、月度与周度变化、主要责任对象、异常原因、执行进展和长期治理动作。

- 开始取数或设计表格前，读取 [references/data-contract.md](references/data-contract.md)，确认期间、比较窗口、指标基础量和维度字段。
- 生成正文前，读取 [references/report-structure.md](references/report-structure.md)，严格使用报告的五段式结构和表格字段。
- 需要编写结论、原因或改善措施时，读取 [references/analysis-and-writing-rules.md](references/analysis-and-writing-rules.md)，避免把相关性、历史案例或行动计划写成已验证事实。
- 生成 HTML 报告时，读取 [references/html-output-template.md](references/html-output-template.md)，复制并填充 [assets/weekly-report-html-template.html](assets/weekly-report-html-template.html)，不得从零重建另一套版式。

参考报告只用于提取结构、信息层级和呈现方式。参考报告中的数值、基地表现、人员责任、问题原因和改善动作均属于历史样例，不得自动进入新报告。

## 工具

- `gea_kb.weknora_list_knowledge_bases`：列出本人有问答权限的知识库；只能选择实际返回且权限含 `ASK` 的 GEA 知识库 ID。
- `gea_kb.weknora_ask`：以自包含的单轮问题核对指标定义、阈值、制度规则和业务背景，保留返回引用；`gea_kb` 不产出指标数值。无结果时可按行业经验提出并标注待验证假设，不得写成企业正式口径或当期事实。
- `cube_new.inspect_cube_model`：读取本轮可用的 measures、dimensions、segments、时间维度及成员说明。
- `cube_new.query_business_data`：查询指标基础量、结果和维度明细。正常情况下每次 query 前必须先 inspect，查询成员来自本轮 inspect 并遵守成员 description。inspect 成功且明确没有所需成员时标记数据缺口；inspect 失败、超时或返回空结果时，只允许进行一次明确标记“猜测成员”的候选查询，其结果仅作待验证线索。

工具不可用时，只使用用户提供且范围、单位和含义明确的数据。缺失值保留为空或“数据不足”，不得补造。

## 必要输入

至少确认：

- 报告周期、数据截止、时区，以及“本月累计”和“本周”的起止日期；
- 上期月度、上周、去年同期或去年同周的可比窗口；
- 六大核心指标的当前定义、方向、目标/挑战值和统计周期；
- 全国及基地、应责总监、品项的实际成员；
- 指标基础量、维度明细、原因记录、改善动作、责任角色和执行状态；
- 上期未闭环事项，若需要复盘决议闭环。

缺少比较窗口时展示 `—` 并说明缺失，不将不同截止进度的数据强行比较。

## 工作流

### 1. 锁定报告范围

明确标题、报告周期、月度累计区间、本周区间、数据截止和比较窗口。未结束月份必须使用相同截止进度进行环比或同比；无法同截止比较时披露差异。

默认核心指标为：作废率、改单率、订单满足率、准交率、60天以上货龄占比、可发货天数。若本期指标字典发生变更，以生效定义为准并在报告中说明。

### 2. 核对口径并检查语义模型

先通过 `gea_kb.weknora_list_knowledge_bases` 选择有 `ASK` 权限的知识库，再用 `gea_kb.weknora_ask` 核对指标定义、方向、目标/挑战值、时间口径和排除规则，最后调用 `cube_new.inspect_cube_model`。只选择语义与本期定义一致的 Cube 成员；存在冲突时停止受影响指标的正式判级，其他指标继续。

### 3. 分层取数

先查询全国总体，再依次查询基地、应责总监和品项：

1. 月度累计当前值、上期值、去年同期值；
2. 本周值、上周值、去年同周值；
3. 形成比率所需的分子、分母或快照基础量；
4. 未达成对象对应的下钻明细、业务事件和改善台账。

不要用 Top N 结果冒充全量。总体和各维度表使用同一截止、筛选和版本；维度切面之间不得相加。

### 4. 计算与质量检查

按 [references/data-contract.md](references/data-contract.md) 重算比例、环比、同比和周环比。比例差使用百分点 `pct`；天数、数量等使用原单位差。期间比率先汇总同口径分子和分母再相除；库存和货龄快照不得跨日相加。

检查空值、重复、分页、单位、分母为零、维度映射和全国汇总勾稽。无法计算时使用 `—`，不得填零或输出无穷大。

### 5. 判级并选取重点对象

根据指标方向和生效阈值判定达标、预警或严重。阈值缺失、区间重叠或与指标方向冲突时标记“口径待确认”，不进行正式红黄绿判级。

重点对象不仅包括未达标者，还包括：

- 环比或同比显著恶化；
- 连续两周红灯；
- 满足率与库存周转方向矛盾；
- 总体达标但局部对象严重异常；
- 指标恢复但改善动作尚未完成或缺少验收证据。

### 6. 分析原因和措施

按“指标差异 - 贡献对象 - 业务约束 - 事件 - 原始记录”核查原因。每条原因说明影响对象、时间关系、影响量或量化方法及当前证据状态。

历史报告、会议纪要和业务经验只能作为调查线索。没有当期对象关联和事件证据时写“待核查”，不得直接复用历史原因。已验证原因可形成改善动作；待验证原因只形成核查动作。

改善部分区分：

- 已落地；
- 正在执行；
- 待启动；
- 已完成但待观察；
- 已验收关闭。

行动完成不等于问题关闭；必须按同口径观察窗口复核指标恢复情况。

### 7. 生成和校验报告

严格按 [references/report-structure.md](references/report-structure.md) 生成五段式报告。默认交付基于 [assets/weekly-report-html-template.html](assets/weekly-report-html-template.html) 的单文件 HTML；用户明确要求时可同时生成 Markdown、DOCX 或 PDF。HTML 必须遵守 [references/html-output-template.md](references/html-output-template.md) 的替换和验收规则。生成 PDF 时必须渲染逐页检查表格、换页、字体和颜色标识。

交付前确认：

- 报告标题、期间和截止一致；
- 六大指标卡与全国汇总一致；
- 月度表、周度表和文字结论数值一致；
- 全国、基地、总监和品项使用相同口径；
- 未达成项都有原因状态或数据缺口；
- 改善动作能回到具体问题，并包含责任、时间或验收条件；
- 不包含参考报告的历史数值或原因，除非本期数据重新验证。

## 默认交付

1. 使用指定样式模板生成的计划运营周度管理报告 HTML；
2. 数据范围、截止和口径说明；
3. 数据缺口与未判级项目清单；
4. 未闭环措施及下周跟进重点。
