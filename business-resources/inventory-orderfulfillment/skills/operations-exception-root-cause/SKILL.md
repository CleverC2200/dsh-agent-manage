# 订单工作台异常归因 Skill

## 适用边界

- 用于解释基地、省区、负责人、品项或订单维度的未达标项、显著恶化项和重点风险项。
- 输出可复核的“现象—影响—证据—直接原因/待验证假设—建议”链路，区分事实与推断。
- 不代替指标计算，不在证据不足时下确定性结论；不直接修改订单、库存、排产或要求外部人员执行动作。

## 输入与前置条件

至少需要异常指标、统计范围、周期、对比基线及数据时间。优先补充受影响订单/SKU、库存与货龄、生产计划与完成、物流节点、销售归属、原因记录和既有措施。

若用户只提供“某指标不达标”，先使用 [operations-kpi-performance-analysis](../operations-kpi-performance-analysis/SKILL.md) 确认异常对象、差距和变化，再开始归因。

## 工作步骤

1. 定义问题：说明未达标指标、目标差距、变化幅度、影响对象及排序依据。
2. 下钻定位：依次识别贡献最大的基地/省区/负责人/品项/订单，并验证贡献与总额能够对账。
3. 收集证据：按问题类型关联对应领域数据：
   - 订单满足、改单、作废、准交、节点异常 → [order-fulfillment-risk](../order-fulfillment-risk/SKILL.md)；
   - 缺货、库存、货龄、可发货天数 → [sku-inventory-shortage](../sku-inventory-shortage/SKILL.md)；
   - 生产计划、产能、完成与供给覆盖 → [production-fulfillment-progress](../production-fulfillment-progress/SKILL.md)；
   - 仓库、物流商、运单与在途节点 → [warehouse-logistics-fulfillment](../warehouse-logistics-fulfillment/SKILL.md)；
   - 销售需求、区域、客户和负责人归属 → [sales-organization-analysis](../sales-organization-analysis/SKILL.md)。
4. 形成归因层级：先列直接可证实原因；证据不足的内容标“待验证假设”，并说明需要的字段、负责人或验证动作。
5. 评估影响：量化受影响订单数、数量、客户/区域、指标缺口与紧急性，避免只描述单个案例。
6. 提出建议：区分短期止损、下一周期改善和长期机制；每项建议应对应一个已证实原因或明确假设。

## 根因判定规则

- 仅有时间相关或单一案例时，不得写为“根因”；使用“可能相关/待验证”。
- 同一异常可包含多项原因，但应区分主因、次因和放大因素，不重复累计影响。
- “库存充足”不等于可满足订单；须验证可用量、占用、分配顺序、基地与 SKU 可用性。
- “有排产”不等于可交付；须验证产出时间、合格入库、可调拨性和订单需求时间。
- 对影响订单满足率和准交率的原因，先说明直接影响哪个分子/分母或节点规则。

## 输出与安全约束

每个异常项使用固定结构：

**异常**：指标、目标差距、趋势、范围和数据时间。  
**影响**：受影响基地/省区/SKU/订单/客户及量化影响。  
**证据与归因**：已验证事实、直接原因、待验证假设及所需验证。  
**建议**：短期动作、长期机制、依赖条件；不宣称已执行。  
**限制**：缺失数据、口径差异和无法确认事项。

当需要指定责任人、截止日期、状态和升级规则时，路由至 [improvement-action-closure](../improvement-action-closure/SKILL.md)。对涉及订单、库存、生产、物流的实际操作，必须在操作前取得相应授权。

## 当前安装能力边界

本 Skill 由订单工作台与订单履约 Agent 共用，技能描述不授予查询、人员范围或业务写入权限。只能使用当前 Agent 已安装、已授权的页面证据和工具；用户角色描述不代表实际授权。

订单履约只使用 order01 的当前用户受控只读能力，缺失指标和接口保持未知。订单工作台沿用其当前已发布能力；页面处于 mock 时，只分析明确标记的报告摘录、演示数据或用户提供的证据，不宣称已接入实时订单系统。

销售确认、每小时提醒、飞书消息、OMS 更新、WMS/TMS 下发及外部改善任务尚无本次新增的写入或调度接口。可以解释流程、分析证据和生成草案，不能因加载 Skill 就启动执行或声称已完成。实际操作仍需相应工具、有效权限和明确授权。
