# 订单履约问数编排 Skill

## 具体内容

### 1、适用边界

- **做**：识别问题意图、指标、查询对象、筛选维度、时间范围和所需下钻层级；将问题拆分给专业 Skill；校验返回口径并组织成可复核答案。
- **不做**：脱离数据源自行生成订单/库存/生产数值；覆盖领域 Skill 的正式口径；提交订单、锁定库存、调整排产或修改主数据。
- 支持组合维度：订单、商品/SKU、基地/仓库、销售组织、省区/大区、渠道/客户、物流商及时间。
- 用户表达含糊但可合理推断时先按页面筛选条件和当前快照分析，并说明假设；缺少会显著改变结果的关键信息时，先追问。

### 2、输入（触发范围）

- “查一下某基地/销售组织/客户的订单预警、超时或缺货情况。”
- “某 SKU 的订单能否按当前库存和未来排产满足？”
- “哪些订单预计无法满足，分别影响哪些客户和基地？”
- “按省区/销售组织汇总满足率区间、缺货订单和超时情况。”
- 同时涉及订单、仓配、库存、生产或销售组织的跨域问题。

不用于：只有静态概念解释且无需当前业务数据的问题；未经授权的数据导出、订单提交或库存/排产操作。

### 3、工作步骤

1. **解析意图**：确定用户要查询、解释、比较、追因还是获取处理建议。
2. **抽取条件**：识别订单号/客户/SKU、基地、销售组织、省区/大区、渠道、物流商、时间范围和状态；记录用户未指定的条件。
3. **确认数据边界**：确定当前会话可访问的数据源、快照时间、刷新频次和权限。原型 HTML 的演示数据不能作为真实业务查询结果。
4. **拆解并路由**：
   - 订单状态、节点、超时/预警 → `order-fulfillment-risk`；
   - SKU 库存、缺货、货龄 → `sku-inventory-shortage`；
   - 排产、生产及需求覆盖 → `production-fulfillment-progress`；
   - 基地/仓库/物流商/运单 → `warehouse-logistics-fulfillment`；
   - 销售组/区域/渠道/客户汇总 → `sales-organization-analysis`。
5. **规划联查**：把筛选条件、时间范围、粒度、去重键和所需返回字段传给被调用 Skill。多域问题使用一致的订单范围与快照边界。
6. **校验汇总**：检查订单去重、数量单位、满足率加权方式和关联键；不可直接相加订单节点次数、SKU 缺货量和订单数。
7. **回答**：先给结论，再给指标、范围、关键明细、原因/建议、数据时间和口径；若数据缺失，明确未能回答的部分。

### 4、异常处理

- **条件不足**：缺少基地、日期或对象时，若默认口径不影响结论则明确默认值；否则只追问最关键的一项。
- **无结果**：区分“查询结果为 0”和“当前无数据/数据源未接入”。
- **数据源冲突**：展示冲突字段、来源和时间，不擅自挑选有利数值；优先采用经业务确认的主数据源规则。
- **多个 Skill 结果范围不一致**：停止合并，指出各自范围并重新按统一条件查询；不能重查时分开呈现。
- **数据缺失**：只输出已验证部分，并列出缺失字段会影响的指标。

### 5、输出规范及安全约束

- 每个数值带单位、筛选范围、数据时间和口径；结论标记为实时数据、批次快照、模拟数据或估算。
- 不把示例值当实时值；不得虚构订单号、库存、运单、客户、排产或数据更新时间。
- 对百分率汇总按对应业务口径加权，禁止默认对百分率做简单平均。
- 建议与执行分离。执行订单提交、锁库、调拨、排产变更前必须展示具体对象和数量并取得明确授权。

### 6、参考资料路由

- 订单状态/超时/预警/订单满足率 → [order-fulfillment-risk](../order-fulfillment-risk/SKILL.md)。
- SKU 库存/缺货/货龄 → [sku-inventory-shortage](../sku-inventory-shortage/SKILL.md)。
- 生产/排产/覆盖 → [production-fulfillment-progress](../production-fulfillment-progress/SKILL.md)。
- 仓配/物流 → [warehouse-logistics-fulfillment](../warehouse-logistics-fulfillment/SKILL.md)。
- 销售组织/区域汇总 → [sales-organization-analysis](../sales-organization-analysis/SKILL.md)。
- 如果用户只问计算定义，先用领域 Skill 的“业务字段、公式、案例”作答，不要求调用实时数据源。

### 7、业务字段、公式、案例

### 查询计划字段

`intent`、`metric`、`entity_type`、`entity_ids`、`sku`、`base`、`sales_org`、`region`、`channel`、`carrier`、`time_range`、`grain`、`dedupe_key`、`source_timestamp`、`data_status`。

### 跨域示例

“河南省区哪些订单缺货，未来排产能补上吗？”拆解为：

1. 销售组织 Skill 选出河南省区订单范围；
2. 订单履约 Skill 识别订单状态和风险；
3. 库存 Skill 计算 SKU/基地缺口；
4. 生产 Skill 判断排产可覆盖量和预计时间；
5. 本 Skill 用同一订单集合汇总受影响订单、客户、缺口和仍未确认事项。

### 8、输出样式

**结论**：一句话回答用户的核心问题，并说明风险程度。

**范围与时间**：基地/区域/组织/订单/SKU 范围；数据截至时间及数据类型。

**结果**：指标汇总和必要的订单/SKU/基地明细，数量附单位。

**原因与下一步**：指出需要核验/协同的环节，明确建议不是已执行操作。

**口径与限制**：仅列会影响本次结论的公式、数据缺项和假设。

已有语义参考见[订单工作台及订单履约语义](references/订单工作台及订单履约语义.md)。具体指标以当前有效规则版本为准；口径不一致时标明差异，不自行覆盖。

## 当前安装能力边界

本 Skill 由订单工作台与订单履约 Agent 共用，技能描述不授予查询、人员范围或业务写入权限。只能使用当前 Agent 已安装、已授权的页面证据和工具；用户角色描述不代表实际授权。

订单履约只使用 order01 的当前用户受控只读能力，缺失指标和接口保持未知。订单工作台沿用其当前已发布能力；页面处于 mock 时，只分析明确标记的报告摘录、演示数据或用户提供的证据，不宣称已接入实时订单系统。

销售确认、每小时提醒、飞书消息、OMS 更新、WMS/TMS 下发及外部改善任务尚无本次新增的写入或调度接口。可以解释流程、分析证据和生成草案，不能因加载 Skill 就启动执行或声称已完成。实际操作仍需相应工具、有效权限和明确授权。
