# 订单工作台改善闭环 Skill

## 适用边界

- 把已确认或明确待验证的经营异常组织为行动项，并追踪执行、验证、关闭、逾期和升级。
- 支持高库存 SKU 退出、产销进度对齐、满足率与货龄双指标、ODM 产能备份、下市品清理等长期机制的台账化管理。
- 不凭空指定责任人、承诺完成时间或确认“已完成”；不未经授权向飞书、工单或业务系统创建任务、发送催办或变更数据。

## 输入与前置条件

每个行动项应至少关联：异常编号或问题描述、影响范围、指标基线、目标值、责任团队/人、计划完成时间和验证方式。缺少责任人或时限时可生成草案，但状态须为“待确认”。

异常事实和原因优先来自 [operations-exception-root-cause](../operations-exception-root-cause/SKILL.md)；指标基线与目标来自 [operations-kpi-performance-analysis](../operations-kpi-performance-analysis/SKILL.md)。

## 工作步骤

1. 建立问题卡：记录异常、范围、数据时间、指标基线、目标差距、已确认原因与依赖关系。
2. 拆分行动：每项只解决一个明确问题，区分“短期止损”“周期改善”“长期机制”；避免将泛泛表态作为行动。
3. 明确闭环字段：责任人/协同方、计划时间、里程碑、所需资源、风险、验收指标、证据链接和当前状态。
4. 跟踪进展：状态建议使用“待确认、未开始、进行中、受阻、待验证、已关闭、已取消”；状态变更必须记录时间、操作者和依据。
5. 验证关闭：仅在验收周期内指标达到约定标准且证据完整时关闭；若只是动作完成但效果未验证，保留“待验证”。
6. 升级与复盘：逾期、受阻或影响扩大的事项输出升级建议及所需决策；复盘时检查措施是否真正改善指标，而非只检查任务完成率。

## 长期机制的最低闭环要求

| 机制              | 至少验证内容                                         |
| ----------------- | ---------------------------------------------------- |
| 高库存 SKU 退出   | 分级阈值、停售/限产规则、库存消化与满足率影响        |
| 产销进度对齐      | 需求、下单、发货、生产进度的同口径对比与偏差阈值     |
| 满足率/货龄双指标 | 责任归属、目标阈值、两项指标的权衡与例外审批         |
| ODM 产能备份      | 备选产能、准入状态、切换条件、验证记录               |
| 下市品清理        | 下市标识、剩余库存、清理计划、禁止新增需求或例外规则 |

## 输出与安全约束

输出行动台账：`问题｜措施｜类型｜责任人/协同方｜截止时间｜状态｜验收指标｜证据｜风险/依赖｜下一步`。

- 明确区分“建议措施”“已授权待执行”和“已完成并验证”；没有证据不得标记关闭。
- 不把结果改善自动归因于某一措施；需注明验证周期、对照基线和可能的外部影响。
- 需要向飞书群、任务系统或业务系统写入时，先展示目标、字段和影响范围，并取得明确授权；实际写入后返回记录编号或失败原因。
- 对订单履约的销售确认与 OMS/WMS/TMS 下发，使用 [fulfillment-sales-confirmation-automation](../fulfillment-sales-confirmation-automation/SKILL.md)，不要将其作为普通整改任务自动执行。

## 当前安装能力边界

本 Skill 由订单工作台与订单履约 Agent 共用，技能描述不授予查询、人员范围或业务写入权限。只能使用当前 Agent 已安装、已授权的页面证据和工具；用户角色描述不代表实际授权。

订单履约只使用 order01 的当前用户受控只读能力，缺失指标和接口保持未知。订单工作台沿用其当前已发布能力；页面处于 mock 时，只分析明确标记的报告摘录、演示数据或用户提供的证据，不宣称已接入实时订单系统。

销售确认、每小时提醒、飞书消息、OMS 更新、WMS/TMS 下发及外部改善任务尚无本次新增的写入或调度接口。可以解释流程、分析证据和生成草案，不能因加载 Skill 就启动执行或声称已完成。实际操作仍需相应工具、有效权限和明确授权。
