# 订单履约与节点风险 Skill

## 具体内容

### 1、适用边界

- **做**：订单生命周期查询、节点状态和时效风险判定、订单级去重、满足率和状态区间分析，并下钻订单及 SKU 明细。
- **不做**：推测未接入的节点时间；替物流商确认到货；核定库存/生产可用量；提交或修改订单。
- 结论基于可访问的订单快照和已配置的节点规则，不等同于客户签收或现场实物状态。

### 2、输入（触发范围）

- 订单号、客户、商品、基地或销售组织的履约查询。
- 超时订单、预警订单、订单状态、未开订单、履约节点、准交或满足率区间分析。
- 用户问“现在到哪一步”“哪些订单需要先跟进”“某区域有多少风险订单”。

不用于：仅库存是否够、未来排产能否覆盖的问题；提交流程或修改订单数据。

### 3、工作步骤

1. 识别订单标识、客户/SKU、基地、销售组织、地区、渠道、时间范围及用户关心的节点。
2. 查询订单主表及履约事件，确认订单唯一键、数据截至时间和状态来源。
3. 将节点事件按配置顺序映射为备单、派车、装车、在途、完成；不完整或无法映射的节点标记异常/未知。
4. 按业务配置判断超时和预警：对比节点承诺/最晚完成时间、当前时间及预警提前量。缺少阈值时不自创规则，输出节点时间和“规则待确认”。
5. 按订单唯一键去重统计超时和预警；同一订单多个节点命中时可以列出多个原因，但订单数只计一次。
6. 核对订单需求量、实际发货量及缺货量，计算订单满足率；汇总时按总需求量加权。
7. 组织结果，提供风险订单、当前节点、预计/最晚时间、客户/SKU 和下一步核查建议。

### 4、异常处理

- 没有承诺时间或节点时间：不判定准交/超时，标注缺失字段。
- OMS 状态与履约事件不一致：并列显示来源和更新时间，标记状态冲突待核实。
- 重复订单/多条事件：根据已确认订单主键去重，事件只用于节点追踪。
- 缺少发货或需求量：不计算满足率；不可用缺货率冒充满足率。
- 找不到订单：返回未匹配的筛选条件，不创建虚构订单。

### 5、输出规范及安全约束

- 订单级结果至少显示订单号、客户、基地、当前状态/节点、风险及命中时间；涉及订单人员/客户信息遵守当前用户授权范围。
- 总数说明订单去重口径；节点数量可能是一张订单跨多个节点的事件数，不能与去重订单数混用。
- 明确快照时间及“实时/批次/模拟/未接入”状态。
- 仅给跟进建议，不代表已通知客户、物流或修改订单。

### 7、业务字段、公式、案例

### 字段

订单号、订单创建时间、客户名称/编码、销售组、省区、大区、渠道、销售人员、订单人员、所属基地、物流商、订单状态、处理状态、订单需求量、实际发货量、缺货量、节点承诺时间、节点实际时间、事件时间。

### 公式与口径

- 订单满足率 = `min(实际发货量 ÷ 订单需求量, 100%)`。需求量为 0 或缺失时结果为不可计算。
- 汇总满足率 = `min(所选订单实际发货量合计 ÷ 所选订单需求量合计, 100%)`，不平均各订单百分比。
- 超时订单数 = 命中已确认超时规则的去重订单数。
- 预警订单数 = 命中已确认预警规则的去重订单数。
- 未开订单 = 已进入履约流程但未生成有效 OMS 执行单的有效订单；其筛选条件须由业务系统确认。
- 满足率区间：采用页面配置的区间边界，区间互斥且完整覆盖 0%–100%，边界归属要统一确认。

### 案例

订单需求 100 件、已发 80 件，则订单满足率为 80%。若同一订单备单和派车节点都超时，超时订单计 1 张，明细中可列出两个超时节点。

### 8、输出样式

先给汇总：“筛选范围内共 X 张订单，其中超时 X 张、预警 X 张，数据截至……”。

随后按风险展示订单明细：订单号｜客户｜基地｜当前节点｜超时/预警原因｜订单满足率｜建议核查动作。

缺数据时单列“无法判断项”，明确缺少的节点时间、承诺时间或订单量。

## 当前安装能力边界

本 Skill 由订单工作台与订单履约 Agent 共用，技能描述不授予查询、人员范围或业务写入权限。只能使用当前 Agent 已安装、已授权的页面证据和工具；用户角色描述不代表实际授权。

订单履约只使用 order01 的当前用户受控只读能力，缺失指标和接口保持未知。订单工作台沿用其当前已发布能力；页面处于 mock 时，只分析明确标记的报告摘录、演示数据或用户提供的证据，不宣称已接入实时订单系统。

销售确认、每小时提醒、飞书消息、OMS 更新、WMS/TMS 下发及外部改善任务尚无本次新增的写入或调度接口。可以解释流程、分析证据和生成草案，不能因加载 Skill 就启动执行或声称已完成。实际操作仍需相应工具、有效权限和明确授权。
